## Version 2027.01.0

<span style={{ display: 'inline-block', backgroundColor: '#86efac', color: '#056d4f', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>NEW FEATURES</span>

- ### WebSocket API Proxy Carries Socket.IO Clients
A WebSocket API proxy can now carry the HTTP long-polling requests of Socket.IO clients. Select **Socket.IO Compatibility** in the connection settings of the proxy and set the **Read Timeout**. The request and response policies, the Rate Limit Control List and the Limit Plan run on a polling request. After the backend confirms the Socket.IO session, the heartbeat frames no longer write one traffic record each, and the record that closes the connection carries a heartbeat summary. The APIops WebSocket settings call has the new `socketIoEnabled` field. [See](/en/develop/routing/websocket-routing#socket-io-compatibility) APNZ-6140

<span style={{ display: 'inline-block', backgroundColor: '#bfdbfe', color: '#1e40af', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>CHANGES AND IMPROVEMENTS</span>

- ### Policy and Routing Secrets Are Stored Encrypted
The API Manager now stores the secrets of the policies and routing of an API proxy, of policy groups, of proxy groups and of global policies in encrypted form, whichever save brings them: the editor, APIops promotion or an import package. The upgrade encrypts the values that earlier releases stored as typed. Some saves that return the saved API proxy now show a secret that the request brought as typed in encrypted form. A save of an API proxy now refuses an AI policy in a REST to SOAP method copy of an API proxy that is not an AI proxy. APIops and REST responses no longer carry the fields that hold the resolved copy of a value, for example the resolved form of a header value. Read the upgrade notes before you upgrade. [See](/en/upgrade/apinizer-version-upgrade) APNZ-7186

- ### Test Console History Stores the Request as Written
Test Console History, Test Console Audit and the audit record now store the request as you wrote it, so a `${NAME}` reference stays a reference. The request that is sent is resolved as before. Send, the code snippet, the JOSE key test and the Uptime Monitor resolve variables of the caller's project (the monitor's project for Uptime) and of the Administration project only. History records saved before this version are not changed. [See](/en/develop/test-debug-tools/test-console#history) APNZ-7186

- ### Failure Text of a Test or Check With a Variable in the URL
When a Test Console request or an Uptime Monitor check whose URL has a variable does not reach the target, the history, the Manager log, the Uptime result history, the result export and the notification now carry only the name of the error type, for example `UnknownHostException`. The Test Console screen still shows the full error. A URL without a variable is not changed. [See](/en/monitor/api-health-check) APNZ-7186

- ### Code Snippet Carries SOAPAction
When you select a SOAP method, the Test Console code snippet now carries the SOAPAction (the `SOAPAction` header for SOAP 1.1 and the action in the `Content-Type` header for SOAP 1.2). A test saved from the screen now appears in the test list of the API proxy method. [See](/en/develop/test-debug-tools/test-console#code-snippet) APNZ-7186

- ### Duplicating a Record With Secret Values Needs Read Permission
A user without read permission on a shared record cannot duplicate it when it holds a value that can carry a secret. This applies to Uptime monitors, Anomaly Detectors, Task Flows, e-mail connections and Mock APIs. The error is `duplicate.secretNotReadable`. APNZ-7186

- ### Policy Editors Return to the Flow, Global Policy Dialog Removed
A policy editor URL that was not opened from the flow now returns to the flow, also with the browser Back and Forward buttons. The "global policy changed" dialog inside an API proxy, the **Select From Global Policies** link in a policy form and the **Back** buttons of the embedded global policy list are removed. Add a global policy with **Add Policy**. A global policy opens read-only inside a proxy. APNZ-7191

<span style={{ display: 'inline-block', backgroundColor: '#e65a2a', color: '#ffffff', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>BUG FIXES</span>

- ### WebSocket API Proxy Fixes
On a WebSocket API proxy, a successful backend connection (HTTP 101) is now recorded as Successful, so the error counts of dashboards and reports fall by one for each connection. A request without an upgrade now gets HTTP 404 with `ERR-006` instead of 500. With a root context and several relative paths, the longest matching path is cut, as in a REST API proxy. Escaped characters (for example `%2F`, `%20`, `%25`) in the path and in the routing address, and the query, reach the backend as they were sent. When the backend closes the connection, the close record of the backend side is kept also under a heavy log load. [See](/en/develop/routing/websocket-routing) APNZ-6140

- ### DB-2-API Answers a SQL ARRAY Column as a JSON Array
A DB-2-API request whose result has a SQL ARRAY column now answers with a JSON array, and an array of rows is written as rows, so the answer body is no longer empty. A NULL REF_CURSOR column is written as `null`. An answer that cannot be written as JSON now returns HTTP 500 with the text of the failed statement instead of an empty HTTP 200. APNZ-7244


- ### Worker Stops in Order on SIGTERM Within 15 Seconds
On SIGTERM the worker now stops in order within 15 seconds: running requests get 5 seconds, then every buffered log record is written or counted as SHUTDOWN, a summary line reports the results, and connector or cleanup closes that do not answer no longer hold the stop. If you lower `terminationGracePeriodSeconds` or the `preStop` wait in Kubernetes, keep their difference at 15 seconds or more. [See](/en/integrations/connectors/overview) APNZ-7213

- ### API Portal Subscriptions Take Access Only From Approved Subscriptions
In the API Portal, a consumer's access rules come only from its application's approved subscriptions. A portal user can only cancel an existing subscription, not approve it or move it to another product or plan. A new subscription takes its organization from the application and its account from the signed-in user, so a pending or rejected organization cannot subscribe. Access rules written in API Manager (contract, consumer regenerate) and the deletion of a contract file require the user's right in the target's project. [See](/en/api-portal/application-promote) APNZ-7212

- ### Write Endpoints Verify the Project of the Stored Record
Write endpoints that grant permission by the project id in the request body now check the project of the stored record. Sending the id of a record of another project returns HTTP 400 with `projectidimmutable`, and credential access rows (a row deleted after the page was opened is no longer re-created), task flow runs and identity source tests follow the same rule. The new global WS-Security from target policy is now created correctly in the UI (the save no longer returns `notfound`). [See](/en/admin/user-access-management/authorization-matrix) APNZ-7211

- ### Project of a Record Cannot Be Changed by an Update Request
An update request can no longer change the project of a record. This applies to connection settings, IP groups, environment variables, database and API credentials, certificates, crypto keys, key stores, JWKs, contracts, task flows and OIDC identity providers. An older APIops or REST integration that updates a record of another project with its own project id now gets HTTP 400 with `projectidimmutable`. To change the project of a record, use **Move to Global**. [See](/en/admin/user-access-management/authorization-matrix) APNZ-7207

- ### Portal Does Not Send the Proxy Client Secret to the Browser
API Portal no longer sends the proxy client secret in the API specification, and the MCP tool `get_api_auth_info` no longer returns `client_secret`. If your integration used this value, get the token with `get_token`. An anonymous Try It call that needs the secret now gets HTTP 401. Upgrade API Portal together with API Manager. [See](/en/api-portal/mcp-usage/mcp-overview#token-and-authentication) APNZ-7209

- ### API Product Documentation Can Be Generated From the APIs, Try It Calls Only Product Addresses
An API product can now take its portal documentation from its API proxies and proxy groups instead of an uploaded file. The documentation updates when a proxy changes. Existing products keep the uploaded file. The portal Try It console now calls only the product's own gateway addresses and does not follow redirects. Upgrade API Portal together with API Manager. [See](/en/api-portal/api-product#documentation-source) APNZ-7146

- ### Promotion Instance Endpoints Require System Admin or Promotion Manager
Promotion instance endpoints now require System Admin or Promotion Manager. The promotion wizard's pickers stay open to users with the PROMOTION permission in any project, and remote project and API lists no longer carry routing passwords. Execution details require PROMOTION View in the execution's source project. [See](/en/admin/api-promotion/overview#permissions) APNZ-7208

- ### Permission Required for Spec Import, Test Console Import, Certificate Fetch and Promotion Connection Test
Spec import from URL or file, Test Console import from URL, certificate fetch from URL and promotion instance connection test now require the permission of the screen that uses them. Requests without that permission get HTTP 403. [See](/en/develop/api-proxy-creation/api-proxy-creation) APNZ-7205

- ### Manager and API Portal Login Ignore Remember Me
The Manager and API Portal login now give every token the normal token validity (`token-validity-in-seconds`). A client that sends `rememberMe: true` to `/api/authenticate` gets this validity and no error. Tokens issued before the upgrade keep their original expiry, up to 30 days. Refresh does not extend or shorten it. The config key `token-validity-in-seconds-for-remember-me` is still accepted and ignored, so old configs still start. APNZ-7204

- ### Array Paths in XML to JSON Conversion Fixed
An array path such as `root#liste#aciklama` now converts the last element to a JSON array under every repeated parent, at any depth. Before, the element stayed a single value when the parent repeated two or more times. This applies to the REST to SOAP response transformation, the XML Transformation policy, Redaction, Business Rule policies and the XML transformation test tool. [See](/en/develop/policies/xml-transformation) APNZ-7171

- ### Portal Test Screen and MCP Token Tool Refuse Tokens That Cannot Work
Some token policies issue tokens only to the API's own client, not to an application credential. This applies to an OAuth2 policy that manages its own keys. It also applies to a JWT policy whose keys the portal does not publish. For these APIs, the portal test screen now disables **Authorize** and shows a hint. The `get_token` MCP tool refuses the request and `get_api_auth_info` says that the portal cannot get a token. The portal sends no request to the gateway. [See](/en/api-portal/api-product) APNZ-6092


- ### API Portal Upgraded to Angular 22, Closing CVE-2026-88059
API Portal now runs on Angular 22.2.3. This closes the vulnerability CVE-2026-88059 that a security scan reported on API Portal. The fix is in Angular 22.1.1 and later. API Portal does not use server-side rendering, so the server-side rendering cache issue was not exploitable before the upgrade. APNZ-6932
