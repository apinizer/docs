## Version 2027.01.0

<span style={{ display: 'inline-block', backgroundColor: '#e65a2a', color: '#ffffff', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>BUG FIXES</span>

- ### Array Paths in XML to JSON Conversion Fixed
An array path such as `root#liste#aciklama` now converts the last element to a JSON array under every repeated parent, at any depth. Before, the element stayed a single value when the parent repeated two or more times. This applies to the REST to SOAP response transformation, the XML Transformation policy, Redaction, Business Rule policies and the XML transformation test tool. [See](/en/develop/policies/xml-transformation) APNZ-7171

- ### MCP Call (Fixed) and A2A Call (Fixed) Refuse an Empty Catalog With HTTP 503
The two policies answer HTTP 503 (ERR-288 and ERR-286) when the target tool or skill is not in the saved catalog, an empty catalog included. Before, the status was 500. The upgrade changes the status to 503 for the error messages that still have the default status. A deploy now fills a catalog that has no tool or skill with a name, and it clears the drift warning of the old fingerprint. **Discover / Reparse Skills** warns when an agent card offers no JSON-RPC binding, and the discovery answer of the APIops lists them in `unsupportedBindings`. A card whose `skills` field is not a list is rejected. The Discover errors of the MCP and A2A policy screens show in your language. [See](/en/ai-gateway/a2a-gateway) APNZ-6960
