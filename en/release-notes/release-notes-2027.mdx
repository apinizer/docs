## Version 2027.01.0

:::warning Before you upgrade

- **An API proxy that routes to a DB-2-API, Script-2-API or Mock API definition of another project can no longer be saved.** An API proxy routes only to a definition of its own project. Recreate the API proxy from a definition of its own project, or import it with **Replace Existing**. The import removes the reference and reports it.
- **Text criteria "is equal to" and "not equal" now compare the whole value and ignore letter case.** Before, they compared a part of the value. Saved reports and anomaly detectors that use these criteria can return different results. Client IP "is equal to" no longer matches 10.0.0.10 for 10.0.0.1. A wildcard `*` works as before. An empty **in** list matches nothing and cannot be saved.
- **AI count alerts use the selected Period as the search window.** This applies to PII detection, guardrail hit, provider failover, quota soft-cap and quota alerts: minute = 1 minute, day = 24 hours, month = 30 days. Existing alerts keep their one-hour window until you change the Period.
- **Alert, Anomaly Detector, Uptime Monitor, Quota Alert, Task Flow and Promotion action templates resolve `${NAME}` only to a variable of the object's project or of the Administration project.** A variable of another project stays as typed. A report template follows the same rule. A `{{key}}` text inside the value of a `${NAME}` variable is not filled in a report e-mail; the value is sent as it is.
- **A Quota Alert of a project evaluates and notifies only counters of its own project or of the Administration scope.** Counters of other projects no longer trigger it and do not appear in its counter list. Quota Alerts in the Administration scope do not change.
- **A saved "Organization Based" ACL report runs organization based, so its layout changes.**
- **The traffic log fields for request and response body size count bytes instead of characters.**
- **A connector added to an environment after the upgrade does not write logs until you turn it on.** Open the traffic log settings, turn on **Active for this environment** and save. The upgrade writes explicit entries for the connectors that exist. An APIops update of the connector settings replaces the whole connector map, so connectors you do not list stop logging. Upgrade Manager first, wait for the migration to finish, and then restart the Gateway Engine instances. [See.](/en/analytic/api-traffic-log-settings)
- **The alert trigger "API Traffic Exist in Database" is named "Unsent Traffic Logs Exist in Database".** Notification texts that use the trigger type show the new name.
- **A record that other records use can no longer be deleted.** The refusal names the records that use it. This covers a log connection that an environment uses; an Email, SNMP, Linux Script or DB pool connection that an alert, monitor, report, integration, portal, database authentication or log setting uses; all other connection types (LDAP for the first time); certificates; key stores; keys; knowledge bases; IP groups; LLM providers and models; Vector DB connections; OIDC providers; consumers; organizations; portal apps; limit plans; consumer roles; and API plans. A knowledge base, certificate or key store is also refused while a RAG policy (bound by collection name) or the mTLS settings of an MCP or A2A connection still use it. APIops delete follows the same rule. APNZ-7050
- **Task flow run history and deleting all run logs work inside one project.** The run history of a project shows only the runs of that project, and the delete never reaches the runs of another project. System administrators and system analyzers still read the run history of every project. APNZ-7030
- **Existing AI Token Usage Percentage and AI Daily Cost Threshold (USD) alarms switch to Execute once for same violation series.** Other existing alarms and uptime checks keep sending a notification for every violating run. You can change the **Execution Mode** of each alarm. [See.](/en/monitor/alarm#results-events-and-notifications) APNZ-6512 APNZ-7002
- **An anomaly condition on AI token usage that uses the minimum or maximum metric ends as Evaluation Error.** The condition uses the metric you choose; sum, average and count of documents are supported. [See.](/en/monitor/anomaly-detector) APNZ-3864 APNZ-4851

:::

- ### Traffic Tab on the API Proxy Group Page
The API Proxy Group page has a **Traffic** tab. It lists the requests that came through the group, with the same filters, record details and Excel export as the API Proxy Traffic tab. [See.](/en/develop/api-proxy-group-creation) APNZ-4492

- ### Audit of Log Access
Log searches, log record views and log exports write an audit event with the user and a filter summary. This covers traffic, AI traffic, audit records, login and token records, test console audit, security events, application logs, and API and AI traces. DB-2-API **Try SQL** is audited too. SIEM destinations that use the v2 profile receive the log type, filters, time range, environment and result count of these records. [See.](/en/admin/system-settings/siem-log-forwarding) APNZ-4703

- ### Used By Panel and Names of Users in Delete Refusals
A record that other records use cannot be deleted. The refusal names the records that use it: up to five names and "and N more". Usages in other projects are counted. Connections (including Kafka, Webhook and the other connection types), LDAP settings, certificates, key stores, cryptographic keys, knowledge bases and IP groups are checked against every use. Records that are deleted together with their parent are not changed. Removing an LLM model that is still in use is refused in the same way and names the users. The IP group and knowledge base pages have a **Used By** panel. APNZ-7050 APNZ-4313 APNZ-6959

- ### More Fields in the Traffic Search
The Advanced search of API Traffic and AI Traffic has a **More fields** criterion. It searches any logged field that has no criterion of its own, grouped as Caller, Request, Backend, AI and Diagnostics. Consumers, API clients, organizations, API products and LLM providers are picked by name, and durations are entered in milliseconds. A query that uses **More fields** cannot be used as a trace filter. After an import, re-select the consumers, API clients, organizations, products and providers that the import report lists. [See.](/en/analytic/api-traffic)

- ### New Places in the Menu
Administration > Identity > ACL Report moved to Administration > API Governance > Inventory Reports > ACL Report. Administration > Gateway Infrastructure > Route Analysis moved to Administration > API Governance > Route Analysis. The admin API Growth and Endpoint Growth reports moved from the Metrics tabs to Administration > API Governance > Inventory Reports; old bookmarks redirect. The API Growth list view is removed; the list is Administration > API Governance > API Proxies. API Governance also lists API Proxies, Proxy Groups, Global Policies, Integrations and API Creators of all projects, and AI Governance lists LLM Gateways, MCP Gateways and A2A Gateways, all read-only. The ACL Report of a project stays under Identity. In API Governance > Integrations, system administrators and system analyzers can open the run history of an integration with **Details**, and the View page shows its endpoint address. API Governance > API Proxy Groups lists the groups of all projects, and the API Creators page lists DB-2-API, Script-2-API and Mock API definitions of all projects. [See.](/en/integrations/api-integrator-task-flow-builder/overview) APNZ-4426 APNZ-4344 APNZ-4515 APNZ-4943 APNZ-5734 APNZ-7030

- ### Report E-mail With an HTML Table
The `{{report.resultTable}}` variable puts the first 25 rows of the report in the e-mail as an HTML table, for every report type. Metric reports add the Total row. [See.](/en/monitor/alarm) APNZ-7030

- ### Provider Health: Time to First Token
Provider Health shows TTFT p50/p95 per provider for the last 24 hours. The cell shows the exact figures of the environment with the most streaming requests, with its name. A tooltip lists the figures of every environment; there is no combined value. LLM Gateway **Least Latency** load balancing can use time to first token of streaming requests. Metrics › AI › Performance shows TTFT p50 · p95 per model, and the trace timing bar marks the first token. An optional streaming health check, off by default and using LLM tokens, records the time to first token on every scheduled check. The Provider Health list Excel names the environments that could not be read and has a note column with the environment the figures come from and the figures of every environment. [See.](/en/ai-gateway/reports) APNZ-6901

- ### New Alert Triggers
**MongoDB Disk Percentage** fires when the filesystem that holds the MongoDB data of Apinizer passes a percentage threshold; through a mongos it gives one row per shard. **Elasticsearch Heap Percentage** checks the heap of every Elasticsearch node and gives one row per node. **Elasticsearch Shard Usage Percentage** compares the open shards with the shard limit of the cluster. **Remaining Expiration Days of License** fires when the license has fewer days left than the threshold. **SSL Certificate Remaining Duration** also scans every entry (alias) of the key stores. [See.](/en/monitor/alarm) APNZ-1634 APNZ-4319 APNZ-5663 APNZ-3801

- ### ACL Report: Blocked Endpoints and Request Counts
The ACL Report can list the endpoints a consumer is blocked from. It can also show the request count of each consumer per endpoint, for a chosen environment and period, in the table and in Excel. Access Control dialogs can allow or block all endpoints at once. A re-parse can keep new endpoints blocked for consumers that already have access. Scheduled ACL reports offer the **Endpoints** filter and the **Requests** column, and the run total counts every row. An ACL report with request counts needs an environment and a filter date range when you save it. The **Endpoints** filter also has **Endpoints of the API proxies without a grant**: for each consumer it lists the endpoints of the API proxies in the report scope that the consumer has no grant on, marked **No grant**, on screen, in Excel and in the Report Generator. The report is refused when it would list more rows than the report record limit allows. The report has **HTTP Method** and **Limit Plan** fields and Excel columns, and the organization access report in APIops returns the HTTP method of each method row and the Limit Plan of each consumer. [See.](/en/admin/identity-management/acl-report) APNZ-5799 APNZ-6441 APNZ-6387 APNZ-6293 APNZ-6388

- ### OpenTelemetry Export From Manager, Integration and Cache Calls
Manager and Integration can export traces and metrics over OTLP. Set `APINIZER_OTEL_ENVIRONMENT` to the environment whose OpenTelemetry settings they follow. REST requests, scheduled jobs and task-flow runs with their steps appear as spans under their own instrumentation scope (`com.apinizer.manager`, `com.apinizer.integration`). Native OTLP export records a client span for every gateway call to the Cache (operation, cache name, outcome; never keys or values). Cache calls of async policies and A2A/MCP background tasks appear under the request's trace. The Cache metrics are collected with the collector's `prometheus` receiver from `:9091/metrics`. gRPC and WebSocket requests continue the trace of an incoming `traceparent`; forwarding it to the backend is still HTTP/SOAP only. [See.](/en/develop/monitoring-analysis/opentelemetry-export) APNZ-6535

- ### One Search Line in API Traffic
API Traffic has one search line. Up to 6 quick fields and the **Advanced** condition tree work together, and **Search** runs both. **Apply saved filter…** copies the conditions of a saved query to the screen. The message body criteria have a **contains the word** operator that matches whole words. New criteria are Endpoint, Correlation Id, Routing Address, Routing Retry Count, Routing Failover Count, Backend Status Code, Routing Failure Reason, API Proxy Group, Canary Request, Canary Status and Mirror Traffic. In the date selector you can type an absolute date as `yyyy-MM-dd HH:mm`; text that is not a date keeps the applied range. [See.](/en/analytic/api-traffic) APNZ-4078 APNZ-6414 APNZ-6418 APNZ-5266 APNZ-5210 APNZ-6477 APNZ-5591

The API Traffic log settings list shows the values in effect for each API Proxy, environment and connector, with the deployment state and the reason a connector is off. **Apply to selected** and **Apply to filtered results** change the log settings of many API Proxies, in groups of 50. - ### Alert, Anomaly Detector and Uptime Results
Alerts, anomaly detectors and uptime monitors end every run with one of five results: a violation (Threshold Exceeded, Anomaly Detected or Down), a normal result, Evaluation Error, No Data or Suppressed. A value that cannot be read is an Evaluation Error, never 0. **Execution Mode** sends a notification for every violating run or once for each series, and a **Recovery** notification closes a series. **If no data** decides what a No Data run does. A daily **Maintenance window** records results as Suppressed and sends no notification. The History tab filters by result and can show only the state changes. A row that cannot be checked shows **Not monitored**, for example `1 of 2 breached · 2 not monitored`. [See.](/en/monitor/alarm#results-events-and-notifications) APNZ-6512 APNZ-7002 APNZ-4150 APNZ-5215

- ### Anomaly Detector: No Data, Each API Proxy and Open in Traffic
A condition with nothing to measure ends as **No Data**, not 0, and a detector that is still collecting data shows **Warming up**. When Elasticsearch cannot be read, the result is an Evaluation Error. **Evaluate conditions for** can track the whole scope or **Each API Proxy**, with its own baseline, notification and recovery, and a **State by API Proxy** table. **Open in Traffic** in the History opens the traffic of that run, with **Back to results**. The metric list has the 95th and 99th percentile. [See.](/en/monitor/anomaly-detector#open-in-traffic) APNZ-3864 APNZ-4851 APNZ-4672 APNZ-4438 APNZ-6512

- ### Uptime: Service Level and Badge on the API Proxy
The health check detail page has a **Service level** card with the uptime of the last 24 hours, 30 days and 90 days, and a **Daily Summary** view. Failed checks inside a maintenance window are Suppressed and are not counted. The header of an API Proxy shows an uptime badge, for example `Uptime 99.9% · 2 monitors`, or **Not monitored**. [See.](/en/monitor/api-health-check#uptime-badge-in-the-api-proxy-header) APNZ-2458 APNZ-6512

The counter `apinizer_api_traffic_error_count_tagged` has a `status_code` label with the HTTP status sent to the client. Values outside 100–599 are reported as "other". A selector without aggregation returns one series per proxy, group and status code, so aggregate with `sum by (...)`. The metrics endpoint on `:9091` has no authentication. - ### Elasticsearch Errors and Disabled Connections
Dashboard, metrics, portal analytics and AI reports show an Elasticsearch error instead of "no data" or zero when Elasticsearch answers with an error. When a log connection is disabled, reads that use it return "Elasticsearch connection disabled". Disabling a connection through APIops takes effect for reports at once. One connector that several environments share is no longer counted twice. APNZ-7030

- ### Anomaly Detector and Uptime Monitor
SUM-based anomaly conditions treat zero traffic as No Data; "below X" SUM detectors stay silent on zero traffic unless the detector is set to notify on no data. Uptime check retention keeps today's checks until the daily summary has run, and never deletes the checks of the last 24 hours. A monitor whose summary failed keeps its checks of the last 120 days. Uptime logs, results and notifications show the target URL with the user name, password and query values masked, including `${monitor.uptime.targetUrl}` in notification templates. APNZ-7030

- ### Reports and Filters
A report of a project reads that project only, in preview, run now, export and schedule. Route Conflict and ACL Audit reports are limited to the project of the report. A report or anomaly detector can link only a query or filter of its own project or of the Administration project. Reports whose scheduled job is lost show **Not scheduled**. APIops saved query results omit `totalMs` for a record without a total time; Manager shows Cache Hit "Unknown" and latency "-" for such records. Saving a filter updates its linked copies in reports and anomaly detectors. APNZ-7030

- ### Permissions
The analyzer role still reads Uptime and Anomaly results of every project but cannot delete them, alert history, report results or API proxy traces. Deleting these needs a system admin or the manage permission of the feature in the project. Deleting a report needs a system admin or ANALYTICS manage in the project of the report. A global policy delete checks the permission before it deletes. APNZ-7049

- ### APIops Secrets in the Administration Project
Through the path of a project, APIops reaches a global certificate, keystore, key or JWK of the Administration project by name only for a system administrator or a user with the Secrets permission in the Administration project. Other callers get "not found". APNZ-7030

- ### Security of DB-2-API, Script-2-API and Mock API
DB-2-API Try SQL and API proxy trace records require the project permission of the definition or proxy. Try SQL runs only on the pools of the project or of Administration. DB-2-API definitions use only pools of their own project or of Administration on every save path, including APIops and import. Saving a DB-2-API, Script-2-API or Mock API keeps its project and changes only the API proxies of that project. An API proxy routes only to a definition of its own project; on import, other references are removed and reported. APIops promotion does not overwrite or move an API proxy or proxy group of another project. APIops API proxy update endpoints answer 400 instead of 500 when a save rule refuses the change. The Try SQL audit record stores no edited SQL text and no database error text. The Script-2-API and Mock API name checks and the **Manage API Proxies** lists of a definition require permission in the project of the definition and show only the API proxies of that project. APNZ-7030
