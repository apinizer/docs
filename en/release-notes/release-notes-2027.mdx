## Version 2027.01.0

:::warning Before you upgrade

- **An API proxy that routes to a DB-2-API, Script-2-API or Mock API definition of another project can no longer be saved.** An API proxy routes only to a definition of its own project. Recreate the API proxy from a definition of its own project, or import it with **Replace Existing**. The import removes the reference and reports it.
- **Text criteria "is equal to" and "not equal" now compare the whole value and ignore letter case.** Before, they compared a part of the value. Saved reports and anomaly detectors that use these criteria can return different results. Client IP "is equal to" no longer matches 10.0.0.10 for 10.0.0.1. A wildcard `*` works as before.
- **AI count alerts use the selected Period as the search window.** This applies to PII detection, guardrail hit, provider failover, quota soft-cap and quota alerts: minute = 1 minute, day = 24 hours, month = 30 days. Existing alerts keep their one-hour window until you change the Period.
- **Alert, Anomaly Detector, Uptime Monitor, Quota Alert, Task Flow and Promotion action templates resolve `${NAME}` only to a variable of the object's project or of the Administration project.** A variable of another project stays as typed. A report template follows the same rule.
- **A Quota Alert of a project evaluates and notifies only counters of its own project or of the Administration scope.** Counters of other projects no longer trigger it and do not appear in its counter list. Quota Alerts in the Administration scope do not change.
- **A saved "Organization Based" ACL report runs organization based, so its layout changes.**
- **The traffic log fields for request and response body size count bytes instead of characters.**
- **A connector added to an environment after the upgrade does not write logs until you turn it on.** Open the traffic log settings, turn on **Active for this environment** and save. The upgrade writes explicit entries for the connectors that exist. An APIops update of the connector settings replaces the whole connector map, so connectors you do not list stop logging. Upgrade Manager first, wait for the migration to finish, and then restart the Gateway Engine instances. [See.](/en/analytic/api-traffic-log-settings)
- **The alert trigger "API Traffic Exist in Database" is named "Unsent Traffic Logs Exist in Database".** Notification texts that use the trigger type show the new name.

:::

- ### Traffic Tab on the API Proxy Group Page
The API Proxy Group page has a **Traffic** tab. It lists the requests that came through the group, with the same filters, record details and Excel export as the API Proxy Traffic tab. [See.](/en/develop/api-proxy-group-creation) APNZ-4492

- ### Audit of Log Access
Log searches, log record views and log exports write an audit event with the user and a filter summary. This covers traffic, AI traffic, audit records, login and token records, test console audit, security events, application logs, and API and AI traces. DB-2-API **Try SQL** is audited too. SIEM destinations that use the v2 profile receive the log type, filters, time range, environment and result count of these records. [See.](/en/admin/system-settings/siem-log-forwarding) APNZ-4703

- ### Used By Panel and Names of Users in Delete Refusals
A record that other records use cannot be deleted. The refusal names the records that use it: up to five names and "and N more". Usages in other projects are counted. Connections (including Kafka, Webhook and the other connection types), LDAP settings, certificates, key stores, cryptographic keys, knowledge bases and IP groups are checked against every use. Records that are deleted together with their parent are not changed. Removing an LLM model that is still in use is refused in the same way and names the users. APNZ-7050

- ### New Places in the Menu
Administration > Identity > ACL Report moved to Administration > API Governance > Inventory Reports > ACL Report. Administration > Gateway Infrastructure > Route Analysis moved to Administration > API Governance > Route Analysis. The admin API Growth and Endpoint Growth reports moved from the Metrics tabs to Administration > API Governance > Inventory Reports; old bookmarks redirect. The API Growth list view is removed; the list is Administration > API Governance > API Proxies. API Governance also lists API Proxies, Proxy Groups, Global Policies, Integrations and API Creators of all projects, and AI Governance lists LLM Gateways, MCP Gateways and A2A Gateways, all read-only. The ACL Report of a project stays under Identity.

- ### Report E-mail With an HTML Table
The `{{report.resultTable}}` variable puts the first 25 rows of the report in the e-mail as an HTML table, for every report type. Metric reports add the Total row. [See.](/en/monitor/alarm) APNZ-7030

- ### Provider Health: Time to First Token
Provider Health shows TTFT p50/p95 per provider for the last 24 hours. The cell shows the exact figures of the environment with the most streaming requests, with its name. A tooltip lists the figures of every environment; there is no combined value. LLM Gateway **Least Latency** load balancing can use time to first token of streaming requests. Metrics › AI › Performance shows TTFT p50 · p95 per model, and the trace timing bar marks the first token. An optional streaming health check, off by default and using LLM tokens, records the time to first token on every scheduled check. [See.](/en/ai-gateway/reports) APNZ-6901

- ### MongoDB Disk Percentage Alert
Alerts get a **MongoDB Disk Percentage** trigger. It fires when the filesystem that holds the MongoDB data of Apinizer passes a percentage threshold. Through a mongos, it gives one row per shard. [See.](/en/monitor/alarm) APNZ-1634

- ### ACL Report: Blocked Endpoints and Request Counts
The ACL Report can list the endpoints a consumer is blocked from. It can also show the request count of each consumer per endpoint, for a chosen environment and period, in the table and in Excel. Access Control dialogs can allow or block all endpoints at once. A re-parse can keep new endpoints blocked for consumers that already have access. Scheduled ACL reports offer the **Endpoints** filter and the **Requests** column. An ACL report with request counts needs an environment and a filter date range when you save it. [See.](/en/admin/identity-management/acl-report) APNZ-5799 APNZ-6441 APNZ-6387

- ### OpenTelemetry Export From Manager, Integration and Cache Calls
Manager and Integration can export traces and metrics over OTLP. Set `APINIZER_OTEL_ENVIRONMENT` to the environment whose OpenTelemetry settings they follow. REST requests, scheduled jobs and task-flow runs with their steps appear as spans under their own instrumentation scope (`com.apinizer.manager`, `com.apinizer.integration`). Native OTLP export records a client span for every gateway call to the Cache (operation, cache name, outcome; never keys or values). Cache calls of async policies and A2A/MCP background tasks appear under the request's trace. The Cache metrics are collected with the collector's `prometheus` receiver from `:9091/metrics`. [See.](/en/develop/monitoring-analysis/opentelemetry-export) APNZ-6535

- ### One Search Rule on Report and Dashboard Screens
Report and dashboard screens run once on open with a short default. After that, results change only when you press **Search**, and the bar shows how many changes are not applied yet. Endpoints and Consumers with No Requests run only after Search. API Growth and Endpoint Growth open on the last 30 days with a Daily interval. APNZ-6999

- ### Growth Reports Group by Routing Address
API Growth and Endpoint Growth can group counts by routing address: backend host, LLM provider, or MCP/A2A server. The API Growth Excel file uses the same grouping. The API Proxy Groups list Excel has an **Environment** column with the environments each group is deployed to. APNZ-4314 APNZ-5186

- ### Report Generator Export Limit
Report Generator Export follows the **Email Attachment Max Size** setting instead of a fixed 25 MB, and the error shows the configured size. APNZ-4427

- ### Optional Trigger for Integrations
The trigger of an integration is optional. Turn off **Run on schedule** to run an integration only with Execute or through its endpoint. APNZ-4660

- ### Integration Server Status
The Integration server status shows **Reachable**, **Not Reachable** or **Not configured**, and the detail page explains the state. APNZ-3686

- ### Application Logs Download
Download needs a time range of at most 7 days and holds at most 100,000 records. A larger result is cut, and the screen says so. [See.](/en/admin/audit-compliance/application-logs)

- ### Notification Date Format and Source
You can choose the date format of notification date variables (alert, anomaly, uptime, report, promotion) in System Settings. The default stays `yyyy-MM-dd HH:mm:ss`. Every in-app notification records its source (Alert, Anomaly Detector, Uptime Monitor, Quota Alert, Report, Task Flow, Promotion). The Notifications page can filter by source and exports it to Excel. APNZ-3913 APNZ-6081

- ### Quota Alert for Selected Proxies and Groups
A Quota Alert can be limited to selected API proxies or proxy groups, so only their quota counters are evaluated. The action editor lists the `{{quota.alert.*}}` variables the alert fills. APNZ-3894

- ### Queries Row Menu
The row menu of a saved query offers **With this query** actions for the monitoring features that can use the query. APNZ-3605

- ### Run a Report Generator Report With APIops
APIops can now run a Report Generator report by name and get its headers, rows and Total row as JSON. [See.](/api-reference/reports/run-report-configuration) APNZ-6064

- ### APIops Proxy Report
The APIops API proxy report shows the creation type of each proxy and marks Reverse Proxy records. It lists the member proxies of each group by name. A proxy with a hidden spec no longer shows its spec URLs. APNZ-3560

- ### Prometheus Metrics With status_code and Group Labels
The counter `apinizer_api_traffic_error_count_tagged` has a `status_code` label with the HTTP status sent to the client. Values outside 100–599 are reported as "other". The request and response body size metrics (`apinizer_api_traffic_request_size`, `apinizer_api_traffic_response_size`) report bytes. A selector without aggregation returns one series per proxy, group and status code, so aggregate with `sum by (...)`. The metrics endpoint on `:9091` has no authentication. [See.](/en/operations/administrator-guides/gateway-metrics-integration/gateway-metrics-overview) APNZ-5172 APNZ-5173 APNZ-5977

- ### AI OTLP Trace Shows the Routing Decision
An AI request's OTLP trace also shows the conditional-route decision. The trace tree, the no-content rule and the behaviour with an unreachable collector are verified against a real collector. APNZ-6903

- ### Elasticsearch Errors and Disabled Connections
Dashboard, metrics, portal analytics and AI reports show an Elasticsearch error instead of "no data" or zero when Elasticsearch answers with an error. When a log connection is disabled, reads that use it return "Elasticsearch connection disabled". Disabling a connection through APIops takes effect for reports at once. One connector that several environments share is no longer counted twice.

- ### Anomaly Detector and Uptime Monitor
SUM-based anomaly conditions treat zero traffic as No Data; "below X" SUM detectors stay silent on zero traffic unless the detector is set to notify on no data. Uptime check retention keeps today's checks until the daily summary has run, and never deletes the checks of the last 24 hours. A monitor whose summary failed keeps its checks of the last 120 days. Uptime logs, results and notifications show the target URL with the user name, password and query values masked, including `${monitor.uptime.targetUrl}` in notification templates.

- ### Reports and Filters
A report of a project reads that project only, in preview, run now, export and schedule. Route Conflict and ACL Audit reports are limited to the project of the report. A report or anomaly detector can link only a query or filter of its own project or of the Administration project. Reports whose scheduled job is lost show **Not scheduled**. APIops saved query results omit `totalMs` for a record without a total time; Manager shows Cache Hit "Unknown" and latency "-" for such records.

- ### Permissions
The analyzer role still reads Uptime and Anomaly results of every project but cannot delete them, alert history, report results or API proxy traces. Deleting these needs a system admin or the manage permission of the feature in the project. Deleting a report needs a system admin or ANALYTICS manage in the project of the report. A global policy delete checks the permission before it deletes. APNZ-7049

- ### APIops Secrets in the Administration Project
Through the path of a project, APIops reaches a global certificate, keystore, key or JWK of the Administration project by name only for a system administrator or a user with the Secrets permission in the Administration project. Other callers get "not found".

- ### Security of DB-2-API, Script-2-API and Mock API
DB-2-API Try SQL and API proxy trace records require the project permission of the definition or proxy. Try SQL runs only on the pools of the project or of Administration. DB-2-API definitions use only pools of their own project or of Administration on every save path, including APIops and import. Saving a DB-2-API, Script-2-API or Mock API keeps its project and changes only the API proxies of that project. An API proxy routes only to a definition of its own project; on import, other references are removed and reported. APIops promotion does not overwrite or move an API proxy or proxy group of another project. APIops API proxy update endpoints answer 400 instead of 500 when a save rule refuses the change. The Try SQL audit record stores no edited SQL text and no database error text.

- ### Connections in Use Cannot Be Deleted
A connection that an environment uses (Elasticsearch, Graylog, Syslog, Kafka, RabbitMQ, ActiveMQ, Logback, Webhook, FTP) can no longer be deleted. An Email, SNMP, Linux Script or DB pool connection that an alert, monitor, report, integration, portal, database authentication or log setting uses cannot be deleted either. APIops delete follows the same rule. APNZ-7050

- ### Dashboard Active Alerts Card
When Manager cannot read the results of one monitoring engine, the active alerts card shows the other engines and names the failed one. Monitor lists show an error instead of an empty list.

- ### User Audit Without a Date Range
A user audit list or Excel without a date range returns the last hour with the filters applied, instead of every record.

- ### Uptime Without Assertions
An Uptime monitor without assertions reports Down for a target that cannot be reached.
