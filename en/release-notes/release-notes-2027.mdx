## Version 2027.01.0

<span style={{ display: 'inline-block', backgroundColor: '#e65a2a', color: '#ffffff', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>BUG FIXES</span>

- ### Promotion Instance Endpoints Require System Admin or Promotion Manager
Promotion instance endpoints now require System Admin or Promotion Manager. The promotion wizard's pickers stay open to users with the PROMOTION permission in any project, and remote project and API lists no longer carry routing passwords. Execution details require PROMOTION View in the execution's source project. [See](/en/admin/api-promotion/overview#permissions) APNZ-7208

- ### Permission Required for Spec Import, Test Console Import, Certificate Fetch and Promotion Connection Test
Spec import from URL or file, Test Console import from URL, certificate fetch from URL and promotion instance connection test now require the permission of the screen that uses them. Requests without that permission get HTTP 403. [See](/en/develop/api-proxy-creation/api-proxy-creation) APNZ-7205

- ### Manager and API Portal Login Ignore Remember Me
The Manager and API Portal login now give every token the normal token validity (`token-validity-in-seconds`). A client that sends `rememberMe: true` to `/api/authenticate` gets this validity and no error. Tokens issued before the upgrade keep their original expiry, up to 30 days. Refresh does not extend or shorten it. The config key `token-validity-in-seconds-for-remember-me` is still accepted and ignored, so old configs still start. APNZ-7204

- ### Array Paths in XML to JSON Conversion Fixed
An array path such as `root#liste#aciklama` now converts the last element to a JSON array under every repeated parent, at any depth. Before, the element stayed a single value when the parent repeated two or more times. This applies to the REST to SOAP response transformation, the XML Transformation policy, Redaction, Business Rule policies and the XML transformation test tool. [See](/en/develop/policies/xml-transformation) APNZ-7171

- ### Portal Test Screen and MCP Token Tool Refuse Tokens That Cannot Work
Some token policies issue tokens only to the API's own client, not to an application credential. This applies to an OAuth2 policy that manages its own keys. It also applies to a JWT policy whose keys the portal does not publish. For these APIs, the portal test screen now disables **Authorize** and shows a hint. The `get_token` MCP tool refuses the request and `get_api_auth_info` says that the portal cannot get a token. The portal sends no request to the gateway. [See](/en/api-portal/api-product) APNZ-6092


- ### API Portal Upgraded to Angular 22, Closing CVE-2026-88059
API Portal now runs on Angular 22.2.3. This closes the vulnerability CVE-2026-88059 that a security scan reported on API Portal. The fix is in Angular 22.1.1 and later. API Portal does not use server-side rendering, so the server-side rendering cache issue was not exploitable before the upgrade. APNZ-6932
