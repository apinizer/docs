## Version 2027.01.0

:::warning Before you upgrade

- **SQL/JDBC failover connector only: run the failover table script before you upgrade.** If a log connector of your installation (an environment log connector or a SIEM destination) uses a relational database (Oracle, MySQL, PostgreSQL, or SQL Server) as its failover connector, run the script **before** you upgrade the Manager and the gateways to 2027.01.0. This version adds the `log_type` column to `log_UnsentMessage`. The gateway writes it with every failover insert, so until the script runs, every failover insert fails and the log records are lost when the primary destination is down. Do not run the script twice: adding a column that already exists raises an error. Installations that use MongoDB as the failover connector skip this step. [2027.01.0 — Log Table ALTER Scripts](/en/release-notes/2027-01-0-log-table-alter)

- **APIops refuses a request body with an unknown field.** The call answers `400` with the error key `unknownField`, and nothing is saved. Check the field names of your automation against the API Reference before you upgrade. [See](/api-reference/apiops-common-contract#unknown-fields) APNZ-7023

- **A record that other records use can no longer be deleted.** The refusal names the records that use it; APIops delete follows the same rule.

- **DB-2-API, Script-2-API, Mock API, task flow run logs, Quota Alerts and `${NAME}` variables work inside one project.** An API proxy routes only to a definition of its own project, and a variable of another project stays as typed.

- **Text criteria "is equal to" and "not equal" now compare the whole value and ignore letter case.** Saved reports and anomaly detectors that use them can return different results.

- **The MCP `server.json` document shows the access URL of the environment.** On an environment with one address, `remotes[].url` no longer echoes the request host or `X-Forwarded-Host`. If the environment is behind an ingress, enter the external address as the **Access URL** or as an additional access URL. [See](/en/admin/server-management/gateway-runtimes#access-urls) APNZ-7174

- **A connector added to an environment after the upgrade does not write logs until you turn it on.** Turn on **Active for this environment** in the traffic log settings.

- **Existing AI Token Usage Percentage and AI Daily Cost Threshold (USD) alarms switch to Execute once for same violation series.** You can change the **Execution Mode** of each alarm.

:::

- ### Several Access URLs for One Environment
An environment can have more named access URLs, for example an internal and a public address, so you do not need a second environment. Specification documents (OpenAPI, Swagger, WSDL, XSD, WADL), the MCP `server.json` document and the A2A agent card show the address that matches the request. In the Client Route of an API proxy or an API proxy group, **Published Access URLs** selects the addresses that the proxy shows. The selection does not change routing or access. The API Endpoint report now includes the proxy path in the **Access URL** column. The OAuth `.well-known` documents now read the RFC 7239 `Forwarded` header when the request has no `X-Forwarded-*` header. Add the additional addresses after all API Manager pods run the new version. [See](/en/admin/server-management/gateway-runtimes#access-urls) APNZ-7174

- ### WebSocket API Proxy Carries Socket.IO Clients
A WebSocket API proxy can now carry the HTTP long-polling requests of Socket.IO clients. Select **Socket.IO Compatibility** in the connection settings of the proxy and set the **Read Timeout**. The request and response policies, the Rate Limit Control List and the Limit Plan run on a polling request. After the backend confirms the Socket.IO session, the heartbeat frames no longer write one traffic record each, and the record that closes the connection carries a heartbeat summary. The APIops WebSocket settings call has the new `socketIoEnabled` field. [See](/en/develop/routing/websocket-routing#socket-io-compatibility) APNZ-6140

- ### WebSocket API Proxy Carries SignalR Clients and Allowed Subprotocols
Select **SignalR Compatibility** in the connection settings of a WebSocket API proxy, and the proxy carries the negotiate, Server-Sent Events, long-polling, send and close requests of ASP.NET Core SignalR clients. Before, these requests got HTTP 404 with `ERR-006`. In **Allowed Subprotocols**, list the subprotocols that your clients require, for example `graphql-transport-ws` or `mqtt`. The APIops WebSocket settings call has the new `signalREnabled` and `allowedSubprotocols` fields. [See](/en/develop/routing/websocket-routing#signalr-compatibility) APNZ-6378

- ### APIops Reads the Validity of Its Own Token
The call `GET /apiops/auth/me/token` answers the name, the creation date, the expiration date and the remaining seconds of the token that sent the request, so a pipeline can renew the token before it expires. The answer never carries the token value. [See](/api-reference/auth#get-current-token) APNZ-7079

- ### APIops Consumer Access Report
The call `GET /apiops/reports/consumer-access` lists, for each consumer, the API proxies and API proxy groups that it may call. A user without a system role reads only the projects where the user has the Identity View permission. You can filter by project, organization, consumer key or text, and sort by username or full name. [See](/api-reference/reports/consumer-access-report) APNZ-7249

<span style={{ display: 'inline-block', backgroundColor: '#bfdbfe', color: '#1e40af', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>CHANGES AND IMPROVEMENTS</span>

- ### Secrets Stored Encrypted, Test Console History and Uptime Texts
The API Manager now stores the secrets of API proxy policies and routing, policy groups, proxy groups and global policies in encrypted form. Test Console History stores a request as you wrote it, and a failed check with a variable in its URL shows only the error type. The **Save** button of the Access tab shows the gateway result in the deploy result window, and shows a failure when an environment did not receive the change. Read the upgrade notes before you upgrade. [See](/en/upgrade/apinizer-version-upgrade) APNZ-7186

- ### WebSocket API Proxy Spreads Clients Over Its Addresses
A plain WebSocket proxy (Socket.IO and SignalR Compatibility off) with two or more primary addresses now spreads clients over the addresses by client IP address and skips an address that the health check marks unhealthy, as it already did with Socket.IO or SignalR on. Before, every connection went to the first address. Read the upgrade notes before you upgrade. [See](/en/develop/routing/websocket-routing#routing-address-distribution) APNZ-6378

- ### WebSocket Subprotocol Check, Idle Time and Close Codes
If the backend selects a different subprotocol than the one the gateway told the client, or none, the client connection is now closed with 1002 (protocol error). Before, it stayed open. A message that the backend sends to the client now restarts the idle time, so a client that only receives a feed stays connected. When the backend connection ends with a code that cannot be sent in a close frame (for example 1006), the client now gets a code that it can receive (1011). With **Auto Reconnect** on, a WebSocket connection whose new backend connection selects another subprotocol is closed with 1002, as on the first connect. [See](/en/develop/routing/websocket-routing#allowed-subprotocols) APNZ-6378, APNZ-6140

- ### Streaming Requests End Normally When the Client Leaves
On a REST API proxy with **Enable Server-Sent Events (SSE)** on and on a SignalR event stream, a client that closes the stream after data reached it now ends the stream normally. The traffic record shows the status code of the backend as a success, no error with a stack trace is logged, and the request is not sent to the backend again (Retry Count). A client that resets its connection before any data reached it is still logged as 499, now without a stack trace and without a retry. A streamed response whose client leaves only at the final close is recorded as a normal end and is not sent to the backend again. [See](/en/develop/routing/http-routing#server-side-streaming-sse) APNZ-6378 When the backend drops the connection after part of a streamed answer has reached the client, the gateway no longer sends the request to the backend again (Retry Count) or to a failover address, and the traffic record shows the backend error (502). Before, the gateway sent the request again and the record showed a client-closed error (499).

- ### Streaming Requests Build No Trust Store for Each Request
A streaming request (REST API proxy with **Enable Server-Sent Events (SSE)** on, SignalR event stream) no longer builds a trust store and no longer writes two INFO lines for each request. A certificate that you add or remove still reaches the next request without a redeploy. APNZ-6378

- ### Used By Panel and Delete Checks Read Less Data and Run Faster
The Used By panel and the delete checks now read an API proxy without its imported specification text and WSDL/XSD bodies, and read a large API proxy collection in parts at the same time. A reference that is only typed into an imported specification or schema text is no longer counted as a use. The new system settings **Usage Scan Parallel Reads** and **Usage Scan Parallel Read Threshold** control the parallel read. [See](/en/admin/system-settings/system-settings-and-limits#mongodb-usage-scan) APNZ-7030

- ### Mask Shape Keeps the First N and the Last M Characters, Privacy Rules Edit in One Window
A privacy rule can now keep the first N and the last M characters of a value and mask the rest, for example `1234******123456`. The API proxy log settings, the method override and the Policy Log privacy tables now show the rule type, the element or pattern, the operation and the mask shape, and edit a row in the same rule window as the environment screen. A rule that you change in this window marks the form as changed. [See](/en/develop/api-proxy-configuration/api-traffic-log-settings#mask-shape) APNZ-5825, APNZ-6963

- ### Method Override Privacy Inherits From the Proxy
A new method override starts with privacy **Inherited from the proxy-level settings**, and the gateway applies the privacy rules of the proxy to that method. The **Method Overrides** section appears only for a proxy that has API methods. In APIops, a method override without `enablePrivacy` inherits the proxy-level setting. [See](/en/develop/api-proxy-configuration/api-traffic-log-settings#method-overrides) APNZ-5515

- ### Application Log Names the Policy
A log line that is written while a policy runs now carries the name and the type of the policy. The log detail window shows them in the **Policy** row, and they are in the MongoDB and Graylog log targets and in the SIEM data. [See](/en/develop/monitoring-analysis/application-logs#policy-name-and-type-in-a-log-line) APNZ-5170

- ### Minimum MongoDB Version Is 5.0
Apinizer 2027.01.0 requires MongoDB 5.0 or later. Upgrade MongoDB 4.4 before you upgrade Apinizer. Read the upgrade notes before you upgrade. [See](/en/concepts/deployment/software#mongodb-requirements)

- ### Key Store Update Marks the Proxies That Use It
When a key store update changes what the gateway loads (the file, the password, the key alias, the type or the environments), the API Manager marks every deployed API proxy and proxy group that uses the key store as **Redeploy required**. After the redeploy, the OIDC, MCP and A2A connections of the proxy present the new client certificate. The key store update reads its users at that moment, so an API proxy bound to the key store a few seconds earlier is marked too. [See](/en/admin/secrets-management/keystore-management#proxies-that-use-the-key-store) APNZ-6943

- ### API Proxy Save Refuses a Key Store or Trust Store of Another Project
API proxy save now refuses a routing, AI routing or MCP / A2A backend server mTLS setting that names a key store or trust store of another project. Stores of the proxy's own project and of the shared administration scope are accepted. Read the upgrade notes before you upgrade. APNZ-7189

- ### Portal Reports Overview Opens the Request Detail for Portal Roles
Portal Manager and Portal Business users can now open the request detail of a traffic row in Portal Reports > Overview. The detail shows only records of the selected portal, with credential header values masked. [See](/en/api-portal/traffic-and-usage) APNZ-7217

- ### APIops Consumer and Application Take the Owner Settings of the Consumer Screen
The APIops consumer and application calls now read and write the external flag, the geolocation list, the IP lists of the environments, the identity service and the JWT regenerator service. The password of an environment is never returned, and a write keeps it. [See](/api-reference/consumers-and-applications#owner-settings) APNZ-7128

- ### APIops Refuses a Request Body With an Unknown Field
Every APIops request that has a body now answers HTTP 400 with the error key `unknownField` when the body has a field that the call does not know, and nothing is saved. The answer lists the full path of each field, for example `actionList[0].targetValue`. A request with an invalid token still gets HTTP 401 first. You can send the answer of a GET call back unchanged in a PUT or POST call. Read the upgrade notes before you upgrade. [See](/api-reference/apiops-common-contract#unknown-fields) APNZ-7023

- ### Certificate, Key Store and Private Key Reads Return the File Only on Request
The Manager calls `GET /api/certificates/{id}`, `GET /api/key-stores/{id}` and `GET /api/crypto-key-infos/{id}` now return the file or the key content only with `?includeFile=true`. Without it the record comes back without the bytes. The `includeFile=true` read needs **View** or **Manage** in the Secrets & Certificates category of the project of the record (or the System Administrator role), writes one **Secret Revealed** audit record, and is sent with `Cache-Control: no-store`. A save without the bytes keeps the stored bytes, and create, update and delete answers carry no bytes. The key store password is never in a `GET` answer: you read it with the reveal action and a written reason. These APIops reads now write a **Secret Revealed** record too: key store and key export, JWK file export, portal application credentials, full promotion certificates, and a full API proxy that carries an embedded JWK key. Read the upgrade notes before you upgrade. [See](/en/upgrade/apinizer-version-upgrade) APNZ-7169

- ### Report Screens Show a Warning When the Elasticsearch Answer Is Too Large
When the Elasticsearch answer for a Report Generator query, an export or a query preview is larger than the limit, the screen now shows a yellow warning that asks you to narrow the date range or the filters. Before, it showed a red error or nothing. The new **Elasticsearch Response Max Size** setting in System Settings (default 25 MB, 1 MB - 100 MB) sets the limit for the Report Generator, reports, API Traffic, the Portal Traffic lists and analytics, and applies right after you save it. A higher value uses more API Manager memory. The reporting settings now show the **Applied on Save** badge. The "result too large" warning on report screens now closes when you leave the page, and the ACL report shows a separate, correct message when the request counts cannot be read in time. [See](/en/admin/system-settings/system-settings-and-limits) APNZ-4753

- ### WebSocket API Proxy Fixes
On a WebSocket API proxy, a successful backend connection (HTTP 101) is now recorded as Successful, so the error counts of dashboards and reports fall by one for each connection. The client address of a WebSocket connection (traffic record, IP allow and block lists, Limit Plan Target Audience, scripts) is now the IP of the connection without a port, as on HTTP. Before, an exact IP entry in an allow list could refuse the client and the same entry in a block list could let it pass; such entries now work, so review the IP lists of your WebSocket proxies before you upgrade. A request without an upgrade now gets HTTP 404 with `ERR-006` instead of 500. With a root context and several relative paths, the longest matching path is cut, as in a REST API proxy. Escaped characters (for example `%2F`, `%20`, `%25`) in the path and in the routing address, and the query, reach the backend as they were sent. When the backend closes the connection, the close record of the backend side is kept also under a heavy log load. On every transport, when the Forwarded IP header is on and the selected item of the header is empty (for example `, 198.51.100.7`), the gateway now uses the address of the connection as the client address. Before, an empty client address passed the IP allow list, the IP block list and the IP restriction of a credential, and a value of only a comma gave an error. [See](/en/develop/routing/websocket-routing) APNZ-6140

- ### DB-2-API Answers a SQL ARRAY Column as a JSON Array
A DB-2-API request whose result has a SQL ARRAY column now answers with a JSON array, and an array of rows is written as rows, so the answer body is no longer empty. A NULL REF_CURSOR column is written as `null`. An answer that cannot be written as JSON now returns HTTP 500 with the text of the failed statement instead of an empty HTTP 200. APNZ-7244


- ### API Product Documentation Can Be Generated From the APIs, Try It Calls Only Product Addresses
An API product can now take its portal documentation from its API proxies and proxy groups instead of an uploaded file. The documentation updates when a proxy changes. Existing products keep the uploaded file. The portal Try It console now calls only the product's own gateway addresses and does not follow redirects. Upgrade API Portal together with API Manager. [See](/en/api-portal/api-product#documentation-source) APNZ-7146

- ### Array Paths in XML to JSON Conversion Fixed
An array path such as `root#liste#aciklama` now converts the last element to a JSON array under every repeated parent, at any depth. Before, the element stayed a single value when the parent repeated two or more times. This applies to the REST to SOAP response transformation, the XML Transformation policy, Redaction, Business Rule policies and the XML transformation test tool. [See](/en/develop/policies/xml-transformation) APNZ-7171

- ### Portal Test Screen and MCP Token Tool Refuse Tokens That Cannot Work
Some token policies issue tokens only to the API's own client, not to an application credential. This applies to an OAuth2 policy that manages its own keys. It also applies to a JWT policy whose keys the portal does not publish. For these APIs, the portal test screen now disables **Authorize** and shows a hint. The `get_token` MCP tool refuses the request and `get_api_auth_info` says that the portal cannot get a token. The portal sends no request to the gateway. [See](/en/api-portal/api-product) APNZ-6092


- ### API Portal Upgraded to Angular 22, Closing CVE-2026-88059
API Portal now runs on Angular 22.2.3. This closes the vulnerability CVE-2026-88059 that a security scan reported on API Portal. The fix is in Angular 22.1.1 and later. API Portal does not use server-side rendering, so the server-side rendering cache issue was not exploitable before the upgrade. APNZ-6932

- ### Trace Logs No Longer Store Credentials
When trace is on for an API proxy, the application log no longer stores the Authorization, Cookie and Set-Cookie values that the HTTP client header, wire and cookie logs write, the values of credential form fields sent to the backend, or the text of WebSocket messages written by the WebSocket client library. Apinizer's request and response header, query and form dumps show the names and hide the value of every credential name: Authorization, Cookie, the api-key names, and any name with token, secret or password. The Kafka connection debug line hides `sasl.jaas.config`. A logger that an operator sets to DEBUG or TRACE still writes as before. [See](/en/develop/monitoring-analysis/application-logs#credentials-in-trace-logs) APNZ-5170

- ### AI Streaming Requests Answer Like Other Requests When Every Provider Fails
When every provider fails before the first byte, a streaming AI request now gets the same answer as a request without streaming: HTTP 502 with the `X-Apinizer-AI-Exhausted` headers. Before, the client saw the status code of the provider, for example 503. A provider that accepts the connection and does not finish the TLS handshake now fails over within the connect time-out. Before, the stream time-out (120 seconds by default) had to pass. Read the upgrade notes before you upgrade. APNZ-7108

- ### Content Filter Predefined Rules Block Their Attacks
Twelve of the 26 predefined Content Filter rules matched no request, so a policy built from them let attacks such as `sql=' or` pass. They now block their attacks. The predefined rules window keeps its rows when you change the page or the page size. Read the upgrade notes before you upgrade. APNZ-5143

- ### Deploy, Undeploy and Save Skip Environments With 0 Instances
Deploy, undeploy and save operations no longer wait for, or fail on, an environment whose gateway Apinizer manages with 0 instances. The environment is listed as **Not Sent** and its gateway loads the saved state when it starts. An API proxy deploy to such an environment reports that clearly; an undeploy from it now succeeds. This covers the save or delete of a certificate, key store, crypto key or JWK. The APIops deployment result carries `skippedEnvironmentList` for these environments. [See](/en/admin/secrets-management/keystore-management#gateways-with-no-instances) APNZ-6968

- ### Organization Name Shows Correctly
The **Organization** column of the Consumer list Excel export now carries the name that the Consumer list shows. An organization that was created on the current form had an empty cell, and a renamed one its old name. Organization select boxes and the screens that name an organization show the same name. APNZ-7248

- ### Names With an Underscore or a Dot Stay as Written
An OpenAPI import no longer turns an underscore in a schema field name into a dot, so the `?openapi` output of the proxy is correct. A path with a dot, for example `/v1.0/users`, shows as stored on the Design screen, in export and in APIops. The upgrade converts the existing records. Read the upgrade notes before you upgrade. APNZ-7247

- ### E-Mail Connection Fixes
**Send Test E-Mail** and the API Portal e-mails now resolve environment variables in the host, the user name and the additional properties of the e-mail connection. The server certificate hostname check stays on. APNZ-4317

- ### Remote Cache Server Page Opens Without Cluster Permission
The cache server page no longer asks Kubernetes for nodes and namespaces for a remote cache server, so a restricted service account no longer causes a 403 error. APNZ-6288

- ### From Target Traffic Log Hides the Correlation Header
The From Target traffic log no longer shows the correlation header of the gateway. When the target itself sends a header with that name, the log shows the values of the target only. APNZ-6322

- ### JWK Generate, JOSE Key Test and APIops JWK Export Write No Misleading Warnings
Generating a JWK, the JOSE dynamic key test and the APIops full JWK export no longer write "could not be decrypted" warning lines to the log. APNZ-5872

- ### gRPC Client Address Variable
The **client address** context value variable of a gRPC call is now the client address as on HTTP and WebSocket, for example `127.0.0.1` with no port. When the proxy reads the Forwarded IP header, it is the element of that header. Before, it was the transport address text with a port. APNZ-6140
