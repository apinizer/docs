## Version 2026.10.0

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>REMOVED FEATURES</span>

**WARNING!** The **Token Quotas** screen and the budgets it saved are removed: the organization AI budget, the AI proxy application budget, the anonymous budget of the AI proxy routing, the project budget, and the default and default anonymous budgets in AI Gateway Settings. The upgrade removes the stored values. It does not convert them into Limit Plans. Recreate each limit as an AI Token Limit plan or as AI Proxy Protection in the Token Rate Limit policy. Export packages and APIops requests that still carry these fields are accepted. Apinizer ignores the fields and keeps the rest. [See](/en/ai-gateway/limit-plans#removed-ai-budgets)

**WARNING!** The APIops `/ai-budgets` endpoints (scope rules, hierarchy, effective limit and budget update) are removed. Use the Limit Plans endpoints instead. [See](/api-reference/limit-plans-management-api)

**WARNING!** The default budget fields of AI Gateway Settings, the application budget and routing anonymous budget fields of an API proxy, and the budget field of a project are removed from the Management API. [See](/api-reference/ai-gateway-settings/get-ai-gateway-settings)

**WARNING!** The **AI Budget Source** setting and the AI token budget of each environment on an API proxy access row are removed. [See](/en/ai-gateway/limit-plans#removed-ai-budgets)

**WARNING!** The **Project and Platform Limits** screen and the project and platform limit assignments are removed, for API Request Count and for AI Token Limit. A Limit Plan can be assigned to a consumer, an API client, an application, an organization, an API proxy (AI Gateway) or an audience rule. The gateways no longer enforce project or platform assignments. On upgrade, every project and platform assignment that was not ended is ended, and every enabled **AI Token Usage Percentage** alarm with the **Project** scope is disabled. The alarm is kept. Change its scope to **AI Gateway** and enable it again. The Manager REST API and the Management API refuse a new project or platform assignment, and a package import skips such an assignment file. [See](/en/ai-gateway/limit-plans#project-and-platform-limits-removed)

## Version 2026.09.6

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>REMOVED FEATURES</span>

**WARNING!** The model catalog and the separate **Models** page are removed. A model is now managed only inside its LLM provider. The provider definitions (the **Definitions** tab, custom provider definitions and **Clone from Catalog**) and the built-in seeded models and prices are removed too. [See](/en/ai-gateway/llm-providers#models)

**WARNING!** The allow-list of models of an LLM provider (**Allowed at gateway**) and the model lifecycle (the deprecated flag and **Sunset At**) are removed. Use the **Enabled** switch of a model instead. After the upgrade every existing model is switched on.

**WARNING!** The **Model Definition** export and import type and the APIops `/llm-models` endpoints are removed. The models travel inside their LLM provider. The `allowedModelIds` and `providerDefinitionId` fields of the LLM provider payloads are removed. [See](/api-reference/llm-providers)

**WARNING!** The typed access model is removed. Access is defined only on the ACL (the **Access Control** screen). The access entitlements and the API client authorization restrictions (Follow the owner, Deny all, Allow a subset) no longer exist, and nothing is carried over from them. See [Authorization of an API Client](/en/admin/identity-management/credentials#authorization-of-an-api-client).

**WARNING!** The **Authorization** tab of the API client, and the client mode, access and reach badges and columns of the **Access Control** screen, are removed.

**WARNING!** The access-entitlement REST endpoints and the API client restriction endpoints (`authorization-restrictions`) are removed. The APIops `/entitlements` sub-resources of consumers, applications and API clients, and the API client restriction section of APIops, are removed too. [See](/api-reference/api-clients)

**WARNING!** The **Access Entitlement** (`ACCESS_ENTITLEMENT`) export and import type is removed. An old package that still contains such files imports normally; each file is skipped with the advisory `accessEntitlement.removed`.

**WARNING!** Upgrade order: start the Manager first, then upgrade all Workers, and change ACL rows only after the last old Worker is gone. See [Apinizer Version Upgrade](/en/upgrade/apinizer-version-upgrade).

## Version 2026.09.3

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>REMOVED FEATURES</span>

**WARNING!** The Rate Limit Control List screen has been removed from the project and Administration menus. The records had already been converted into Limit Plans and assignments at upgrade; every limit is now managed from Limit Plans, which is also available under Administration → Identity Management for system administrators. Legacy records stay readable through the management API. [See](/en/admin/identity-management/rate-limit-control-list)

**WARNING!** The **Inherit** limit assignment mode has been retired. The gateway never resolved it — an Inherit assignment behaved exactly like Off — so it is no longer offered on the Limits tab, and existing Inherit assignments are converted to **Off** at upgrade. Gateway behaviour is unchanged. Use an organization's Default Limit Plans to give new consumers a starting limit. [See](/en/admin/identity-management/organizations#limits)

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>REMOVED FEATURES</span>

**WARNING!** The Rate Limit Control List has been retired; the gateway no longer evaluates these records. Your existing records were converted automatically into Limit Plans and assignments on upgrade, and the screen is kept read-only for viewing and deleting only. ## Version 2026.04.0

## Version 2024.09.0

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>FEATURES TO BE REMOVED</span>

**WARNING!** Due to the requirement for data owners to control the deletion of log records, the automatic deletion of log records with retention period in Monitor Screens, Application Logs, API Integration, and Reports pages has been removed. Purge scripts have been prepared for manual deletion of these records from the database. [See](/en/operations/overview#database-growth-management)

**IMPORTANT!** Snapshot policy screens used for automatic backup of Elasticsearch indices through Apinizer screens have been removed due to snapshot policy usage requirements. Necessary scripts have been prepared for manual execution of these operations. [See](/en/setup/installations-overview)

**WARNING!** All features related to the old revision logic have been removed due to usage difficulties. Now, completely switched to the "Deployment History" application started in Version 2023.06.1. Revision parameters in Apinizer Management APIs have also been removed. [See](/en/develop/deployment-and-version-management)

## Version 2024.05.3

<span style={{ display: 'inline-block', backgroundColor: '#e5e7eb', color: '#4b5563', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>REMOVED FEATURES</span>

**WARNING** Multiple API Proxy selection has been enabled in API Proxy Group. With this setting, the feature of applying policies in API Proxy Group to API Proxies has been removed as it existed before. [See](/en/develop/routing/http-routing)
