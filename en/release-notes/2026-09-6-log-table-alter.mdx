## Who needs this

This script is only relevant if your Apinizer installation writes API proxy traffic logs to a **relational database via the SQL/JDBC traffic-log connector** (Oracle, MySQL, PostgreSQL, or SQL Server).

**If you use the Elasticsearch or MongoDB connector, skip this page entirely** — those targets carry the new data without any manual step. On Elasticsearch the index template is updated and the index is rolled over automatically during the upgrade.

## What changed

Apinizer 2026.09.6 adds the LLM route classifier to AI routing. The traffic log records the classifier decision for every request that evaluated a classifier route.

**`log_ApiProxyTraffic` gains six columns:**

- `ai_route_cls_label` — the label the classifier picked.
- `ai_route_cls_outcome` — the outcome of the classifier decision.
- `ai_route_cls_latency_ms` — the classifier decision time in milliseconds.
- `ai_route_cls_token_in` — the input tokens the classifier used.
- `ai_route_cls_token_out` — the output tokens the classifier used.
- `ai_route_cls_cost_micro` — the classifier cost in micro-USD.

All six columns are nullable and sparse. They stay `NULL` for traffic that did not evaluate a classifier route. Existing rows stay `NULL`.

:::warning Run the script BEFORE you upgrade the gateway

The gateway INSERT names every column of `log_ApiProxyTraffic`. If these six columns are missing, **every traffic-log insert to this database fails** and the traffic records are lost. Run the script **before** you upgrade the gateway to 2026.09.6.

:::

## When to run it

Run this **once**, against each configured SQL/JDBC traffic-log database, before you upgrade the gateway to 2026.09.6. It does not need to be run inside a maintenance window. Because the columns are nullable, older gateway workers that still write pre-upgrade log rows are unaffected. Test in a non-production environment first if you use a change-control process for DDL.

This script is independent of the earlier ALTER scripts. If you upgrade from an older version, also run the scripts of the versions you pass through, in order (see [Apinizer Log Table Creation Commands](/en/operations/administrator-guides/apinizer-log-table-creation-commands)).

If you create the table from the `CREATE TABLE` statements on the [Apinizer Log Table Creation Commands](/en/operations/administrator-guides/apinizer-log-table-creation-commands) page of 2026.09.6, the table already has these columns and you do not run this script.

## Oracle

```sql
ALTER TABLE log_ApiProxyTraffic ADD (
    ai_route_cls_label VARCHAR2(64),
    ai_route_cls_outcome VARCHAR2(16),
    ai_route_cls_latency_ms NUMBER(19),
    ai_route_cls_token_in NUMBER(19),
    ai_route_cls_token_out NUMBER(19),
    ai_route_cls_cost_micro NUMBER(19)
);
```

## PostgreSQL

```sql
ALTER TABLE log_ApiProxyTraffic
    ADD COLUMN ai_route_cls_label VARCHAR(64),
    ADD COLUMN ai_route_cls_outcome VARCHAR(16),
    ADD COLUMN ai_route_cls_latency_ms BIGINT,
```

## Verification

After running the script, confirm the column count on `log_ApiProxyTraffic` increased by 6. For example, on PostgreSQL, MySQL, or SQL Server:

```sql
SELECT COUNT(*) FROM information_schema.columns WHERE table_name = 'log_ApiProxyTraffic';
```

On Oracle, count the columns in `USER_TAB_COLUMNS` for `LOG_APIPROXYTRAFFIC`. Then send a request through an AI API Proxy that has a classifier route and check the new columns:

```sql
SELECT correlation_id, ai_route_cls_label, ai_route_cls_outcome, ai_route_cls_latency_ms
FROM log_ApiProxyTraffic
WHERE ai_route_cls_label IS NOT NULL
ORDER BY log_timestamp DESC;
```
