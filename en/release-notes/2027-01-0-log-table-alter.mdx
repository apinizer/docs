## Who needs this

This script is only relevant if a log connector of your installation — an environment log connector or a SIEM destination — uses a **relational database via the SQL/JDBC connector** (Oracle, MySQL, PostgreSQL, or SQL Server) as its **failover connector**.

**If you use MongoDB as the failover connector, skip this page entirely.** The Manager creates the index on MongoDB automatically.

## What changed

Apinizer 2027.01.0 stores the record type with every record that a connector cannot send. The [Migrate Unsent Logs](/en/analytic/transfer-unsent-api-traffic-logs) screen and the alarm use the type to select the records.

**`log_UnsentMessage` gains one column:**

- `log_type` — the record type of the unsent record (API traffic, policy capture, token, audit, and so on).

The column is nullable. Records written before the upgrade keep an empty `log_type`. The Migrate Unsent Logs screen shows them as **Unknown type** and moves them like the other types.

The script also creates the recommended `(connector_id, log_type)` index. The alarm and the Migrate Unsent Logs screen read the table by connector and by type.

:::warning Run the script BEFORE you upgrade

The gateway writes `log_type` with every failover insert. If the column is missing, **every failover insert fails**. When the primary destination is down, the log records are lost. Run the script **before** you upgrade the gateway to 2027.01.0.

:::

## When to run it

Run this **once**, against each failover database of a log connector, before you upgrade to 2027.01.0. It does not need to be run inside a maintenance window. Because the column is nullable, older gateway workers that still write pre-upgrade rows are unaffected. Test in a non-production environment first if you use a change-control process for DDL.

:::warning Do not run this script twice

Adding a column that already exists raises an error. If you create the table from the `CREATE TABLE` statements on the [Apinizer Log Table Creation Commands](/en/operations/administrator-guides/apinizer-log-table-creation-commands) page of 2027.01.0, the table already has this column and you do not run this script.

:::

## Oracle

```sql
ALTER TABLE log_UnsentMessage ADD (log_type VARCHAR2(50));
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## PostgreSQL

```sql
ALTER TABLE log_UnsentMessage ADD COLUMN log_type VARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## MySQL

```sql
ALTER TABLE log_UnsentMessage ADD COLUMN log_type VARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## SQL Server

```sql
ALTER TABLE log_UnsentMessage ADD log_type NVARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## Verification

After running the script, confirm the column exists. For example, on PostgreSQL, MySQL, or SQL Server:

```sql
SELECT COUNT(*) FROM information_schema.columns WHERE LOWER(table_name) = 'log_unsentmessage' AND LOWER(column_name) = 'log_type';
```

On Oracle, check `USER_TAB_COLUMNS` for `LOG_UNSENTMESSAGE`. The result is 1.
