:::note

This report does not use Elasticsearch traffic data. It counts API Proxy records that exist today, by their creation date. An API Proxy that was deleted is not counted.

:::

## Where to Find the Report

- **Administration:** Open **Administration > API Governance > API Growth** (in the **Inventory Reports** section). The report covers all projects and has a **Project** filter.
- **Project menu:** Open the **API Growth** tab of the **Metrics** page. The report covers the active project.

The report is a chart. To see the individual API Proxies, open the API Proxies list. In the **Administration** menu, it is **API Governance > API Proxies**.

The **Endpoint Growth** report is related; see [API Endpoint Creation Report](/en/analytic/analytics-reports/api-endpoint-creation-report).

## Defaults and Search

The report runs one search when you open it. The default creation window is the last 30 days and the default interval is **Daily**.

After that, the chart changes only when you click **Search**. The bar next to **Search** shows how many filter changes are not applied yet. The eraser button resets the filters to the defaults and applies them.

Inside the **Metrics** page, the report has its own created-date fields and filters. The environment and date range at the top of the Metrics page do not apply to it.

## Filtering

| Option | Description |
|---------|----------|
| **Project** | (Administration only) Limits the count to the selected projects |
| **Interval** | **Daily**, **Weekly** or **Monthly**. It is not used while the chart is grouped by routing address |
| Created from / to | The creation date range |
| **API Proxy Type** | REST, SOAP, gRPC, WebSocket, AI, MCP, A2A. All types when empty |
| **API Proxy Creation Type** | WSDL, Swagger 2.x, Open API/Swagger 3.0.x, Reverse Proxy, No-Spec API, DB-2-API, Mock API, Script-2-API, Connector |
| **Environment** | Counts only the API Proxies deployed to the selected environments |
| **Protocol Transformation** | Filters REST proxies by protocol transformation |

## Grouping

Use the **Group by** switch above the chart to choose how the bars are formed.

<CardGroup cols={2}>
  <Card title="By period" icon="calendar">
    One bar per interval. The title is "API proxies created per period (existing records)".
  </Card>
  <Card title="By routing address" icon="route">
    One bar per address the API Proxies route to. The title is "API proxies by routing address (existing records)".
  </Card>
</CardGroup>

When you group by routing address, the report counts the API Proxies created in the selected date range under each address:

- For an HTTP address, the address is `host:port`.
- For an AI proxy, the address is the LLM provider.
- For an MCP or A2A proxy, the address is the connected server.
- An API Proxy with addresses on more than one host is counted under each host. The total can therefore be larger than the number of API Proxies.
- An API Proxy without a routing target is counted under "(no routing address)".

## Excel Export

The Excel button exports the table behind the chart as `apinizer-api-growth.zip`. The file uses the filters and the grouping on screen:

- Grouped by period, the file has the columns **Period** and **New API proxies**.
- Grouped by routing address, the file has the columns **Routing address** and **New API proxies**.

## Showing Routing Information in the List

The API Proxies list has two options that show where your API Proxies route requests. Both are off by default.

<CardGroup cols={2}>
  <Card title="Show route address" icon="route">
    Adds a **Route Address** column with the target addresses of each API Proxy.
  </Card>
  <Card title="Show route condition" icon="filter">
    Adds a **Route Condition** column with a summary of the condition of each target. The option is available once **Show route address** is on.
  </Card>
</CardGroup>

:::note

How targets are displayed depends on the API Proxy type. REST, SOAP, gRPC, and WebSocket show backend addresses; AI shows provider and model information; MCP and A2A show the connected server name and address.

:::
