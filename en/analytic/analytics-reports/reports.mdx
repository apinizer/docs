All analytics reports are reached through a single **Metrics** page with one tab per report. In the left menu, **Reports** is a separate group (it requires the Advanced Analytics license): open the page via **Administration > Reports > Metrics** or **Reports > Metrics** in the project menu. The group has two entries:

The tabs of the Metrics page and the reports they show are as follows. Hover over a tab to see the full report name.

| Inactive Endpoints | Endpoints with No Requests |

## API and AI Views

When your license includes both the API Gateway and the AI Gateway, the first control in the top row of the Metrics page is an **API | AI** switch. The page shows one view at a time and loads only the selected one.

- **API:** The tabs above (REST, SOAP, gRPC, and WebSocket traffic).
- **AI:** The AI Gateway analytics for AI, MCP, and A2A traffic, with the tabs **Performance**, **Cost & Consumers**, **Usage Reports**, **Security & Guardrails**, and **Provider Health**. **Provider Health** also shows the time to first token (TTFT) of each provider for the last 24 hours. See [AI Gateway Reports](/en/ai-gateway/reports#provider-health-tab).

The switch lists only the views your license covers. If only one view is licensed, the switch is hidden and that view opens. The same switch is on the Analytic > Dashboard and Analytic > Traffic pages; see [Dashboard](/en/analytic/dashboard) and [Traffic](/en/analytic/api-traffic).

## Shared Filter and Refresh

A filter row shared **across every tab** sits at the top of the page: Environment, Project (**Admin menu only**), and date range. This filter is chosen once, and stays in effect no matter which tab you switch to.

:::info

**The default date range is the last 1 hour.** Choosing a wide range can slow queries down, especially on installations with high traffic volume. Widen the range manually whenever you need a longer window.

:::

The **Excel Export** button also lives in this shared row and exports whichever report is currently on screen, using the filters of the view that is currently active: in chart view only the project and date filters apply, while in list view every list filter is applied.

## Search Rule on Report Screens

Report and dashboard screens that have a **Search** button follow one rule:

- The screen runs one search when you open it, with a short default range.
- After that, the results change only when you click **Search**. Changing a filter does not reload the data.
- Press Enter in a filter field to search too. While changes wait, the **Search** button shows the number of changes that are not applied yet.
- **Refresh** searches again with the filters you applied last.

| Screen | Default on open |
|--------|-----------------|
| Metrics and dashboard screens that read Elasticsearch | The last 1 hour |
| API Growth and Endpoint Growth | The last 30 days, with the **Daily** interval |
| Alert history | The range and result filters are a draft. The list changes when you click **Search** |
| Traffic | One search on open. The list refreshes by itself only if you turn on auto-refresh |
| Endpoints with No Requests, Clients with No Requests | No search on open. They run only after you click **Search** |

:::note

Endpoints with No Requests and Clients with No Requests read a long period. Choose the period first and then click **Search**.

:::

### Lists of Records

Lists of records, such as the API Proxies, Consumers or Limit Plans lists, follow the same rule. The fields of the filter bar are a draft. The list changes only when you click **Search** or press Enter. **Clear filters** and the eraser button reset the fields and show the full list.

Some controls stay instant because they choose what the screen shows, not which rows match. Examples are the environment, the period and the identity type (consumer or application) selectors. Quick filters inside a panel are instant too.

:::note

The growth tabs (API Growth / Endpoint Growth) have their own created-date fields. The shared date range at the top of the page does not apply to them.

:::

## Lazy Tab Loading

When the Metrics page opens, only the **currently active tab** is mounted and runs its query — the other tabs are not loaded yet. Switching to another tab unmounts the previous report and mounts the newly selected one, which then runs its own query. As a result, at most one query runs in the background at any given moment.

**Refresh** follows the same principle: it reloads only the report currently on screen and has no effect on the other, unmounted reports.
