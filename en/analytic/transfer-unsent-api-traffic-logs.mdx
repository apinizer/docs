---
title: "Migrate Unsent Logs"
description: "You can see the records that connectors could not send and wrote to their failover database. You can select the record types and send them to the connector again without data loss."
---

When a connector cannot write a log to its destination, it writes the record to its failover database if the connector has a failover connector. After you fix the connector, you send these records to the connector again from this screen.

:::note
Only a System Admin or a System Analyst can use this screen.
:::

## Connector List

The screen lists the log connectors of the environments and the SIEM destinations.

| Column | Description |
|--------|-------------|
| Source | The environment or the SIEM destination that owns the connector. |
| Connector | The connector that sends the logs. |
| Failover Connector | The failover connector that stores the records the connector could not send. A connector without a failover connector shows a gray **Failover connector is not defined** text. |
| Waiting Records | **Yes** with the waiting record types, or **No waiting records**. If the failover database cannot be read, the column shows **Failover database could not be read**. If only the types cannot be read, it shows **types could not be read**. |
| Last Migration | The result and the number of records of the last migration. The result is **Completed**, **Stopped**, or **Stopped with an error**. |

The column shows whether records wait for each type. It does not show a record count. The alarm uses the same measurement.

You can filter the list by source and by record type. Click **Refresh** to read the failover databases again.

## Moving Records

1. Click **Move…** in the row of the connector. A drawer opens on the right.
2. Select the waiting record types you want to send.
3. Click **Move (N types)**.

The drawer lists these record types:

- API Traffic
- Policy Capture
- Token
- Audit
- SIEM Audit
- SIEM Token
- Unknown type

The migration sends only the selected types. The connector deletes each sent record from the failover database. A record that the connector cannot send stays in the failover database. In this case the migration stops and the result is **Stopped with an error**. You can start it again later.

While the migration runs, the row shows the number of moved records. Click **Stop** to stop it. The migration stops before its next batch and the result is **Stopped**.

If the record types cannot be read, the drawer shows **All records**. The migration then moves all waiting records of the connector.

:::info
**Unknown type** covers two kinds of records. These are the records written before 2027.01 and the records dropped from a shared send queue (RabbitMQ, ActiveMQ). These records carry no type. They are moved like the other types.
:::

:::info
A record sent to a Syslog destination again has no STRUCTURED-DATA metadata. The message body is the same.
:::

:::warning
When **Apinizer configuration database (MongoDB)** is used as the failover connector, accumulated logs can be sent back to the connectors from this screen. If these records are overlooked, MongoDB can grow large enough to crash, and the entire Apinizer platform may go down. Therefore, using the Apinizer configuration database as a failover connector is **strongly not recommended**.
:::

:::info
**Alternative:** Unsent logs can be written to a relational database of your choice. For creating the target table, see the [Apinizer Log Table Creation Commands](/en/operations/administrator-guides/apinizer-log-table-creation-commands) page.
:::

:::info
If a **separate MongoDB** is used as failover instead of the Apinizer configuration database, accumulated logs can be sent back to Elasticsearch. For detailed information, see the [Writing Logs from MongoDB to Elasticsearch with Bash Script](/en/operations/troubleshooting/writing-mongodb-logs-to-elasticsearch) page.
:::

You can also receive an alarm when records wait in a failover database. See the **Unsent Traffic Logs Exist in Database** trigger type on the [Alarm](/en/monitor/alarm) page.
