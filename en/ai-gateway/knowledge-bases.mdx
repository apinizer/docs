## Overview

A **knowledge base** is your own collection of documents, indexed so a model can retrieve and use them at request time through [RAG](/en/ai-gateway/rag-injection). You manage knowledge bases from a dedicated screen — create, update, and delete them independently of any API proxy.

## Supported Document Types

- **Plain text** (`.txt`, `.md`) — paste directly or upload the file
- **PDF** (`.pdf`) — content is automatically extracted to text; if a single document fails to extract, the rest of the upload still succeeds
- **Excel** (`.xlsx`, `.xls`) — every sheet and row is processed individually, and each cell's value is turned into text together with the sheet and row it came from, so a single chunk stays meaningful on its own. A formula cell contributes the **result value** the workbook last computed and saved, never the formula text itself.

:::note Size ceilings on Excel documents
Three ceilings keep an oversized workbook from exhausting memory: at most **50 sheets**, at most **20,000 rows per sheet**, and at most **5,000,000 characters** across the whole workbook. Reaching a ceiling doesn't stop indexing — everything read up to that point is indexed, with a visible note appended to the end of the text marking where it was cut; the document is **not** treated as an error, it's indexed with partial content. A password-protected Excel file cannot be indexed and is treated as an error.
:::

## How a Knowledge Base Is Built

<Steps>
  <Step title="Create a Knowledge Base">
    Give it a name and description so you can reference it when configuring RAG.
  </Step>

  <Step title="Upload Documents">
    Upload text, PDF, or Excel files. PDF and Excel content is automatically extracted to text; if a single document fails to extract, the rest of the upload still succeeds.
  </Step>

  <Step title="Automatic Chunking">
    Each document is automatically split into smaller passages sized for retrieval, rather than being searched as one large block of text.
  </Step>

  <Step title="Automatic Indexing">
    Chunks are embedded and stored in your [vector database](/en/ai-gateway/vector-database), ready to be searched at request time.
  </Step>

  <Step title="Manage">
    View, update, or delete documents and chunks from the knowledge base screen at any time.
  </Step>
</Steps>

## A Lighter Alternative to Fine-Tuning

<Card title="Update Knowledge Without Retraining" icon="sparkles">
  Fine-tuning bakes knowledge into a model and requires retraining every time your data changes. A knowledge base lets you add, update, or remove information at any time — the next request simply retrieves the latest content, with no retraining or redeployment of the model itself.
</Card>

## Using a Knowledge Base

Once created, a knowledge base is attached to a RAG policy so incoming requests can retrieve from it — see [Retrieval-Augmented Generation (RAG)](/en/ai-gateway/rag-injection). A single request can also be scoped to one specific knowledge base rather than every knowledge base in a project.

:::danger Deletion is permanent and unconditional
Deleting a knowledge base is **not blocked by any dependency check**. The delete confirmation shows, best-effort, how many RAG policies currently reference the knowledge base — but that count is informational only, not a gate: whether it loads or not (it silently shows nothing if the lookup fails), confirming **Delete** removes the knowledge base immediately.

Deletion also permanently purges the knowledge base's records from the [vector database](/en/ai-gateway/vector-database). If no other knowledge base shares its collection, the entire collection is removed; if one does, only this knowledge base's own records are removed and the shared collection is preserved.

If a deployed RAG policy still references the deleted knowledge base or its collection, that policy starts failing — and blocking — every subsequent request; see the fail-closed behavior on the [Retrieval-Augmented Generation (RAG)](/en/ai-gateway/rag-injection) page. Update or remove any RAG policy that depends on a knowledge base before deleting it.
:::

Knowledge bases and their documents can also be managed through the APIops REST API; see [API Reference: Knowledge Bases](/api-reference/knowledge-bases).
