## The Prompt Template Catalog

A **Prompt Template** is a reusable, named catalog entry made of one or more messages (`system`, `user`, `assistant`, and so on), each of which may contain `{{paramName}}` placeholders. It carries:

- **Name** — the reference key other screens use to find this template; must be unique within what you can see (built-in, shared, and your own project's templates)
- **Description**
- **Messages** — a role plus content for each message, with `{{paramName}}` placeholders anywhere in the content
- **Parameters** — the names the messages reference, each optionally marked required and given a default value
- **Enabled**

Each template belongs to one of three scopes:

| Scope | Who sees it | Who can edit it |
|-------|-------------|------------------|
| **Built-in** | Everyone | Read-only |
| **Shared** | Every project in the installation | A system administrator |
| **Project-owned** | Just that project | Members of that project |

A caller always sees the union of built-in, shared, and their own project's templates.

:::warning Renaming Is a Breaking Change
A [Prompt Template policy](#the-prompt-template-policy) copies a template's messages and parameters into itself the moment it is picked — it does not keep a live link back to the catalog. Renaming a template afterward does not update any policy that already copied it, and a client that referenced the old name directly will find it gone. Renaming shows a warning for this reason; editing a template's content has the same limitation — the change only reaches a policy that re-picks the template.
:::

## The Prompt Template Policy

A **Prompt Template policy** picks one or more templates from the catalog into its own list of **bindings**, then expands a matching binding into the request's message list at gateway time. Each binding has:

- **Alias** — the value a client's request sends to select it (defaults to the catalog template's name at pick time, but can be changed per binding without affecting the catalog)
- **Messages** and **parameters** — a read-only, snapshot copy of the catalog template's content at the moment it was picked

  </Step>

  <Step title="Set the Alias">
    Give each binding the alias a client will send to select it.
  </Step>

  <Step title="Configure Behavior">

  </Step>

  <Step title="Deploy">

  </Step>

### How a Request Uses It

A client sends the alias — and, if the template has parameters, their values — in two request body fields (**`template`** and **`template_params`** by default; both field names are configurable per policy):

```json
{
  "template": "greeting",
  "template_params": {
    "name": "Ada"
  }
}
```

The gateway looks up `greeting` among the policy's bindings, substitutes `{{name}}` with `"Ada"` in every message, and forwards the expanded `messages[]` array to the LLM provider — the `template`/`template_params` fields themselves are removed from the body first, since most LLM providers reject an unrecognized top-level field.

A request that doesn't include the template field at all passes through unaffected — this policy only acts when a client is actually using it.

### Unknown Alias and Missing Parameters

| Setting | Options | Behavior |
|---------|---------|----------|
| **Unknown Template Behavior** | Pass Through (default) / Block | What happens when the alias matches no binding on this policy. Pass Through forwards the body completely unchanged, including the template fields; Block rejects the request (HTTP 400). |
| **Missing Parameter Behavior** | Block (default) / Substitute Empty / Use Default | What happens when a `{{param}}` referenced by the matched template has no client-supplied value. Block rejects the request (HTTP 400); Substitute Empty replaces it with an empty string; Use Default falls back to the parameter's declared default value (or an empty string if none was declared). |

### Merge Mode

Controls how the expanded template messages combine with any `messages[]` the client itself sent:

| Mode | Result |
|------|--------|
| **Replace** (default) | The template's messages replace the client's own entirely |
| **Prepend** | Template messages first, then the client's own |
| **Append** | Client's own messages first, then the template |

### Expanded-Content Budget

The **Expanded Content Budget** bounds the total character count across every expanded message's substituted content. Exceeding it **rejects the request** (HTTP 400) rather than injecting a truncated prompt.

:::warning Parameter Substitution Is Single-Pass
A parameter value is substituted literally, even if it happens to contain `{{...}}` itself — it is never expanded a second time. This is a deliberate protection: a client-supplied parameter value can never smuggle in another template reference or otherwise change what gets sent beyond the one placeholder it was meant to fill.
:::

## Execution Order

Prompt Template expansion runs at the very front of the AI request lane — even before [Prompt Decorator](/en/ai-gateway/prompt-decorator). Every downstream feature (guardrails, the semantic cache, RAG injection, token-quota counting) sees the fully expanded message list, never a bare `template`/`template_params` pair.

## Centralized Management

:::
