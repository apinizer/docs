---
title: "Anomaly Detector Usage"
description: "You can detect anomalies in log records with the anomaly detector. You can examine time-based data with queries and filters to detect anomalies that reach threshold values and define actions in case of anomalies."
---

## General definition

Open **Monitoring → Anomaly Detector** and create a detector with **+ Create Detector**. Under **Definition**, enter a **Name** and optional **Description**.

Use **Query & Scope** and **Environment** to attach a query, filter, and target environment (steps below). Under **Evaluation schedule**, set how often evaluation runs (example: every **5 minutes**).

<img
  src="/images/tutorials/api-izleme/anomali-detector-general.png"
  alt="Anomaly detector general form"
  width="1000"
/>

Queries and filters run against the logging infrastructure of the selected **environment**.

## Creating a query

A query defines which log records match by combining fields (HTTP method, error type, etc.) with **AND** / **OR** / **NOT**.

In the **Query** field, click **Select Query** to pick an existing query or create a new one.

<img
  src="/images/tutorials/api-izleme/anomali-select-query.png"
  alt="Select Query"
  width="1000"
/>

On **New Query**, fill **Name** and **Description**; add criteria with **+ New Criteria** (example: **Error Type** — **is** — **Any of errors is enough**). Click **Save** to attach the query to the detector.

<img
  src="/images/tutorials/api-izleme/anomali-new-query.png"
  alt="New Query"
  width="1000"
/>

:::tip

To open the **Queries** screen where all queries are managed, [click here.](/en/analytic/query-editor/queries)

:::

## Creating a filter

Filters narrow the data together with the query: API proxies, date range, and result types (Success / Blocked / Error).

Under **Scope**, click **Select Filter** to choose or define a filter. Select the target **Environment** from the dropdown.

<img
  src="/images/tutorials/api-izleme/anomali-select-filter-scope.png"
  alt="Select Filter and environment"
  width="1000"
/>

On **New Filter**, enter **Name** and **Description**; under **Proxies**, set scope (example: **All Proxies**). Select **Result Type** values as needed. Click **Save**.

<img
  src="/images/tutorials/api-izleme/anomali-new-filter.png"
  alt="New Filter"
  width="1000"
/>

:::tip

To open the **Filters** screen where all filters are managed, [click here.](/en/analytic/query-editor/filters)

:::

## Conditions

After the query and filter are defined, configure threshold logic under **Conditions**. Multiple conditions are combined with **and**.

Example: when **count of documents** **is increased by** **more than** **50** **%** **according to** **average** **previous 1** **results**.

<img
  src="/images/tutorials/api-izleme/anomali-conditions.png"
  alt="Conditions"
  width="1000"
/>

## Actions

Define actions to run when an anomaly is detected. Use **+** under **Actions**; this example uses **Email**.

<img
  src="/images/tutorials/api-izleme/anomali-actions-modal.png"
  alt="Actions picker"
  width="1000"
/>

In **E-Mail Sending Configuration**, choose an SMTP **Server**, set recipients and **Subject** / **Message** (template variables such as `{{anomaly.detector.name}}` are supported). Give the action a short **Name** and click **Add**.

<img
  src="/images/tutorials/api-izleme/anomali-email-action.png"
  alt="Email action"
  width="1000"
/>

:::tip

For action types, usage, and task variables, [click here.](/en/concepts/core-concepts/connector)

:::

## Viewing results

Under **Monitoring → Anomaly Detector**, open the **All Detections** tab, open the row’s menu (**⋯**), and choose **Results**.

<img
  src="/images/tutorials/api-izleme/anomali-results-menu.png"
  alt="Results menu"
  width="1000"
/>

The results view shows summary KPIs, the **Metric vs. expected range** chart, and tabs such as **Execution History**, **Anomalies**, and **Configuration**.

<img
  src="/images/tutorials/api-izleme/anomali-execution-dashboard.png"
  alt="Anomaly detector results"
  width="1000"
/>

On the **Execution History** tab, each run lists execution time, result type (e.g. Stable), measured value, and duration.

<img
  src="/images/tutorials/api-izleme/anomali-execution-history.png"
  alt="Execution History tab"
  width="1000"
/>

For deeper troubleshooting, use your environment’s log or traffic views as needed.
