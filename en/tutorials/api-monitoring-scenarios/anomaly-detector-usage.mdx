## Defining the Filter

The Filter defines the calls that the detector watches. You combine specific fields (HTTP Method, Error Type, etc.) with criteria of **and** / **or** / **not** types to create the expected conditions.

To define the Filter, click **Select Filter** to choose a saved Filter, or **New Filter** to create one. Click **Save** in the dialog to add the new Filter to the job being defined.

:::tip

For detailed information about Filters, [click here.](/en/analytic/query-editor/filters)

:::

## Defining the Base Filter

The base filter defines all calls that count. Its time range is the window that the detector measures on every run. The time range is required and must be rolling, for example Last 1 hour.

To define the base filter, click **Select Filter** or **New Filter** in the **Base filter** section. Click **Save** in the dialog to add the base filter to the job being defined.

## Conditions

In the following condition, **'count of documents'** will look at the request count. It will check if there is an increase of more than **"50%"** compared to the average.

In this case, the **"'1 Result'"** expression indicates that if the anomaly occurs only once, it will be considered as an anomaly.

## Actions

When anomaly detection is performed, we can create an alert system. In this example, we will make it send an email when an anomaly occurs.

<img
  src="/images/tutorials/api-izleme/actions-mail-ayarlari.png"
  alt="Actions Mail Settings"
  width="1000"
/>

In the **'Server'** field, you can add new mail connection information or select an existing one. The **address**, **subject**, and **message** to which the email will be sent are entered and saved.

<img
