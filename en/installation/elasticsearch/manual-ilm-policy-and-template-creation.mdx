title: "Manual ILM Policy and Template Creation"
description: "Provides the necessary definitions for manually creating log entities required by Apinizer when log management is managed manually. Step-by-step explains ILM policy and Template creation operations in the Elasticsearch cluster."
---

:::warning

**If log management will be done through Apinizer, these operations do not need to be performed, these operations are done automatically by Apinizer.**

:::

## Variables

Dynamic values and their descriptions in the requests are shown in the table below.

| Variable | Description |
|----------|------------|
| `<ELASTICSEARCH_IP_ADDRESS>` | Host information of the Elasticsearch cluster. |
| `<ELASTICSEARCH_PORT>` | Port information of the Elasticsearch cluster. |
| `<INDEX_KEY>` | Unique identifier for the index. |
| `<INDEX_PATTERN_NAME>` | Index pattern name. It is the index name followed by `*` (e.g.: apinizer-log-apiproxy-default*). |
| `<ILM_POLICY_NAME>` | ILM policy name (e.g.: apinizer-log-ilm-policy-default). |
| `<NUMBER_OF_SHARDS>` | Number of shards for the index (Apinizer default: 1). |
| `<NUMBER_OF_REPLICAS>` | Number of replicas for the index (Apinizer default: 0). |
| `<REFRESH_INTERVAL>` | Index refresh interval (Apinizer default: 5s). |
| `<LOAD_FIXED_BITSET_FILTERS_EAGERLY>` | The `index.load_fixed_bitset_filters_eagerly` setting (Apinizer default: true). |

## Creating ILM Policies

### Creating ILM Policy Request Named apinizer-log-ilm-policy-default

```bash
curl -XPUT "http://<ELASTICSEARCH_IP_ADDRESS>:<ELASTICSEARCH_PORT>/_ilm/policy/apinizer-log-ilm-policy-<INDEX_KEY>" \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'EOF'
{
  "policy": {
    "phases": {
      "hot": {
        "min_age": "0ms",
        "actions": {
          "rollover": {
            "max_age": "30d",
            "max_size": "30gb",
            "max_docs": 15000000
          },
          "set_priority": {
            "priority": null
          }
        }
      },
      "warm": {
        "actions": {
          "readonly": {},
          "allocate": {
            "number_of_replicas": 0,
            "include": {},
            "exclude": {}
          },
          "shrink": {
            "number_of_shards": 1
          },
          "forcemerge": {
            "max_num_segments": 1
          },
          "set_priority": {
            "priority": null
          }
        }
      },
      "cold": {
        "min_age": "90d",
        "actions": {
          "set_priority": {
            "priority": null
          }
        }
      }
    }
  }
}
EOF
```

| `aircs` | Route classifier outcome: MATCHED, NONE, UNKNOWN_LABEL, TIMEOUT, ERROR, TRUNCATED, BACKOFF, NO_PROVIDER, or NO_INPUT | String | keyword |
| `aircms` | Route classifier call latency (ms) | Long | long |
| `aircti` | Route classifier prompt tokens | Long | long |
| `aircto` | Route classifier completion tokens | Long | long |
| `airccm` | Route classifier cost in micro USD (not included in `aicm`) | Long | long |
| `aivs` | Why the request continued without the vector layer (RAG, semantic cache, or Topic Guard) | String | keyword |
| `cr` | Pipeline position where the Log policy captured the record (FROM_CLIENT, TO_BACKEND, FROM_BACKEND, TO_CLIENT); written only in Log policy records | Enum | keyword |
| `cl` | Assignment level of the Log policy (API_PROXY_GROUP, API_PROXY, API_PROXY_METHOD); written only in Log policy records | Enum | keyword |

:::info

You can review the data example created in this data structure on the [API Traffic Log Record Data Structure](/en/analytic/api-traffic-log-record-data-structure) page.

:::

## Index Creation and Querying

When creating indices or querying with data stream, requests are sent according to the value in the **index_patterns** metadata within the template.

### Index Creation

```bash
curl -XPOST "http://<ELASTICSEARCH_IP_ADDRESS>:<ELASTICSEARCH_PORT>/apinizer-log-apiproxy-<INDEX_KEY>/_doc" -H 'Content-Type: application/json' -d'{"@timestamp": "2023-05-31T11:40:36.376Z"}'
```

### Running Query

```bash
curl -XGET "http://<ELASTICSEARCH_IP_ADDRESS>:<ELASTICSEARCH_PORT>/apinizer-log-apiproxy-<INDEX_KEY>/_search" \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'EOF'
{
  "from": 0,
  "size": 10,
  "query": {
    "bool": {
      "filter": [
        {
          "range": {
            "@timestamp": {
              "from": "now-10m/m",
              "to": "now/m",
              "include_lower": true,
              "include_upper": true
            }
          }
        }
      ],
      "adjust_pure_negative": true,
      "boost": 1
    }
  }, 
  "sort": [
    {
      "@timestamp": {
        "order": "desc"
      }
    }
  ]
}
EOF
```

:::info

The templates on this page are for the API traffic log. The index templates for SIEM destinations are different. See [Elasticsearch Index Templates for SIEM Destinations](/en/operations/administrator-guides/siem-elasticsearch-index-templates).

:::
