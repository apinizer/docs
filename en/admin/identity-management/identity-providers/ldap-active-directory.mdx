description: "You can configure identity provider for user verification via LDAP/Active Directory. You can use simple or advanced authentication methods and configure user and group class definitions."

:::info

Accessible and manageable by roles that have the "Manage Authentication Services" permission such as "Project Owner".

:::

## List

Directories that Apinizer uses to authenticate API calls and to synchronize consumers are listed on this screen. Use the search box to filter by name, and the two filters next to it to narrow the list further.

| Filter | Description |
| --- | --- |
| Status | All statuses, Enabled, or Disabled. Reflects the provider's Enable Synchronization setting. Hover over the column header for the same explanation. |
| Directory Type | All directory types, Active Directory, OpenLDAP, or Other. Comes from the Directory Type of the provider's connection pool. |

The table shows the following columns.

| Column | Description |
| --- | --- |
| Name | The provider's name and description. |
| Directory Type | A badge with the Directory Type of the connection pool. Empty when you cannot view the connection, or the pool no longer exists. |
| Server | The server address of the connection. |
| Base DN | The Base DN of the connection. |
| Status | An Enabled or Disabled badge for the provider's synchronization setting. |
| Project | Only in admin (global) scope. The name of the project the provider belongs to. |

Each row has a single **⋮** menu, in this order: **View**, **Edit** (if you can manage identity providers), **Duplicate** (if you can manage global settings), **Delete** (if you can manage identity providers), **Move to Global** (if you can manage identity providers, for a provider that is not already global), and **Export** (if you can export/import identity data).

Click **+ New** at the top of the screen to create a provider, or **Import** to bring one in from an [export package](/en/admin/secrets-management/export-import).

## View

The view screen opens from a row's name or **View** button, in the standard page frame: a plain Back bar above a single main card. The card's title row shows the provider's name, an Enabled/Disabled synchronization badge, a Directory Type badge, and its description. If you can manage identity providers, the same title row also has, in order, **Edit**, **Delete**, **Connection Test**, and **Directory Preview** buttons.

:::note

There is no **Synchronize…** button on this screen. To start a synchronization run for this provider, open the [Synchronization screen](/en/admin/identity-management/identity-providers/credential-sync#starting-a-synchronization).

:::

Below the header, a **Configuration** tab holds the cards described below. An **Audit and Rollback** tab holds the provider's change history and lets you roll back to an earlier version — see [Asset Lifecycle](/en/concepts/core-concepts/asset-lifecycle).

### Configuration cards

**General** — the provider's Name, Description, and Directory Type (as a badge).

**Connection and bind** — read from the connection pool: Server Address, Security (LDAPS or StartTLS), Base DN (from the connection), and Connection Timeout; then the LDAP Authentication Type (Simple or Advanced — see [Edit](#edit) below), the User Configuration Expression when Simple authentication is used, the Bind DN, and the Bind password. The password is always shown as a masked value, or **Not set** when the connection pool has none — the value itself is never shown on this screen. If you cannot view the provider's connection, the card shows a note instead of these values.

**Users** and **Groups** (side by side) — for Simple authentication, both cards show a note that they are not used. For Advanced authentication, each shows its object class definition, read-only: the object class name, the custom filter and base DN attributes, the search scope, an **Attribute mapping** box, and the attributes to fetch. Users additionally shows the account state attribute and format; Groups additionally shows how membership is determined and the member strategy — see [Users](#users) and [Groups](#groups) under Edit below for what each field means.

**Membership** — how a user's group membership is determined (with an explanation next to it), the membership and member attributes, and the member strategy. When membership is determined automatically, the member strategy shows **Detected automatically** instead of a fixed value, because the format of each member value is then read individually.

**Synchronization** — the provider's sync profile, read-only:

| Field | Description |
| --- | --- |
| Enable Synchronization | See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#sync-profile). |
| Schedule | The cron expression, or **Manual only** when it is blank. |
| Deactivation Mode | See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#sync-profile). |
| Scope: users / Scope: groups | How many include/exclude patterns are set for users and for groups/organizations, and which field and pattern type they match — see [Edit](#synchronization) below. |
| Scope Exit Policy | What happens to a record that still exists in the source but no longer matches the scope: Leave as is, Disable, or Tombstone. |
| Deactivation thresholds | The percentage and record-count guardrails: reconciliation pauses for approval instead of running when the records it would deactivate exceed either one. |
| Without stable identity | Whether reconciliation is prevented from deactivating or deleting records when the source returns no stable external identity (so a renamed user is not mistaken for a removed one). |

### Directory Preview

Opens from the **Directory Preview** button. It reads the directory with the provider's **saved** configuration and writes nothing. It has tabs for Users, Groups, Membership, and Issues, plus a **Full scan (dry run)** option that pages through the whole directory and reports what a real synchronization run would create, update, or deactivate. The Issues tab lists configuration problems such as a group object class whose member attribute does not match its object class (code LDAP-I14); some issues carry an **Apply** suggestion, which you can only write back to the form from the [Edit](#edit) screen.

### Synchronization history

At the bottom of the screen, a **Synchronization History** card lists the last runs of this provider — the same table as the project-wide Synchronization screen, without the Source column, described in [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#run-history). Click **Refresh** to reload it, or click an **N issues** badge to open the issues drawer for that run. While one of the listed runs is queued or running, the card reloads itself automatically every few seconds, so you do not need to click Refresh to watch it progress. Click **Open Synchronization screen** to see the provider's full run history and every other source in the project.

### Connection and bind

Select the **LDAP Connection Pool Definition**, or click **Create New Connection Pool** to define one without leaving this screen. Once selected, the pool's Server, Base DN, Bind DN, and Bind password (masked, or **Not set**) appear read-only under it — these values, including the bind account's password, are edited on the connection pool itself, not here.

Two buttons next to the section title test the connection with the values currently on the form, so they also work before the provider is saved:

| Button | Description |
| --- | --- |
| Test connection | Runs the full step-by-step connection test (the same matrix as the List screen's Connection Test). |
| Test bind | Signs in with only the bind DN and password of the connection pool. |

Choose the **LDAP Authentication Type**, Simple or Advanced:

- **Simple** — enter the **User Configuration Expression**. **Test Configuration** signs in with a test username and password through this expression; if the expression or the connection pool uses a variable, the test opens an environment picker first.
- **Advanced** — click **Apply Preset** to fill the Users and Groups sections below with the defaults of a directory type (Active Directory, OpenLDAP, 389 Directory Server / FreeIPA, or Active Directory with groups kept as organizational units). Applying a preset replaces values already entered in those fields, but nothing is saved until you save the provider. **Test Configuration** here reads a small sample of users and groups with the values on the form.

### Users

A summary of the current User Object Class Definition is shown read-only, with a **Configure** button that opens it in a drawer (Advanced authentication only — the summary shows a note instead, for Simple).

| Field | Description |
| --- | --- |
| User Object Class Names | The class name(s) used to filter users. Separate more than one with a comma. Example: `person,inetOrgPerson` |
| User Base DN Attribute | Used instead of the connection's Base DN when searching and loading users, if set. Example: `cn=users,dc=ad,dc=example,dc=com` |
| Custom Filter Attribute | An additional filter used together with the connection's filter when fetching users. Example: `(&(objectCategory=Person)(sAMAccountName=*))` |
| Search Scope | The level at which the search runs under the base DN. |
| Attribute mapping — Login Name Attribute | The attribute holding the user's login name. Example: `uid` |
| Attribute mapping — First Name Attribute | The attribute holding the user's first name. Example: `givenName` |
| Attribute mapping — Last Name Attribute | The attribute holding the user's last name. Example: `sn` |
| Attribute mapping — Full Name Attribute | The attribute holding the user's full name. Example: `cn` |
| Attribute mapping — E-mail Attribute | The attribute holding the user's e-mail address. Example: `mail` |
| Attribute mapping — Membership Attribute | The attribute holding the user's group memberships. Example: `isMemberOf` |
| Attributes To Fetch | Extra attributes read for the user in addition to authentication; see [below](#attributes-to-fetch). |
| Account State Attribute | The attribute that tells whether the account is switched off in the directory. Example: `userAccountControl` on Active Directory, `pwdAccountLockedTime` on OpenLDAP, `nsAccountLock` on 389 Directory Server / FreeIPA. Leave it empty to keep the current behavior: the account state is not read, and synchronization never deactivates a consumer because of it. |
| Account State Format | How to read the value of that attribute. Picking the wrong format does not raise an error — it silently reports every locked account as active, so make sure it matches your directory. |

#### Attributes To Fetch

When authentication is performed with LDAP, these attributes are read for the user in addition to authentication, if present:

- If the provider is used to generate a JWT, the attributes and their values (excluding null ones) are added to the JWT as claims.
- If the provider is used with plaintext, basic, or digest authorization, the attributes and their values are added to the message context as custom variables, with the key prefixed by `#clientLDAPAttribute#.`. For example, an `mail` attribute becomes the key `#clientLDAPAttribute#mail`.

A binary attribute is returned as text: Active Directory `objectGUID` in GUID form, `objectSid` in `S-1-5-21-...` form, and any other binary attribute as Base64.

A summary of the current Group Object Class Definition is shown read-only, with a **Configure** button that opens it in a drawer (Advanced authentication only).

With Advanced authentication, **Save and Deploy** stays disabled until a Group Object Class Definition is configured.

| Field | Description |
| --- | --- |
| Group Object Class Name | The class name used to filter groups. Example: `groupOfUniqueNames` |
| Group Base DN Attribute | Used instead of the connection's Base DN when searching and loading groups, if set. |
| Custom Filter Attribute | An additional filter used together with the connection's filter when fetching groups. |
| Search Scope | The level at which the search runs under the base DN. |
| Attribute mapping — Group Name Attribute | The attribute holding the group's name. |
| Attribute mapping — Member Attribute | The attribute holding the group's members. The value must match the group object class: `member` for `groupOfNames` and Active Directory `group`, `uniqueMember` for `groupOfUniqueNames`, `memberUid` for `posixGroup`. With a mismatched value, every group is read as empty and no user is linked to an organization — the **Directory Preview** screen's Issues tab reports this as **LDAP-I14**, and its **Apply** button writes the correct value into this field. Active Directory returns the members of a group with more than 1500 members in parts (`member;range=`); Apinizer reads all parts. |
| How is membership determined? | Selects how a user's group membership is resolved: the current behavior (default, unchanged), automatic detection (recommended), from the user's own membership attribute, from the group's member list, from the organizational unit the user is placed under, or both the OU and every membership list. If you are not sure, leave it as is or choose automatic detection — changing it only affects how memberships are read, not the directory itself. |
| Member Strategy | The strategy used to find a group's members, USER DN or USER LOGIN. Not shown when membership is determined automatically or from the organizational unit tree, since the format of each member value is then detected on its own. |
| Attributes To Fetch | Extra attributes read from each group. Adding the attribute that never changes when a group is renamed or moved (`objectGUID` on Active Directory, `entryUUID` on OpenLDAP and 389 Directory Server / FreeIPA) keeps the organization, its limits, and its members attached to the same record after the move. |

### Membership check

This card only has a one-line description and an **Explain** button; testing a user happens in the dialog that button opens.

- For Advanced authentication, the description is the Explain dialog's own subtitle: it shows step by step how a single user is found in the directory and how the membership is resolved.
- For Simple authentication, which reads no groups, the description points you to **Test Configuration** in Connection and bind instead.

In the Explain dialog, enter a **User name** and, optionally, a masked **Password (optional)**. Without a password, the dialog only searches for the user; with one, it also attempts a sign-in — the password is never stored or displayed. Opened for Advanced authentication, the dialog also shows a **User details** block with the user's Login Name, Full Name, First Name, Last Name, and E-Mail, and a name badge next to each group's distinguished name.

### Synchronization

A read-only summary (Enable Synchronization, Schedule, Deactivation Mode, Scope: users, Scope: groups, Scope Exit Policy, thresholds, and the without-stable-identity guard) is shown, with a **Configure** button that opens it in a drawer:

| Field | Description |
| --- | --- |
| Enable Synchronization | See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#sync-profile). |
| Base DN (from the connection) | Read-only. See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#ldap-active-directory). |
| Cron Expression | See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#sync-profile). Leave it blank to allow only manual synchronization. |
| Deactivation Mode | See [Credential Sync](/en/admin/identity-management/identity-providers/credential-sync#sync-profile). |

Below these, a **Synchronization Scope** section narrows which users and which groups/organizations this provider synchronizes: for each, choose the matched field (such as Username or Path), the pattern type (Glob or Regular Expression), and the patterns to include or exclude. A record outside the scope is not treated as removed from the source — what happens to it is decided by the **Reconciliation Safety Net** below it:

| Field | Description |
| --- | --- |
| Scope Exit Policy | Applied to a record that still exists in the source but no longer matches the scope: Leave as is, Disable, or Tombstone. |
| Deactivation Threshold (%) / Deactivation Threshold (records) | When the records that reconciliation would deactivate exceed either the percentage or the count, reconciliation pauses for approval instead of running. The default is 20%; 0 turns a threshold off. |
| Do not deactivate or delete when the source returns no stable external identity | Without a stable external identity, the only key is the username, so a user renamed in the source looks removed. While this is off, the current behavior is kept and the run only records a warning. |

This scope and safety-net editor is shared by all four provider types (LDAP, Database, API, OIDC).

This drawer, and the Users and Groups drawers above, are edited on a copy: **Cancel** discards your changes, **Apply** writes them back into the form (still unsaved). A section's heading gets a **Changed** badge as soon as you edit it directly, or after you click **Apply** in its drawer.

:::note

This screen has no control to start a synchronization run. Open the [Synchronization screen](/en/admin/identity-management/identity-providers/credential-sync#starting-a-synchronization) to start one.

:::

### Save and Deploy

Click **Save and Deploy** in the breadcrumb bar to open a confirmation that lists which sections you changed, or says no section changed; either way it reminds you that the provider is deployed to every environment where it is used. Click **Back** to leave the screen without saving.

:::info

There is no separate save-only action, and no separate Cancel button. Saving a provider always deploys it — even when no section changed, in which case the provider is only deployed again.

:::
