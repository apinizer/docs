## Where to Find the Report

The project menu has the ACL Report under **Identity**. It covers the active project.

As an administrator, open it from **Administration > API Governance > ACL Report** (in the **Inventory Reports** section). It covers all projects and offers a **Project** filter.

## Search

The ACL Report runs one search when you open it. After that, the table changes only when you click **Search**. The bar next to **Search** shows how many filter changes are not applied yet.

## Blocked Endpoints

Use the **Endpoints** filter to choose which endpoints the report lists:

| Option | Result |
|--------|--------|
| **Allowed endpoints** | Lists the endpoints the consumer can call. This is the default. |
| **Blocked endpoints** | Lists the endpoints the consumer is blocked from. |
| **All endpoints of the granted API proxies** | Lists both. |
| **Endpoints of the API proxies without a grant** | For each consumer, lists the endpoints of the API proxies in the report scope that the consumer has no grant on. |

When the list can contain blocked endpoints or endpoints without a grant, the table adds an **Access** column. It shows **Allowed**, **Blocked** or **No grant** for each row.

The **Endpoints of the API proxies without a grant** option works on screen, in the Excel export and in the Report Generator. A **Requests** column shows 0 for these rows. The report is refused when it would list more endpoints than the **Report Generator Max Records** setting allows (System Settings > Reporting). Narrow the report by consumer, organization or API proxy.

## Request Counts

Select **(Usage) Requests** in **Select field(s)** to add a **Requests** column. It shows how many requests each consumer sent to each endpoint.

Two more filters appear when you select the field:

- **Environment of the requests**: The environment whose traffic log the report reads. The first environment is selected for you.
- **Period of the requests**: The date range the report counts.

The counts come from the traffic log. A reverse proxy row shows all requests of the consumer to the API proxy. A cell shows `-` when no count is available.

:::note

The report needs Elasticsearch to read request counts. Click **Search** after you change the environment or the period.

:::

## HTTP Method and Limit Plan

Two more fields are in **Select field(s)**. Both are selected by default:

- **HTTP Method**: The HTTP method of the endpoint, for example `GET`. It is empty for a reverse proxy row, because a reverse proxy has no method of its own.
- **Limit Plan**: The limit plans of the consumer.
  - The names of the plans assigned to the consumer itself. **Custom** means an inline limit instead of a plan.
  - For a limit family in which the consumer has no assignment of its own, the plan it inherits from its application or organization. It is shown as `<plan> (Inherited from <name>)`, where the name is the application or the organization the plan comes from. If several levels assign a plan to the same limit family, the nearest level wins.
  - If the consumer turns a limit family off unconditionally, no inherited plan is shown for that family.
  - The cell is empty when the consumer has no plan.

The report only reads the limit plans. Nothing is changed.

## Excel Export

The Excel export uses the same filters as the table. The **HTTP Method** and **Limit Plan** columns come after the data columns, before **Status**. It has a **Status** column that shows **Allowed**, **Blocked** or **No grant** for each row. When you select **(Usage) Requests**, it also has a **Requests** column. A row without a count shows 0 in the file.

The ACL report of the Report Generator has the same two columns in its preview, CSV file and mail table.
