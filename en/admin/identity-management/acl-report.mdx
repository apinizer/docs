## Where to Find the Report

The project menu has the ACL Report under **Identity**. It covers the active project.

As an administrator, open it from **Administration > API Governance > ACL Report** (in the **Inventory Reports** section). It covers all projects and offers a **Project** filter.

## Search

The ACL Report runs one search when you open it. After that, the table changes only when you click **Search**. The bar next to **Search** shows how many filter changes are not applied yet.

## Blocked Endpoints

Use the **Endpoints** filter to choose which endpoints the report lists:

| Option | Result |
|--------|--------|
| **Allowed endpoints** | Lists the endpoints the consumer can call. This is the default. |
| **Blocked endpoints** | Lists the endpoints the consumer is blocked from. |
| **All endpoints of the granted API proxies** | Lists both. |

When the list can contain blocked endpoints, the table adds an **Access** column. It shows **Allowed** or **Blocked** for each row.

## Request Counts

Select **(Usage) Requests** in **Select field(s)** to add a **Requests** column. It shows how many requests each consumer sent to each endpoint.

Two more filters appear when you select the field:

- **Environment of the requests**: The environment whose traffic log the report reads. The first environment is selected for you.
- **Period of the requests**: The date range the report counts.

The counts come from the traffic log. A reverse proxy row shows all requests of the consumer to the API proxy. A cell shows `-` when no count is available.

:::note

The report needs Elasticsearch to read request counts. Click **Search** after you change the environment or the period.

:::

## Excel Export

The Excel export uses the same filters as the table. It has a **Status** column that shows **Allowed** or **Blocked** for each row. When you select **(Usage) Requests**, it also has a **Requests** column. A row without a count shows 0 in the file.
