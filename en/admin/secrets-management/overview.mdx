:::info

Secrets Management enables management of certificates, keystores, private keys, and JWKS configurations used for security and encryption in the Apinizer platform. This module provides all the tools needed to create, manage security components used in policies and connections, and perform export/import operations.

:::

:::warning

This screen appears in the menu as **Secret** in two places:

- **Project menu:** Visible while a project is active, to the project administrator or to users whose role has **View** or **Manage** permission in the **Secrets & Certificates** category. For permission categories, see the [Authorization Matrix](/en/admin/user-access-management/authorization-matrix) page.
- **Administration menu:** Visible only to the system administrator.

:::

## Single-Page View

The Secrets Management lists are gathered on a **single page with tabs**: **Certificates**, **Truststore**, **Keys**, **Key Stores**, **JSON Web Keypair Sets**, and **Keystore Studio**. The sidebar menu opens this page directly; each tab keeps its own filters, and the **Import** / **Create** buttons sit on the right side of the filter row of the related tab.

- **Overview cards** at the top show the total count per type together with a one-line status (for example `2 expired · 1 expiring soon`). Clicking a card switches to that tab.
- **Expiry status** is colour coded everywhere: green means valid, amber means it expires within 30 days, red means expired. Tab count pills also turn red when the tab contains expired or erroneous items.
- Related records are grouped **per gateway environment** inside each row; certificate and key store entries show alias, subject and a `Valid : from - until` badge.
- The **Truststore** tab is read **live from the selected gateway environment** — its content is not stored in Apinizer. Select an environment to fetch the currently trusted certificates; this tab has no Import or Create action.
- The **How to read** button at the top right opens a panel that explains each tab and the status colours.

Row clicks keep navigating to the existing detail pages; create and edit screens are unchanged.

## Module Core Components

The Secrets Management module provides centralized management of all components used for security and encryption in the Apinizer platform. With this module:

- Security certificates and keystores are managed
- Encryption keys and JWKS configurations are created
- Configurations are transferred between environments

## Using Records Across Projects

- **Using a key store or certificate by ID.** The test console, creating a proxy from a URL, specification download, the MCP and A2A connection test, uptime and health jobs, and LDAP, email, syslog and vault connections use a key store or certificate by its ID. The record must belong to your project or to **Administration**. Any other record is refused with HTTP 403. Records in **Administration** are available to every project.
- **Saving to the pool.** Saving a key store or certificate to the pool from the SSL settings screens or from Keystore Studio needs **Manage** permission in the **Secrets & Certificates** category of the target project. Users without this permission do not see the save-to-pool checkboxes. A direct call is refused with HTTP 403.
- **Selection lists.** The certificate, key store, JWK and key selection lists show the records of the project and the **Administration** records. To open them for a project, you need any role in that project, or a system administrator or system analyzer role. In the Administration scope, only a system administrator opens them. Other users get HTTP 403.
- **Certificates of all projects.** The list of the certificates of every project (`GET /certificates/all`) is for system administrators only. No screen uses it.
- **JWK dialog in a project.** When you open an **Administration** JWK from a JOSE policy editor, the dialog lists the certificates of your active project. The certificate bound to the JWK stays visible by name.
- **Certificate and key store lists.** Selection lists for certificates and key stores are open to a system administrator, a system analyzer, a system project manager, or a user with a role in any project. A user who has only a portal or promotion system role is refused with HTTP 403. A project screen lists the records of **Administration** and of the active project. The LDAP connection pool edit screen takes its scope (Administration or project) from the page URL. The lists return names and environments only, not certificate content.
- **Test Console in the top bar.** Only a system administrator sees **Tools > Test Console** in the top bar. If you check the save-to-pool box there, the uploaded key store or certificate goes to the **Administration** pool, not to the selected project.
