:::info

### List Columns

| Column | Content |
|--------|---------|
| **Client Route** | The relative paths of the client route. The first two paths show, the rest show as a `+N` link with a tooltip. Hosts and methods show below in small text. An empty list shows **Any host** or **All methods**. |
| **URL** | The access address for each environment. Next to the address, an icon and a label show the TLS of the environment: HTTP, HTTPS or mTLS. |
| **Created** | The creation date and the user who created the API Proxy. Click the column header to sort by creation date. |

### Show Menu

Use the **Show** button above the list to add columns. All options are off by default. Your choice is saved in your browser for this list.

| Option | Column | Content |
|--------|--------|---------|
| **Show route address** | **Route Address** | One line for each routing address. For a DB-2-API proxy, the names of the connection pools used by its methods follow the addresses. |
| **Show route condition** | **Route Condition** | The condition of each routing address, on the same line as its address. Available only when **Show route address** is on. |
| **Show policies** | **Policies** | The name of the active authentication policy and the number of other policies. When there is no active authentication policy, the cell shows **No authentication policy**. Hover over the cell to see every policy with its type, source (global policy, API Proxy, endpoint or proxy group), phase and state. |
| **Show traffic (last 24 hours)** | **Avg. Response Time** and **Last Error** | Values for the last 24 hours, read from the traffic log. Available only if you have permission to view analytics. If the traffic log cannot be read, an error message with a **Retry** button shows. |

In **Route Address**, a tag after the address shows its type when the proxy has more than one address or a weighted address: `[PRIMARY]`, `[CANARY]`, `[MIRROR]` or `[FAILOVER_ONLY]`. A weight greater than 1 shows as `w=3`. A proxy with one primary address and no weight shows the plain address. A list longer than 20 lines ends with `... (+N more)`.

On the LLM Gateway list, **Route Address** shows the LLM provider and the model, for example `Provider (model) [PRIMARY]`. Conditional routes show `[CONDITIONAL: route name]` and failover entries show `[FAILOVER #1]`, `[FAILOVER #2]` and so on. A conditional route that matches by meaning shows its example sentences in **Route Condition**.

:::info

On the LLM, MCP and A2A Gateway lists, **Show traffic (last 24 hours)** is not available.

:::

### Advanced Filtering

To perform more detailed searches, use the **Advanced Filtering** feature. You can access advanced filtering options by clicking the relevant icon next to the filter fields on the list.

**Advanced Filtering Criteria:**

| Criterion | Description |
|-----------|-------------|
| **API Proxy Name** | Retrieves API Proxy records containing a specific name. Case-insensitive. |
| **API Proxy Description** | Retrieves API Proxy records containing a specific description. Case-insensitive. |
| **API Type** | Filters by protocol type. You can select more than one. Options: REST, SOAP, gRPC, WebSocket |
| **API Proxy Type** | Filters by the type selected during creation. Options: Swagger, WSDL, Open API/Swagger 3.0.x, WADL, Fake API, Reverse Proxy, Mirror API, No-Spec API, DB-2-API, Script-2-API, Mock API, Websocket, gRPC, gRPC Proto |
| **Usage Type** | Filters by usage type. Options: All, Producer, Consumer, Producer and Consumer |
| **Sharing Type** | Filters by the API Proxy's sharing type. |
| **Category** | Filters by categories. |
| **API Proxy Address** | Retrieves API Proxy records containing a specific address. Case-insensitive. |
| **Method/Endpoint Name** | Retrieves API Proxy records containing a specific method or endpoint name. Case-insensitive. |
| **Method/Endpoint Description** | Retrieves API Proxy records containing a specific method or endpoint description. Case-insensitive. |
| **Parameter Name** | Retrieves API Proxy records containing a specific parameter name. Case-insensitive. |
| **Parameter Description** | Retrieves API Proxy records containing a specific parameter description. Case-insensitive. |
| **Router Address** | Retrieves API Proxy records containing a specific routing address. Case-insensitive. |
| **Deployment Status** | Filters by deployment status. Options: All, Deployed, Not Deployed |
| **Environment** | Filters by environment information. |
| **Trace Mode** | Filters by trace mode. Options: Active, Inactive |
| **Application Log Status** | Filters by application log status. Options: Active, Inactive |
| **Created from / Created to** | Filters by creation date. Both days are included. |
| **Created by** | Retrieves API Proxy records created by a user whose name contains the entered text. Case-insensitive. |
| **TLS** | Filters by the TLS of the environment where the API Proxy is deployed. Options: HTTP, HTTPS, mTLS. Only deployed API Proxies match. |
| **Authentication** | Options: With authentication policy, Without authentication policy. Only active authentication policies count. The check covers the policies of the API Proxy, its endpoints and its proxy groups. |
| **Policy Type** | Retrieves API Proxy records that use the selected policy types. |

### Sorting

The API Proxy list shows a table. You can sort it in the following ways:

- **Sorting**: Click the **Name** or **Created** column header.

### Excel Export

Click the Excel icon at the top of the page to export the list. The file contains the whole result of the current filters. It includes the **Created** and **Created by** columns. When you turn on **Show route address**, **Show route condition** or **Show policies**, the file also includes the **Route Address**, **Route Condition** and **Policies** columns.

### API Proxy Group Information

In the API Proxy list, the API Proxy groups that each API Proxy belongs to are displayed. An API Proxy can belong to multiple groups, and group information is shown in the list view.

:::info

For detailed information about API Proxy groups, you can refer to the [API Proxy Groups](/en/develop/api-proxy-group-creation) page.

:::

### Tag-Based Filtering


  <Accordion title="Filtering Methods" icon="filter">
    - Click a tag in the tag cloud to filter proxies with that tag
    - Combine multiple tags for more specific filtering
    - Use tag search to find proxies with specific tag combinations
  </Accordion>


### Tagging Best Practices

:::warning

**Things to Consider:**
- **Consistent Naming**: Create a tagging convention and stick to it
- **Number of Tags**: Use 3-5 tags per proxy
- **Hierarchical Tags**: Use dot notation (e.g., `payment.credit-card`)
- **Documentation**: Maintain a tag dictionary for your team

:::


### Operations Available from the List

In the API Proxy list, the following operations can be performed for each API Proxy:

<CardGroup cols={2}>
  <Card title="Export" icon="file-export">
    You can export the API Proxy for backup or migration. The export operation creates a file in JSON format.
  </Card>
  <Card title="Delete" icon="trash">
    You can delete the API Proxy from the list. Confirmation is requested before deletion.
  </Card>
  <Card title="Duplicate" icon="copy">
    You can create a copy of an existing API Proxy. The copy operation includes all configurations.
  </Card>
  <Card title="Reparse" icon="refresh">
    You can perform a reparse operation according to the API Proxy type. This operation re-reads and updates the API Proxy's spec file. The confirmation step can keep the new endpoints blocked for consumers that already have access. See [Access Control](/en/admin/identity-management/access-control).
  </Card>
</CardGroup>

:::info

These operations are performed on individual API Proxies. Bulk operation support is not available.

:::
