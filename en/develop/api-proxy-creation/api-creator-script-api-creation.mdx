## Script-2-API List

Select **Development → API Creator → Script-2-API** in the main menu. The page shows all Script-2-APIs in one card. It has the same layout as the Mock API list.

Type a name in the search box above the table to filter the list. Click the clear button next to the search box to reset the search.

The table has these columns:

| Column | Description |
|------|----------|
| **Name** | The name of the Script-2-API. Its description appears under the name. Click the name to open the editor. |
| **Endpoints** | The number of endpoints in the Script-2-API. |
| **Languages** | The script languages of the endpoints, for example **JS · GROOVY**. |

The **...** menu at the end of each row has these actions:

| Action | Description |
|------|----------|
| **Open editor** | Opens the Script-2-API editor. |
| **Duplicate** | Opens a dialog. Enter a new name to create a copy of the Script-2-API. |
| **Export** | Opens the Export/Import wizard for this Script-2-API. |
| **Delete** | Deletes the Script-2-API. See [Script-2-API Deletion](#script-2-api-deletion). |

The breadcrumb bar above the list has two buttons:

| Button | Description |
|------|----------|
| **Import** | Opens the Export/Import wizard with the API Creator type. Use it to import a file that you created with **Export**. For details, see [Export/Import](/en/admin/secrets-management/export-import). |
| **Create** | Opens the **Create Script API** dialog. See [Creating New Script-2-API](#creating-new-script-2-api). |

## Creating New Script-2-API

<Steps>
  <Step title="Go to Script-2-API Page from Menu">
    Select **Development → API Creator → Script-2-API** in the main menu.
    
    <img src="/images/develop/api-proxy-olusturma/script-api-olusturma-ekrani.png" alt="Script-2-API Creation Screen" width="1000" />
  </Step>
  
  <Step title="Create New API">
    Click the **Create** button in the breadcrumb bar at the top right of the page. The **Create Script API** dialog opens.
  </Step>
  
  <Step title="Fill API Information">
    Enter the name and the description of the API. Define the first endpoint under **First endpoint**. Click **Create**. Apinizer saves the Script-2-API with this endpoint and a starter script, then opens the editor.
    
    <img src="/images/develop/api-proxy-olusturma/script2api-new.png" alt="Filling API Information" width="1000" />
  </Step>
  
  <Step title="Add Endpoint">
    To add another endpoint, click the **+** button next to **API Endpoints** in the editor. If the Script-2-API has no endpoint, you can also click **Add** in the center area.
    
    <img src="/images/develop/api-proxy-olusturma/script2api-neww.png" alt="Adding Endpoint" width="1000" />
  </Step>
</Steps>

The **Create Script API** dialog has these fields:

| Field | Description |
|------|----------|
| **Name** | Required. The name of the Script-2-API. Apinizer checks that the name is unique. |
| **Description** | A short description of the Script-2-API. |
| **HTTP Method** | The method of the first endpoint. |
| **Path** | The path of the first endpoint. The path must start with "/". |
| **Language** | The script language of the first endpoint: **JavaScript** or **Groovy**. |

The starter script returns a short JSON message. To change the script, click **Configure** in the editor.

## Script-2-API Editor

The editor opens after you click **Create**. You can also open it with **Open editor** on the list. The editor has a left column, a center area, and breadcrumb buttons.

:::info

Each panel and dialog that changes data has its own **Save** button. **Save** stores your changes at once.

:::

### Left Column

- The name and the description of the Script-2-API are at the top. A summary line shows the number of endpoints and API proxies.
- The pencil button opens the **Edit name and description** dialog. Change the name and the description, then click **Save**. Apinizer saves the change at once.
- **API Endpoints** lists the endpoints. The **+** button adds a new endpoint.
- Each endpoint card shows the method, the path, a language badge (**GROOVY** or **JS**), and the description.
- Hold the pointer on a card to see the full path and the description.
- Click a card to select the endpoint. The selected card is highlighted.

### Center Area

The top of the center area shows the method, the path, the language, and the description of the selected endpoint. The actions of the endpoint are on the right, in this order:

| Action | Description |
|------|----------|
| **Try it** | Opens the **Try it** panel for this endpoint. See [Try it](#try-it). If the Script-2-API has no API Proxy, the button is disabled. Hold the pointer on the button to see the reason. |
| **Configure** | Opens the **Configure** panel of the endpoint. See [Endpoint Creation](#endpoint-creation). |

Only users who can manage API Creator see **Configure** and the note **Read-only · use Configure to edit**.

The script of the endpoint is below the header. The code view has line numbers and fills the page. It is read-only. To change the script, click **Configure**.

### Breadcrumb Buttons

The breadcrumb bar has these buttons, from left to right:

| Button | Description |
|------|----------|
| **Back** | Returns to the Script-2-API list. |
| **Export** | Opens the Export/Import wizard for this Script-2-API. |
| **Show Specs** | Opens the OpenAPI specification of the Script-2-API in a dialog. Switch between the **Open API Yaml** tab and the **Open API JSON** tab. Use **Copy to Clipboard** or **Download** to copy or download the specification. |
| **History** | Opens the **Audit and Rollback** records of the Script-2-API in a side panel. For details, see [Asset Lifecycle](/en/concepts/core-concepts/asset-lifecycle). |
| **Manage API Proxies** | Shows the API Proxies created from this Script-2-API and their deployment status. See [Deploy/Redeploy](#deployredeploy). |
| **Create API Proxy** | Opens the **Create API Proxy** dialog. See [Creating API Proxy from Script-2-API](#creating-api-proxy-from-script-2-api). |

## Endpoint Creation

Click the **+** button next to **API Endpoints** to add an endpoint. Click **Configure** to change the selected endpoint. The **Configure** panel opens from the right. It edits the definition and the script together.

The title of the panel is **New endpoint** for a new endpoint. A new endpoint starts with a starter script. For an existing endpoint, the title shows the method and the path.

<img src="/images/develop/api-proxy-olusturma/script-api-endpoint-olusturma.png" alt="Endpoint Creation Screen" width="1000" />

Fields used for endpoint creation configuration are explained below, categorized:

    <CardGroup cols={2}>
      <Card title="HTTP Method" icon="list">

        Required. Select the HTTP method of the endpoint: GET, POST, PUT, HEAD, OPTIONS, DELETE, PATCH, TRACE, or QUERY.
      </Card>
      
      <Card title="Path" icon="tag">
        **Field:** Path
        
        Required. The endpoint access address. The path must start with "/". If it does not, an error message appears. When API Proxy is created, the endpoint is accessed through this address.

    </CardGroup>

  <Accordion title="Script Settings">
    <CardGroup cols={2}>
      <Card title="Language" icon="code">
        **Field:** Language
        
        Required. Select the language of the script: **JavaScript** or **Groovy**. For a saved endpoint, the **Unsaved script changes** badge appears next to the field when the script differs from the saved script.
      </Card>
      
      <Card title="Script" icon="code">
        **Field:** Script

      <Card title="Test Script" icon="play">

        Opens the **Script Test** dialog to run the script with sample data. See [Script Test](#script-test).
      </Card>
    </CardGroup>
  </Accordion>

Click a name above the editor to insert it at the cursor. The names are in these groups:

| Group | Content |
|------|----------|
| **From client · read-only** | `requestBodyTextFromClient`, `requestHeaderMapFromClient`, `requestUrlParamMapFromClient` |
| **To client · write-only** | `responseBodyTextToClient`, `responseHeaderMapToClient`, `statusCodeToClient`, `responseErrorMessageToClient` |
| **Shared** | `customVariableMap` |
| **Context values** | A list with a search box. Select a context value to insert it. |
| **Snippets** | **Read a header**, **Read a query param**, **Return JSON**, and **Return an error**. The inserted code matches the selected language. |

The footer of the panel has these buttons:

- **Delete endpoint** deletes the endpoint after you confirm. This button is not shown for a new endpoint.
- **Test script** opens the **Script Test** dialog. The button is disabled when the script is empty.
- **Cancel** closes the panel and discards your changes. If the endpoint is new, Apinizer does not create it.
- **Save** stores the definition and the script together.

## Script Test

**Script Test** runs the script that is in the **Configure** panel with sample data. It runs the script even if you did not save it. It needs no API Proxy. Apinizer saves nothing and calls no backend.

<Steps>
  <Step title="Open Script Test">
    Click **Configure** on an endpoint, or click the **+** button to add a new endpoint. Click **Test script** in the footer of the panel. The **Script Test** dialog opens. The badge next to the title shows the language of the script.
  </Step>

  <Step title="Check the Pipeline">
    Under **Where does your script run?**, **Request** or **Response** is selected. The dialog selects the pipeline where the variables of your script work. A script that writes the response to the client runs in **Response**.
  </Step>

  <Step title="Select the Environment">
    Select the **Environment**. You cannot run the script without an environment.
  </Step>

  <Step title="Enter the Test Data">
    Fill in the sample data under **1 Test data**. Fill in only the values that your script reads. The other values can stay empty.
  </Step>

  <Step title="Run the Script">
    Click **Run script**, or press Ctrl + Enter. The result appears under **3 Result**.
  </Step>
</Steps>

The dialog has three columns:

| Column | Description |
|------|----------|
| **1 Test data** | Sample messages in cards: **From Client**, **To Backend**, **From Backend**, and **To Client**. The dialog shows the messages and the fields that your script uses. The fields are **Headers**, **Parameters**, **Request URL Path**, **Body**, **Error Message**, and **Status Code**. To add another field to a card, click the field next to **Add field:**. If your script reads a value that is empty, a note lists the value. Click the value in the note to add a sample value. |
| **2 Script** | The script in a code editor. Change the script and run it again. Your changes go back to the **Configure** panel when you close the dialog. The **Variables** panel is below the editor. Click a variable to copy it. The variables that your script uses are highlighted. The badge of each variable group shows the access in the selected pipeline: **Read only**, **Read and change**, or **Not available here**. |
| **3 Result** | The result of the last run. See the table below. |

The result has these parts:

| Part | Description |
|------|----------|
| Outcome | **Success** or **Failed**, the run time in milliseconds, and the number of changes. **No changes** means that the script changed nothing. |
| Changes | The title is **Request to the backend API** or **Response to the client**. The tables compare the result with the **To Backend** or **To Client** test data. Each row has a badge: **added**, **changed**, **removed**, or **no change**. Click **Show N unchanged** to see the rows without a change. |
| **Body** | If the script changed the body, the new body appears with the **changed** badge. Click **Show the body before the script** to see the old body. |
| Error | If the script fails, the result shows **The script stopped with an error.** and a hint. If the script sets an error message, the result shows **The flow stops here. The client gets this error.** and the status code. |

If you change the data or the script after a run, a note tells you to run the script again.

## Try it

**Try it** is different from **Script Test**:

- **Script Test** runs the script in the **Configure** panel, saved or not. It needs no API Proxy.
- **Try it** sends a real request through an API Proxy to the saved script.

:::note

**Try it** uses the same request service as the [Test Console](/en/develop/test-debug-tools/test-console). You need the **Execute** permission for Test Console.

:::

:::info

**Try it** needs an API Proxy that routes to the Script-2-API. If the Script-2-API has no API Proxy, the **Try it** button is disabled. Create an API Proxy first. See [Creating API Proxy from Script-2-API](#creating-api-proxy-from-script-2-api).

:::

The **Try it** panel is the same panel as in Mock API. For all its parts, see [Try it in Mock API](/en/develop/api-proxy-creation/api-creator-mock-api-creation#try-it).

<Steps>
  <Step title="Open Try it">
    Select an endpoint in the left column of the editor. Click **Try it** in the header of the endpoint. The **Try it** panel opens from the right.
  </Step>

  <Step title="Select API Proxy and Environment">
    The **API Proxy** list and the **Environment** list are on one line. The panel selects the first API Proxy and its first environment. To change them, select another API Proxy. Then select the **Environment**. The **Environment** list shows only the environments where the API Proxy is deployed.
  </Step>

  <Step title="Prepare the Request">
    The **Request** part shows the method and the full request URL. Change the request in the **Parameters**, **Headers**, and **Body** tabs.

    - Enter a value for each path parameter. A field appears for each parameter in the path.
    - Click **+ Add** in the **Parameters** tab to add a query parameter.
    - Click **+ Header** in the **Headers** tab to add a header. The tab starts with the header `Accept: application/json`.
    - Enter the request body in the **Body** tab. This tab appears for methods that carry a body, for example POST, PUT, and PATCH. For these methods, the panel also adds the header `Content-Type: application/json`.
  </Step>

  <Step title="Send the Request">
    Click **Send** at the end of the URL line. The **Response** part shows the status, the response time, the size, the response body, and the response headers.
  </Step>
</Steps>

The request card also has the **Copy cURL** and **Reset** buttons. An API Proxy that is not deployed shows the **Not deployed** badge. If the panel finds no API Proxy for the Script-2-API, it shows **No API Proxy for this API yet** and a **Create API Proxy** button.

## Creating API Proxy from Script-2-API

After the API's definitions are completed, it's time to open this API as an API Proxy.

:::info

At least one *endpoint* of the API created with Script-2-API must exist to create an API Proxy from Script-2-API. Until then, the **Create API Proxy** button is disabled.

:::

To open Script-2-API as an API Proxy for access, click the **Create API Proxy** button in the breadcrumb bar, as shown in the following visual.

<img src="/images/develop/api-proxy-olusturma/script-api-proxy-olustur-butonu.png" alt="Create Proxy Button" width="1000" />

The **Create API Proxy** dialog opens.

<img src="/images/develop/api-proxy-olusturma/script-api-proxy-olusturma-ekrani.png" alt="API Proxy Creation Screen" width="1000" />

The dialog suggests a name and a relative path from the name of the Script-2-API. Change them if needed. The dialog has these fields:

| Field | Description |
|------|----------|
| **Proxy name** | Required. The name of the API Proxy. Apinizer checks that the name is unique. |
| **Relative Paths** | The paths that route requests to the API Proxy. Each path must start with "/". If the project uses a relative path prefix, the prefix appears before each path. Click **+ Add a path** to add a path. |
| **Methods** | Select one or more methods in the list: GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS, or QUERY. If you select none, Apinizer routes all methods. |
| **Hosts** | Click **+ Add a host** to add a host. |
| **Headers** | Click **+ Add a header** to add a header with a name and a value. |
| **Category List** | Type a category and press Enter to add it. |
| **Deploy to** | One check box for each environment, with the access URL of the environment. |
| **Gateway URL** | A preview of the URL that clients use to reach the API Proxy. |

**Relative Paths**, **Methods**, **Hosts**, and **Headers** form the **Client Route** section. Define at least one path, method, host, or header. For details, see [Client Route Settings](/en/develop/api-proxy-creation/client-route-settings).

The first environment is checked by default. Clear the check box if you do not want to deploy now.

Click **Create and deploy**. Apinizer creates the API Proxy and deploys it to the checked environments. If you check no environment, Apinizer only creates the API Proxy. Click **Cancel** to close the dialog without creating an API Proxy.

After this step, what can be done is the same as the API Proxy document. You can review the [API Proxy Creation](/en/develop/api-proxy-creation) page for detailed information.

:::note

You can create multiple API Proxies for one Script-2-API.

:::

## Deploy/Redeploy

To manage from the Script-2-API page, use the panel opened by the **Manage API Proxies** button in the breadcrumb bar. In the opened panel, you can perform Deploy, Redeploy, and Undeploy operations for API *Proxy*s created from this API. You can visit our Revision, Deployment, Redeployment, Undeployment pages for more detailed information on this topic.

## Script-2-API Deletion

To delete a Script-2-API, click the **...** menu at the end of its row in the Script-2-API list and select **Delete**. A dialog asks you to confirm. It lists the API Proxies that Apinizer deletes with the Script-2-API. Enter the name of the Script-2-API and click **Delete**.

When a Script API is deleted, all API Proxies connected to it are first removed (undeploy) and then deleted.

<img src="/images/develop/api-proxy-olusturma/script-api-silme-uyarisi.png" alt="Script-2-API Deletion Warning" width="500" />
