## DB-2-API List

Select **Development → API Creator → DB-2-API** in the main menu. The table has these columns: **Name**, **Connection Pool Definition**, **Database Type**, **Endpoints** and **URL**. The **Database Type** column shows the database types of the connection pools that the endpoints use.

Use the filters above the table to narrow the list:

| Filter | Description |
|---|---|
| **Search by name** | Shows the DB-2-APIs whose name contains the text. |
| **Search by SQL text** | Shows the DB-2-APIs that have the text in the SQL of an endpoint. |
| **Search by endpoint path** | Shows the DB-2-APIs that have the text in the path of an endpoint. |
| **All connection pools** | Select one connection pool definition. |
| **Database Type** | Select one database type, for example Oracle, MySQL, PostgreSQL or MongoDB. |

Click the Excel button to export the filtered list. The file has these columns: **Name**, **Description**, **Project**, **Database Type**, **Connection Pool Definitions** and **Endpoints**.

### Governance List

System administrators and system analyzers can see the API Creators of all projects. Open **Administration > API Governance > API Creators**. You need the API Creator license for this menu item.

The page has three tabs: **DB-2-API**, **Mock API** and **Script-2-API**. Each tab is a read-only list. It has no create, import or **...** menu actions. Click a name to open the View page. The list adds a **Project** column and a **Project** filter. Click the Excel button to export the filtered list of the tab.

The **Used By** panel on the detail page of a database connection lists the DB-2-APIs that use the connection. See [Connection Management](/en/integrations/connection-management/overview#used-by-panel).

## Creating New DB-2-API

Creating a DB-2-API is a two-step wizard: **Definition** and **Review**.

<Steps>
  <Step title="Go to DB-2-API Page from Menu">
    **Development → API Creator → DB-2-API** item is selected in the main menu.
  </Step>
  
  <Step title="Create New API">
    The **Create** button at the top right of the opened interface is clicked.
    
    <img src="/images/develop/api-proxy-olusturma/db-api-olustur-butonu.png" alt="DB-2-API Create button" width="800" />
  </Step>
  
  <Step title="Fill API Information">
    On the **Definition** step, the **Name** (required, must be unique) and **Description** of the *API* are entered and **Continue** is clicked. The panel on the right explains how a DB-2-API works: the client calls a REST API through Apinizer, Apinizer runs the SQL statement on the database, and the OpenAPI specification is generated automatically.
    
    <img src="/images/develop/api-proxy-olusturma/db2api-new.png" alt="Filling DB-2-API information" width="800" />
  </Step>

  <Step title="Review and Create">
    On the **Review** step, the type, name, and description are shown. Clicking **Create DB-2-API** creates the *API* and opens its editor, where you add the endpoints.
  </Step>
</Steps>

The editor shows the API on the left (name, description, and counts of endpoints, connection pools, and API Proxies; the edit icon changes the name and description) with the **Endpoints** list below it, and the selected endpoint on the right. At the top, the **Variables** and **Show Specs** icons and the **⋯** menu are available. The **⋯** menu holds **API Proxy** (Create API Proxy, Manage API Proxies), **Transfer** (Export, Duplicate), **History** (Audit and Rollback), and **Delete**.

## Testing SQL

It may be desired to see what result will be obtained when a request is sent to the endpoint. If the query to be executed for the endpoint has parameters, test data (Test Value) is entered and the **Try this query** button is pressed.

To send a real request, use **Try it** at the top of the endpoint. It sends the request through an API Proxy created from this DB-2-API, so at least one API Proxy must exist and be deployed.

The template returned as the test result is the Response object that is stable in Apinizer. If there are multiple records matching the query, only the first record is given in the example response.

<img src="/images/develop/api-proxy-olusturma/db-api-sql-test.png" alt="Testing SQL" width="800" />

:::info

If a **null** value is desired to be sent for testing, it is sufficient to write **null** as the parameter.

:::

## Creating API Proxy from DB-2-API

When there is at least one *Method/Endpoint*, an API Proxy is created for DB-2-API from the **⋯** menu with **API Proxy → Create API Proxy**.

:::warning

At least one *Method/Endpoint* must exist to create an API Proxy from DB-2-API. Until then the menu item is disabled ("Add an endpoint first.").

:::

On the **Create API Proxy** dialog, enter the **Proxy name**, set the **Client Route** (relative paths, methods, hosts, and headers; choose at least one), and select the environments to deploy to under **Deploy to**. Clicking **Create and deploy** creates the API Proxy and deploys it to the selected environments. If you select no environment, the API Proxy is created but not deployed.

After this step, what can be done is exactly the same as the API Proxy document. You can refer to the [API Proxy Creation](/en/develop/api-proxy-creation) page for details.

:::info

You can create multiple API Proxies from one DB-2-API.

:::

## Deploy/Redeploy

To view and manage API Proxies in DB-2-API, open the **⋯** menu and click **API Proxy → Manage API Proxies**; they are viewed and managed from the opened window. In the opened window, Deploy/Undeploy and Redeploy operations for API Proxies created with DB-2-API are performed in this section.

To deploy the API Proxy, open **Manage API Proxies** and press the deploy icon.

<img src="/images/develop/api-proxy-olusturma/db-api-proxy-yonetme.png" alt="API Proxy management" width="600" />

After the above operation, confirmation is required. Information about the deployment operation is created and the **(Deploy) Deploy** button is clicked.

<img src="/images/develop/api-proxy-olusturma/db-api-deploy.png" alt="Deploy screen" width="600" />

When a new *Method/Endpoint* is added to DB-2-API or one of the existing *Method/Endpoint*s is updated, all API Proxies must be redeployed.

When you add a new *Method/Endpoint* or update an existing *Method/Endpoint*, a notification like the following will appear.

<img src="/images/develop/api-proxy-olusturma/db-api-yeniden-yukleme-bildirimi.png" alt="Redeploy notification" width="600" />

By saying **Redeploy Required**, changes are applied to API Proxies.

<img src="/images/develop/api-proxy-olusturma/db-api-redeploy.png" alt="Redeploy screen" width="600" />

After the above operation, confirmation is required. Information about the redeployment operation is created and the **(Redeploy) Redeploy** button is clicked.

<img src="/images/develop/api-proxy-olusturma/db-api-redeploy-onay.png" alt="Redeploy confirmation screen" width="600" />

From the DB-2-API page, go to the API Proxy by clicking the link in the API Proxy's name.

<img src="/images/develop/api-proxy-olusturma/db-api-proxy-link.png" alt="Link from DB-2-API to API Proxy" width="600" />

Similarly, to go to the DB-2-API page from the API Proxy page, go by clicking the DB-2-API name in the API Proxy as shown below.

<img src="/images/develop/api-proxy-olusturma/db-api-geri-link.png" alt="Link from API Proxy to DB-2-API" width="600" />

## DB-2-API Deletion

When a DB-2-API is deleted, all API Proxies connected to it are first removed (Undeploy) and then deleted.
