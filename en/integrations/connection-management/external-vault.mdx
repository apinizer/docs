description: "You can read secret values from HashiCorp Vault, AWS Secrets Manager, Azure Key Vault, Google Secret Manager or CyberArk Conjur at runtime. You can use vault references in environment variables and API client secrets, so Apinizer never stores the secret value."
---

An External Vault connection lets the gateway read a secret from your own secret manager. Apinizer stores only the vault settings and a one-line reference such as `{vault://vault-prod/core-banking#password}`. It never stores or shows the value.

## How It Works

1. The database keeps the vault settings and the references. It does not keep the secret value.
2. When an environment is deployed, each worker pod logs in to the vault and reads the values. The values stay in the memory of that pod. Requests do not wait for the vault.
3. In the background, the worker reads the value again from the vault at the refresh interval. A rotated secret is picked up within one refresh period.

## Supported Vault Types

| Type | Login methods |
|------|---------------|
| HashiCorp Vault | Kubernetes, AppRole, Token |
| AWS Secrets Manager | IAM role, Access key |
| Azure Key Vault | Managed identity, Service principal |
| Google Secret Manager | Workload identity, Service account key |
| CyberArk Conjur | API key |

The type cannot change after the vault is created. Prefer the login methods that store nothing secret in Apinizer (Kubernetes, IAM role, Managed identity, Workload identity). The Token login of HashiCorp Vault is meant for trials only: it expires and you must rotate it by hand.

## Vault List

Open **Connection Management > External Vault**. In a project, the list shows the vaults of that project. In Administration, it shows the vaults of all projects.

- **Filter bar**: **Project** (Administration only) and **Name**. **Search** applies the filters. **Clear** empties them.
- **Cards / Table**: switches the view of the list.
- **Columns**: shows or hides the columns Type, Location, Authentication, Refresh, References, Status and Project (Administration only). The Name column always stays.
- **Excel**: exports the list with the applied filters.

The **References** column shows how many environment variables and API client secrets read from the vault.

## Vault Detail Page

The detail page shows the General, Connection, Authentication and cache sections. Use **Configure** on a section to change it. When you save, the changes are saved and sent to the gateways in one step. The workers read the values again with the new settings.

The **⋯** menu on the page has these items:

- **Test Connection**: one item for each published environment. A worker of the selected environment logs in to the vault with the stored settings.
- **Activate / Deactivate**: a deactivated vault is removed from every gateway right away. Its settings stay. References to it cannot be read, so requests that need them are rejected until you activate it again. You must type the vault name to confirm.
- **Where it applies**: lists the environment variables and API client secrets that use the vault, and the effect of each action on them.
- **Duplicate**, **Export**, **Move to Global**, **Audit and Restore** and **Delete**.

## Cache and Refresh Settings

| Field | Description |
|-------|-------------|
| **Refresh every (s)** | How often each worker reads the value again from the vault, in the background. 0 reads the value once at deploy. |
| **Retry after failure (s)** | After a failed read, the worker waits this long before it tries again. |
| **Keep last value (min)** | While the vault cannot be reached, the worker keeps the last value it read for this long. After that, it rejects the requests that need the value. 0 rejects them at once. A value that was never read is always rejected. |

When the vault answers again after an outage longer than the **Keep last value** time, the value comes back by itself. You do not need to deploy again.

## Vault References

A reference points to one secret: `{vault://<vault name>/<secret>#<key>}`.

- **Vault name**: lower-case letters, digits and dashes. It cannot change while references use it.
- **Secret**: the secret path or name in the vault. It is relative to the **Base path** of the vault.
- **Key** (optional): the field to read when the secret has several fields. If you leave it empty, the **Default field** of the vault is read, or the whole value.

The reference picker has the **Vault**, **Secret** and **Key** fields and a **Browse** button. **Browse** lists only the secret names; it never shows secret values. It needs the list permission on the vault.

## Where You Can Use a Reference

- **Environment variable**: select **External vault** as the value source of the variable. See [Environment Variables](/en/develop/environment-variables).
- **API client secret**: select **External vault** when you issue the client secret.

An environment variable or an API client secret can name only a vault of its own project or a global vault (a vault in Administration). A reference to a vault of another project is rejected.

:::warning

The referenced secret of an API client must be a `{vault://...}` reference or a `${...}` / `#{...}` variable expression. Any other text is rejected with the error message "A secret reference must be an external vault reference or a `${...}` variable expression."

:::

:::info

Task flows (Integration) do not read the vault. A variable that reads from a vault stays unresolved in a task flow.

:::

## Export and Import

Export packages carry only the reference, never the secret value. When you import with **Replace**, Apinizer replaces only a vault of the same project.
