## What is API Integrator?

:::info

API Integrator or **Task Flow Manager** (will be named this way from now on), is a workflow management system that can automatically execute multiple tasks in a specific order. Each task can use the output produced by the previous step, communicate with external systems, or perform operations defined in internal systems.

:::

## Basic Features of Task Flow Manager

<CardGroup cols={2}>
  <Card title="Sequential Task Execution" icon="list">
    Tasks are defined sequentially and run in the order they are defined.
  </Card>

  <Card title="Data Flow" icon="arrow-right">
    The output of one task can be used as the input of the next task, and interconnected business processes can be executed effectively.
  </Card>

  <Card title="Automatic Triggering" icon="clock">
    Task flows can run automatically with a scheduler. The schedule is optional. Turn off **Run on schedule** to run a task flow only with **Execute** or through its endpoint.
  </Card>

  <Card title="HTTP Triggering" icon="globe">
    Task flows can be triggered by HTTP requests.
  </Card>

  <Card title="Error Management" icon="shield-alert">
    Operations to be performed in error situations can be defined, enabling predefined operations to occur when an error is encountered in the task flow.
  </Card>

  <Card title="Detailed Logging" icon="file-text">
    Execution and log records of each task can be viewed step by step every time the workflow is triggered.
  </Card>

  <Card title="Statistics" icon="bar-chart">
    Successful, failed, in-progress, and total operation statistics can be viewed through a user-friendly graph.
  </Card>
</CardGroup>

:::info

To use API Integrator, you need to enter the access address information of the integrator in the **Define Your API Integration Module** field on the **General Settings** page under the **Administration** tab in the top navigation bar.

:::

## Task Flow List

The **Task Flows** tab lists the task flows of the active project. Use the **Table** and **Cards** buttons to change the view. The table is the default view.

The table has these columns: **Name**, **Status**, **Trace**, **Executions**, **Success**, **Last Result**, **Last run**, **Tasks**, **Failure Actions** and **Endpoint**. The **Tasks** column shows the number of tasks in the flow. The **Failure Actions** column shows the number of failure actions.

Use the filters above the list to narrow it:

| Filter | Description |
|---|---|
| **Search by name** | Shows the task flows whose name contains the text. |
| **Status** | Select **Enabled** or **Disabled**. |
| **Endpoint** | Select **Enabled** or **Disabled**. |
| **Trace** | Select **On** or **Off**. |

Click the Excel button to export the filtered list. The file has these columns: **Name**, **Description**, **Project**, **Status**, **Trace**, **Endpoint**, **Tasks** and **Failure Actions**. The list and the file do not contain the trigger token.

The View page of a task flow shows the schedule in one of three states:

- A schedule exists: The page shows the cron expression and the next fire time.
- **No schedule:** The task flow has no schedule. Run it with **Execute** or through its endpoint.
- **Unknown:** The Integration server could not be reached. Click **Retry** to read the schedule again.

The cron expression and the endpoint address are only on the View page. The list does not show them.

### Governance List

System administrators and system analyzers can see the task flows of all projects. Open **Administration > API Governance > Integrations**. You need the Integration license for this menu item.

The governance list is read-only. It has no create button and no row menu. It adds a **Project** column and a **Project** filter. Click a task flow name to open its View page.

The header of the governance View page has a **Back** button and a **⋯** menu. The first item of the menu is **Switch to project and edit**. Only a system admin sees it. The item is off, with the reason written under it, when you are not a member of the project of the record. When you choose it, a dialog asks you to confirm. After you confirm, the active project changes to the project of the record and the record opens in its editor.

On the View page, click **Details** to open the run history of the task flow. The View page also shows the endpoint address. System administrators and system analyzers can do both.
