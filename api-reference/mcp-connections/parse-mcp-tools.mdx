---
title: "Discover / Reparse MCP Tools"
description: "Fetches the tools/list from the MCP server using the connection's stored (saved) settings, persists the discovered tool catalog on the connection, and redeploys it to the gateway workers. Manual 'Discover / Reparse' — the counterpart of A2A's parse-skills."
---

## Endpoint

```
POST /apiops/projects/{projectName}/mcp-connections/{connectionName}/parse-tools/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|--------------|
| projectName | string | Yes | Project name |
| connectionName | string | Yes | MCP connection name (must already exist) |

### Query Parameters

None

### Request Body

None. This endpoint takes no body — it calls `tools/list` on the MCP server using the **already-saved** connection settings (endpoint, auth, transport). To discover against different settings, save them first with [Create](/api-reference/mcp-connections/create-mcp-connection) or [Update](/api-reference/mcp-connections/update-mcp-connection) MCP Connection, or use [Test MCP Connection](/api-reference/mcp-connections/test-mcp-connection) for a one-off probe that leaves the stored connection untouched.

## Response

### Success Response (200 OK)

Returns the full, updated connection object — same shape as [Get MCP Connection](/api-reference/mcp-connections/get-mcp-connection) — with `discoveredToolCount` and `toolsParsedAt` reflecting the new discovery.

```json
{
  "status": "SUCCESS",
  "resultList": [
    {
      "id": "665f2a1c9b3e4a0012ab34cd",
      "projectId": "665f2a1c9b3e4a0012ab0001",
      "projectName": "MyProject",
      "name": "github-mcp",
      "endpoint": "https://mcp.example.com/mcp",
      "transport": "HTTP_SSE",
      "authScheme": "BEARER",
      "bearerTokenSet": true,
      "discoveredToolCount": 12,
      "toolsParsedAt": 1721900000000,
      "healthStatus": "HEALTHY",
      "lastHealthCheckAt": "2026-07-25T09:15:00Z",
      "healthMessage": null
    }
  ],
  "resultCount": 1
}
```

#### Response Fields

Same object shape as [List MCP Connections](/api-reference/mcp-connections/list-mcp-connections#mcp-connection-object-fields). The fields most relevant to this endpoint:

| Field | Type | Description |
|-------|------|--------------|
| discoveredToolCount | integer | Number of tools found by this parse — read the tools themselves via [List MCP Tools](/api-reference/mcp-connections/list-mcp-tools) |
| toolsParsedAt | integer | Epoch millis of this parse (now current) |
| healthStatus | string | Updated based on this discovery attempt: `HEALTHY`, `DOWN` or `UNKNOWN` |
| healthMessage | string | Populated with a short error description if `healthStatus` is `DOWN`; `null` otherwise |

### Error Response (400 Bad Request) — Not Found

```json
{
  "status": "FAILURE",
  "resultMessage": "MCP connection (name: github-mcp) was not found!"
}
```

### Error Response (400 Bad Request) — Discovery Failure

Operational discovery failures (server unreachable, `tools/list` rejected, malformed capability response) are caller-actionable and returned as `400`, not `500`:

```json
{
  "status": "FAILURE",
  "resultMessage": "Failed to fetch tools/list: MCP server returned 503"
}
```

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

## cURL Example

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/mcp-connections/github-mcp/parse-tools/" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Permissions

- User must have **`AI_DEVELOPMENT` + `MANAGE`** permission in the project

## Notes and Warnings

- **Uses The Stored Connection**: The probe always runs against the connection's currently saved settings — there is no request body to override endpoint/auth for a single call. Update the connection first if you need to discover against different settings.
- **Persists + Redeploys**: Unlike [Test MCP Connection](/api-reference/mcp-connections/test-mcp-connection) (transport-only, no side effects), a successful call here **writes** the discovered tool catalog onto the connection and pushes the updated connection to the gateway workers.
- **Read The Result Separately**: This endpoint returns the connection object (with a tool *count*), not the tool list itself. Use [List MCP Tools](/api-reference/mcp-connections/list-mcp-tools) to read back the actual discovered tools.
- **Also Runs Automatically**: The same discovery also runs automatically on a connection's first successful deploy — this endpoint is for a manual re-discovery after the MCP server's capabilities change.
- **Health Status Side Effect**: A parse attempt updates `healthStatus`/`healthMessage`/`lastHealthCheckAt` on the connection, whether it succeeds or fails.
