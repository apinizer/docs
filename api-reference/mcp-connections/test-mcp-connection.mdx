---
title: "Test MCP Connection"
description: "Runs a live tools/list probe against the supplied AI Gateway MCP connection settings, Manager-side and in-process. The request body is required (unlike the LLM provider test-connection endpoint) — this endpoint does not read or fall back to a stored connection. It does not persist, deploy, or mutate any cache."
---

## Endpoint

```
POST /apiops/projects/{projectName}/mcp-connections/{connectionName}/test-connection/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |
| Content-Type | application/json | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|--------------|
| projectName | string | Yes | Project name |
| connectionName | string | Yes | MCP connection name (`name` in the body falls back to this if blank, otherwise must match it) |

### Query Parameters

None

### Request Body

**Required.** A `ConnectionConfigMcp` object — same shape as [Create MCP Connection](/api-reference/mcp-connections/create-mcp-connection#request-body-fields). It **must** include `"_class": "mcp"`. Unlike the [LLM provider test-connection](/api-reference/llm-providers/test-llm-provider-connection) endpoint, this one does **not** fall back to any stored connection when the body is empty — the body itself is the entire test target, so real credentials (`bearerToken` / `clientSecret`) must be supplied in plaintext.

#### Full JSON Body Example

```json
{
  "_class": "mcp",
  "name": "github-mcp",
  "endpoint": "https://mcp.example.com/mcp",
  "transport": "HTTP_SSE",
  "mcpProtocolVersion": "2024-11-05",
  "allowPrivateNetworkEgress": false,
  "authScheme": "BEARER",
  "bearerToken": "ghp_...secret..."
}
```

### Notes

- `_class: "mcp"` is mandatory.
- The request body is not persisted anywhere by this endpoint.
- `${env}` placeholders in the body (e.g. an endpoint referencing an environment variable) are resolved before the probe runs.

## Response

### Success Response (200 OK)

```json
{
  "status": "SUCCESS",
  "deploymentResult": {
    "success": true,
    "detail": "MCP connection test successful"
  }
}
```

#### Response Fields

| Field | Type | Description |
|-------|------|--------------|
| status | string | Envelope status — `SUCCESS` when the test executed |
| deploymentResult | object | Result of the live `tools/list` probe |
| deploymentResult.success | boolean | `true` if the MCP server accepted the handshake and returned a `tools/list` response |
| deploymentResult.detail | string | `"MCP connection test successful"` on success, or the raw transport/handshake failure reason on failure |

### Error Response (400 Bad Request) — Validation

```json
{
  "status": "FAILURE",
  "resultMessage": "MCP connection body can not be empty!"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "MCP connection name in path (github-mcp) does not match name in body (github-mcpp)!"
}
```

### Error Response (400 Bad Request) — Transport Failure

The MCP transport layer reports operational failures (server unreachable, TLS handshake rejected, non-2xx from the MCP endpoint) as a caller-actionable `400`, not a `500`:

```json
{
  "status": "FAILURE",
  "resultMessage": "Failed to connect to MCP server: Connection refused"
}
```

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

## cURL Example

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/mcp-connections/github-mcp/test-connection/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "_class": "mcp",
    "name": "github-mcp",
    "endpoint": "https://mcp.example.com/mcp",
    "transport": "HTTP_SSE",
    "mcpProtocolVersion": "2024-11-05",
    "authScheme": "BEARER",
    "bearerToken": "ghp_...secret..."
  }'
```

## Permissions

- User must have **`AI_DEVELOPMENT` + `MANAGE`** permission in the project

## Notes and Warnings

- **Body Is Required — No Stored Fallback**: Unlike [Test LLM Provider Connection](/api-reference/llm-providers/test-llm-provider-connection), this endpoint never reads the stored connection or backfills blank secrets. Every call is a fresh, in-process probe of exactly what is in the body.
- **No Persistence, No Deploy, No Cache Mutation**: This is a pure transport-layer probe. It does not save the connection, does not push anything to the workers, and does not touch the capability cache. Use [Create](/api-reference/mcp-connections/create-mcp-connection) or [Update](/api-reference/mcp-connections/update-mcp-connection) to persist a working configuration, and [Discover / Reparse Tools](/api-reference/mcp-connections/parse-mcp-tools) to populate the tool catalog on a saved connection.
- **Live Probe**: The test performs a real MCP handshake and `tools/list` call against the target server — it is not a syntactic validation only.
- **Outcome In The Body**: A failed probe still returns `200 OK` with `status: "SUCCESS"` when the request itself was well-formed; check `deploymentResult.success`. A transport-layer failure (unreachable server, rejected handshake) instead surfaces as an HTTP `400` with `resultMessage` — see above.
