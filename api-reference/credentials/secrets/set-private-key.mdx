## Endpoint

```
PUT /apiops/projects/{projectName}/credentials/{username}/privateKey/{keyName}/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |
| username | string | Yes | Username of the consumer |
| keyName | string | Yes | Name of the private key to assign |

### Notes

- Private key must exist in the project or in the admin project
- Key must be of type `PRIVATE_KEY`
- Consumer must exist
- Only one private key can be assigned to a consumer at a time
- Assigning a new private key replaces the existing one if present


## Notes and Warnings

- **Private Key Requirements**:
  - Private key must exist in the project or admin project
  - Key must be of type `PRIVATE_KEY`
  - Key name is case-sensitive

- **Consumer Requirements**:
  - Consumer must exist
  - Consumer must be in the same project or accessible from the project

- **Replacement Behavior**:
  - Assigning a new private key replaces any existing private key
  - Previous private key assignment is automatically removed

- **Security Considerations**:
  - Private keys are sensitive and should be handled securely
  - Ensure proper access controls are in place

- **Automatic Deployment**:
  - Consumer is automatically deployed to all environments after private key assignment
  - Deployment results are returned in the response

## Permissions

- User must have **`IDENTITY` + `MANAGE`** permission in the project
- For automatic deployment, user must also have **`IDENTITY` + `DEPLOY_UNDEPLOY`** permission
