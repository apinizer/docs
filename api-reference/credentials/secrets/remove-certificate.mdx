---
title: "Remove Certificate"
description: "Removes the certificate assignment from a consumer. The consumer will no longer use the certificate for TLS/SSL connections or digital signatures. The consumer is automatically deployed to all environments after the certificate is removed."
---

:::warning Deprecated

This operation is deprecated. It still works. Use [the successor operation](/api-reference/consumers/secrets/remove-consumer-certificate) of the [Consumers API](/api-reference/consumers) instead.

Every response of this operation carries a `Deprecation: @1792368000` header and a `Link` header whose `rel` is `successor-version`:

```
Link: </apiops/projects/{projectName}/consumers>; rel="successor-version"
```
:::

## Endpoint

```
DELETE /apiops/projects/{projectName}/credentials/{username}/certificate/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |
| username | string | Yes | Username of the consumer |

### Notes

- Consumer must exist
- Consumer must have a certificate assigned, otherwise the operation returns an error

## cURL Example

```bash
curl -X DELETE \
  "https://demo.apinizer.com/apiops/projects/MyProject/credentials/api-user/certificate/" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Notes and Warnings

- **Consumer Requirements**:
  - Consumer must exist
  - Consumer must have a certificate assigned, otherwise the operation returns a 400 error

- **Automatic Deployment**:
  - Consumer is automatically deployed to all environments after certificate removal
  - Deployment results are returned in the response

- **No Impact on Certificate**:
  - The certificate itself is not deleted
  - Only the assignment to the consumer is removed

## Permissions

- User must have **`IDENTITY` + `MANAGE`** permission in the project
- For automatic deployment, user must also have **`IDENTITY` + `DEPLOY_UNDEPLOY`** permission
