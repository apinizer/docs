---
title: "Consumer Organization Actions"
description: "Suspend and resume every credential of a consumer organization, or revoke them for good. Suspend and resume are reversible and idempotent; revoke-credentials is one-way and reports how many credentials it revoked."
---

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/consumer-organizations/{code}/actions/suspend` | Disable and redeploy every enabled credential of the organization's applications; reversible |
| `POST` | `/consumer-organizations/{code}/actions/resume` | Re-enable and redeploy exactly the credentials the suspend disabled |
| `POST` | `/consumer-organizations/{code}/actions/revoke-credentials` | Permanently revoke every credential below the organization and every token issued before the call |

All three are under `/apiops/projects/{projectName}`, take no request body, require a Personal API Access Token (`Authorization: Bearer YOUR_TOKEN`) and answer `200 OK` with the organization, in the shape of [Get Consumer Organization](/api-reference/consumer-organizations/crud/get-consumer-organization).

## Suspend and resume

Both actions are **idempotent**: suspending a suspended organization, or resuming an active one, repeats safely and needs no `Idempotency-Key` header. The organization's `suspended` field is `true` after a suspend and `false` after a resume.

Suspend disables and redeploys every enabled credential below the organization, so no traffic passes for them. A credential that was already disabled before the suspend stays disabled after the resume, because resume re-enables exactly the credentials the suspend disabled.

## Revoke credentials

:::warning

`revoke-credentials` is **one-way**. It permanently revokes every credential below the organization and every token issued before this call. There is no undo and no resume.

:::

The answer carries one extra field:

| Field | Type | Description |
|-------|------|-------------|
| `revokedCredentialCount` | integer | How many credentials this call revoked. Present on the answer of `revoke-credentials` only |

## Administration project and portal roles

Unlike the rest of this API, these actions are also accepted on the **administration project's** path (`/apiops/projects/admin/consumer-organizations/{code}/actions/...`), where portal organizations live. Only a system administrator passes that path; any other caller gets `404 resourceNotFound`.

An organization that holds a portal application also needs the **System Administrator**, **Portal Business** or **Portal Manager** role, in addition to `IDENTITY` + `MANAGE`. A caller without it gets `403 permissionDenied` (`params.reason` = `portalRoleRequired`), and nothing is changed.

## Errors

| Status | Error key | Cause |
|--------|-----------|-------|
| 403 | permissionDenied | The organization holds a portal application and the caller has none of the roles above (`params.reason` = `portalRoleRequired`) |
| 404 | resourceNotFound | The code is unknown, or the project is outside the scope of the caller |

## cURL Example

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/consumer-organizations/acme-partners/actions/suspend" \
  -H "Authorization: Bearer YOUR_TOKEN"

curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/consumer-organizations/acme-partners/actions/revoke-credentials" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Permissions

- User must have **`IDENTITY` + `MANAGE`** permission in the project
- A project outside the scope of the caller answers `404 resourceNotFound`, never `403`; the `403` above is the only one these actions return
