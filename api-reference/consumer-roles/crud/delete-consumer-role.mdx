---
title: "Delete Consumer Role"
description: "Deletes a consumer role the way the Consumer Roles screen does. The role is also removed from the consumers, the applications and the API proxy authorization settings that use it."
---

## Endpoint

```
DELETE /apiops/projects/{projectName}/consumer-roles/{roleName}
```

## Authentication

Requires a Personal API Access Token.

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |
| roleName | string | Yes | Name of the role in the project |

## Response

`200 OK`.

The delete removes the role from the consumers and applications that hold it, and from the authorization settings of the API proxies of the project. Then it undeploys the role. This is the same behavior as the Consumer Roles screen.

The response is a [write response](/api-reference/apiops-common-contract#write-responses). `result` is the deleted role. `runtimeDeployment.state` is `IN_SYNC` when every environment acknowledged the change, or `DEGRADED` when the change is stored but at least one environment did not acknowledge it. Do not retry a `DEGRADED` write; redeploy instead. `resourceVersion` is not returned.

An unknown `roleName` answers `404 resourceNotFound`.

## cURL Example

```bash
curl -X DELETE \
  "https://demo.apinizer.com/apiops/projects/MyProject/consumer-roles/API_USER" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Permissions

- User must have **`IDENTITY` + `MANAGE`** permission in the project
- A project outside the scope of the caller answers `404 resourceNotFound`, never `403`
- The admin project is served: a call on `/apiops/projects/admin/consumer-roles` addresses the roles of the admin project
