---
title: "Prompt Decorator Policy"
description: "The Prompt Decorator policy prepends and/or appends admin-authored, role-tagged text blocks to a request's messages array before it reaches the LLM provider — always-on system instructions the client never has to send."
---

## General Information

### Policy Types

```plaintext
ai-prompt-decorator
```

Request-phase only. Each block is fixed configuration; nothing about it is client-controlled.

### Endpoints

#### List Policies

```plaintext
GET /apiops/projects/{projectName}/apiProxies/{apiProxyName}/policies/
```

#### Add Policy


#### Update Policy

```plaintext

```

#### Delete Policy

```plaintext
DELETE /apiops/projects/{projectName}/apiProxies/{apiProxyName}/policies/{policyName}/
```

## Blocks

`blocks` is an ordered list of text snippets. Each one is either inserted as a new message or, when `mergeIntoExistingSystem=true` and the block's role is `system`, merged into an existing system message instead of adding a new one.

:::note Only affects OpenAI-compatible chat bodies
A block only has a meaningful place to go when the request body has a `messages[]` array. On the legacy completions `prompt` field, or any non-JSON body, the policy is a documented no-op — the request proceeds undecorated rather than being blocked over a shape it cannot act on.
:::

### Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| enabled | boolean | No | Whether the decorator runs at all. Default `true`. |
| blocks | array | No | Ordered list of blocks. See [Block fields](#block-fields). Empty/absent means no-op. |
| mergeIntoExistingSystem | boolean | No | Merges a `system`-role block into an existing system message's content instead of inserting a new message. Only meaningful for `system` blocks — `user`/`assistant` blocks always insert as new messages. Default `false`. |
| maxTotalChars | integer | No | Fail-closed budget (chars) for the SUM of every enabled block's resolved content. Exceeding it rejects the request with `400` rather than silently truncating a block. Default `16384`. |

### Block fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| position | string | Yes | `PREPEND` or `APPEND`. Prepended blocks keep their relative order at the start of `messages[]`; appended blocks at the end. |
| role | string | Yes | `system`, `user` or `assistant`. |
| content | string | Yes | The block's text. Resolves both `${env}` and `#{context}` variables. |
| enabled | boolean | No | Whether this block is active. Default `true` — a disabled block is skipped without being deleted. |
| presetId | string | No | Id of the built-in decorator preset this block was copied from, if any. A bound block (non-null `presetId`) is refreshed automatically whenever that preset is edited. This is a provenance marker for the catalog link, not a lookup key — it is installation-local, cleared on import, and the block stays fully functional either way. |

#### Body Fields

See [Fields](#fields) and [Block fields](#block-fields) above.

### Response

#### Success Response (200 OK)

```json
{
  "status": "SUCCESS",
  "deploymentResult": {
    "success": true,
```

#### Error Responses

| Code | Reason |
|------|--------|
| 400 | Blank `name`; `maxTotalChars` not positive; a block's `position` is not `PREPEND`/`APPEND`; a block's `role` is not `system`/`user`/`assistant`; proxy not found. |
| 401 | Missing or invalid token. |
| 403 | The token's account lacks permission on the project. |

## Notes and Warnings

- **This policy runs before the guardrails, not after.** Together with the Prompt Template policy, Prompt Decorator is hoisted to the front of the request pipeline so every guardrail, the semantic cache key and the token count all see the fully-assembled prompt. A badly-written block is still caught by the same guardrails that catch a badly-written client prompt.
- **Preset-bound blocks stay in sync automatically.** A block copied from a built-in decorator preset (`presetId` set) is refreshed whenever that preset is edited, and the affected deployment is flagged for redeploy. A hand-written or detached block (`presetId` null) is never touched by preset edits.
- **Exceeding `maxTotalChars` blocks the request, it does not truncate.** A cut-off safety or compliance instruction can read as the opposite of what it said, or vanish entirely — so the platform rejects the request instead of guessing where to cut.
- **`presetId` does not travel across installations.** Export/import clears it; the copied block's content is preserved in full, it simply becomes a detached local copy on the target installation.
