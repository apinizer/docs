## Overview

An API client is a machine credential owned by a consumer or an application — never a subject in its own right. [API Clients](/en/admin/identity-management/credentials#api-clients) covers the concept, the Manager screen, and the client-secret storage modes; this page documents the Management API surface for the same object.

Every address on this page is under `/apiops/projects/{projectName}` and follows the shared [Common Contract](/api-reference/apiops-common-contract): the stable error envelope, correlation IDs, bounded pagination, and `Idempotency-Key` on every create. A caller outside the project's scope always gets `404 resourceNotFound`, never `403`. API clients are project-owned, so the admin (platform) project has no clients of its own and a platform-scoped call is refused with `400 malformedRequest` (`params.reason = platformScopeNotSupported`).

References on this surface are **portable**. A client is addressed by its `apiClientKey` — a public, installation-wide identifier, distinct from the Mongo id and from the gateway-facing `clientId` a token request presents. Its **owner** travels as `{type, key}`: `type` is `CONSUMER` or `APPLICATION`, and `key` is that owner's own public name — a consumer's `username` or an application's `name` — the same reference a limit assignment's `subject.key` already uses, so one client's `owner.key` matches its owner's rows on the sibling surfaces. An organization travels as its `code`.

:::note No reveal endpoint
A generated secret is returned exactly once, by `POST .../secret-versions`, under `no-store`. There is no endpoint on this surface to show a stored secret again — that is a Manager-screen operation only: it demands a written reason, writes an audit row, and is rate-limited, none of which has a meaning for an unattended pipeline. A caller that lost the value rotates again; see [Idempotency](#idempotency) for why a replay cannot hand it out a second time either.
:::

## Endpoints

:::note No access endpoints
An API client has no access setting of its own: it is authorized by the ACL rows of its ACL owner, which are managed on the Access Control screen and with the credential access endpoints. The `authorization-restrictions` and `entitlements` endpoints of earlier versions are removed.
:::

### API Clients — `/api-clients`

| Method | Path | Description |
|---|---|---|
| `GET` | `/api-clients` | List the project's API clients, by `clientId` by default |
| `GET` | `/api-clients/{apiClientKey}` | One API client; never carries secret material |
| `POST` | `/api-clients` | Create an `ACTIVE` client with its first secret and deploy it to the gateways (`201` + `Location`, `no-store`) |
| `PUT` | `/api-clients/{apiClientKey}` | Replace the editable half of a client; the version must match |
| `POST` | `/api-clients/{apiClientKey}/actions/suspend` | Pause an `ACTIVE` client, reversibly |
| `POST` | `/api-clients/{apiClientKey}/actions/resume` | Return a `SUSPENDED` client to service |
| `POST` | `/api-clients/{apiClientKey}/actions/revoke` | End a client permanently and destroy its material — irreversible (`200`, or `202` + `Location` when handed to the durable sweeper) |

:::warning[Draft lifecycle removed]
A client is no longer created as a `DRAFT`. The `POST /api-clients/{apiClientKey}/actions/activate` endpoint (answers `404`) and the draft discard `DELETE /api-clients/{apiClientKey}` (answers `405`) of earlier versions are removed. To take a client out of service, suspend or revoke it.
:::

### Secret Generations — `/api-clients/{apiClientKey}/secret-versions`

| Method | Path | Description |
|---|---|---|
| `POST` | `/api-clients/{apiClientKey}/secret-versions` | Rotate: add a new generation (`201` + `Location`, `no-store`); a generated value is returned once |
| `POST` | `/api-clients/{apiClientKey}/secret-versions/{versionId}/actions/revoke` | Destroy one generation now, including the active one |

### Owner Views (read-only) {#owner-views}

| Method | Path | Description |
|---|---|---|
| `GET` | `/api-clients/{apiClientKey}/limit-assignments` | Every limit assignment whose subject is **this client** |

:::note Not paged
The endpoint above returns a plain array — not the [paged envelope](/api-reference/apiops-common-contract#pagination) `GET /api-clients` uses. Each answers a bounded set that belongs to one client.
:::

### List API clients

`GET /api-clients?ownerType&ownerKey&state&search&page&size&sort` sorts by `clientId,asc` by default; `sort` may also name `operationalState` or `expiresAt`. `name` is still accepted as a sort field and is read as `clientId`. `size` is capped at 200, same as [Pagination](/api-reference/apiops-common-contract#pagination).

| Parameter | Type | Meaning |
|---|---|---|
| `ownerType` | enum | `CONSUMER` or `APPLICATION` — required together with `ownerKey` |
| `ownerKey` | string | The owner's own public key (a consumer's `username` or an application's `name`) — required together with `ownerType` |
| `state` | enum | `ACTIVE` \| `SUSPENDED` \| `REVOKED` (`DRAFT` only matches clients left from earlier versions) |
| `search` | string | Case-insensitive `clientId` / `description` contains-search |

`ownerKey` without `ownerType` is `400 malformedRequest` (`params.reason = ownerKeyRequiresOwnerType`); `ownerType` without `ownerKey` is the mirror (`params.reason = ownerTypeRequiresOwnerKey`).

:::note Ownerless listing is intentional
Unlike the equivalent Manager screen, `ownerType`/`ownerKey` are **optional** here: the project is already authorized from the path, and the answer is bounded by the standard page size — a caller reconciling a whole project's clients has no single owner to name. The owner filter remains available and, when given, is resolved to an id first, so an unknown owner is `404 resourceNotFound` rather than an empty page.
:::

## Idempotency

`POST /api-clients` and `POST /api-clients/{apiClientKey}/secret-versions` each require an `Idempotency-Key` header (see [Common Contract → Idempotency](/api-reference/apiops-common-contract#idempotency)); a missing or blank header is `400 idempotencyKeyRequired`. The key is claimed per project and per operation, together with a canonical hash of the request body:

| Situation | Result |
|---|---|
| New key | The client is created with its first secret, or the secret generation is issued |
| Same key, same body, first call already finished | `409 idempotencyReplayExpired` — `params.resource` names the `apiClientKey` (create) or the `versionId` (secret generation) the first call produced; read it back with `GET` instead |
| Same key, same body, first call still in flight | `409 idempotencyInProgress` |
| Same key, a different body | `409 idempotencyKeyReused` |

:::warning A replayed secret is never handed out twice
The dedup record for `POST /api-clients` and `POST .../secret-versions` stores only the outcome's identity — the generation's `versionId` and the client's new `version` — never the generated value. A replayed key answers `409`, not the original response; store the secret from the first successful call, because it cannot be retrieved again.
:::

## Request Body

### Create / update an API client — `POST` / `PUT /api-clients/{apiClientKey}`

Both share one body. `POST` creates the client **active**, with its first secret, and deploys it to the gateways at once — there is no draft to equip and activate later. On `PUT`, the management key (`apiClientKey`) and the `clientId` are immutable — a body that omits either keeps the stored value, a body that changes either is `409 lifecycleConflict`. The owner is **not editable** through this body: an `owner` sent on update is accepted syntactically and ignored, the stored owner is always restored. An absent `organizationCode` on update keeps the stored organization rather than detaching the client.

| Field | Type | Required | Meaning |
|---|---|---|---|
| `owner` | object | Create: yes. Update: no (kept) | `{type, key}` — see [Owner reference](#owner-reference) below |
| `organizationCode` | string | No | The owning organization's `code`; absent on update keeps the stored one, an explicit blank clears it |
| `description` | string | No | |
| `clientId` | string | No | Blank on create mints one; immutable afterwards |
| `validFrom` / `expiresAt` | timestamp | No | Validity window |
| `allowedGrantTypes` | string[] | No | |
| `tokenEndpointAuthMethod` | string | No | `none` makes a public client (browser login): it is created active without a secret |
| `redirectUris` | string[] | No | Browser-login redirect URIs of a public client; absent on update keeps the stored list |
| `tokenIssuanceProfile` | string | No | |
| `tokenNeverExpires` | boolean | No | |
| `tokenExpiresInAmount` | integer | No | Paired with `tokenExpiresInUnit` |
| `tokenExpiresInUnit` | enum | No | `MILLI_SECONDS` \| `SECONDS` \| `MINUTES` \| `HOURS` \| `DAYS` \| `WEEKS` \| `MONTHS` \| `YEARS` |
| `refreshTokenAllowed` | boolean | No | |
| `refreshTokenCount` | integer | No | |
| `refreshTokenExpiresInAmount` | integer | No | Paired with `refreshTokenExpiresInUnit` |
| `refreshTokenExpiresInUnit` | enum | No | Same values as `tokenExpiresInUnit` |
| `jwtSignatureAlgorithm` | string | No | |
| `secret` | object | `POST` only, optional | The first secret, in the shape of [`POST .../secret-versions`](#issue-or-rotate-a-secret) and under the same rules. Absent, a value is generated and returned once. Refused for a public client, and on `PUT` (`400 malformedRequest`, `params.field = secret`, `params.reason = secretOnCreateOnly`) |
| `version` | integer | `PUT` only | The stored `version` the caller expects to be updating |

A body missing entirely on `POST`/`PUT` is `400 malformedRequest` (`params.reason = bodyRequired`). A create whose body carries no `owner` at all is `400 malformedRequest` (`params.field = owner`, `params.reason = ownerRequired`). A first secret that cannot be used now (already expired, or starting later) is refused before anything is written.

A client has no display name on this surface; it is identified by its `clientId`. A `name` sent in the body is accepted and ignored, never a `400`.

#### Owner reference

| Field | Type | Meaning |
|---|---|---|
| `type` | enum | `CONSUMER` or `APPLICATION` |
| `key` | string | The owner's own public key: a consumer's `username`, or an application's `name` |

### Lifecycle action body

Shared by `suspend` / `resume` / `revoke` on the client, and by `actions/revoke` on a secret generation:

| Field | Type | Required | Meaning |
|---|---|---|---|
| `version` | integer | **Yes** | The stored `version` the caller expects; a missing value is `400 malformedRequest` (`params.field = version`, `params.reason = versionRequired`) rather than an unguarded write |
| `reason` | string | No | Operator free text; stored verbatim, read back only by the actions that record one (`suspend`, `revoke`) |

### Issue or rotate a secret — `POST /api-clients/{apiClientKey}/secret-versions?version=` {#issue-or-rotate-a-secret}

The stored client `version` travels as a **required query parameter**. `Idempotency-Key` is also required (see [Idempotency](#idempotency)).

| Field | Type | Meaning |
|---|---|---|
| `materialType` | enum | `LOCAL_SECRET` (default when absent) or `SECRET_REFERENCE` |
| `generate` | boolean | Ask Apinizer to produce the value; ignored for a referenced secret |
| `value` | string | The operator's own secret, for a manual (non-generated) `LOCAL_SECRET`; never echoed back |
| `reference` | string | Where the secret lives, for `SECRET_REFERENCE`; mutually exclusive with `value` |
| `label` | string | Operator-facing name of this generation |
| `validFrom` / `expiresAt` | timestamp | Validity window |
| `graceWindowSeconds` | integer | How long the superseded generation keeps working; absent takes the platform's suggested default |
| `storageMode` | enum | `ENCRYPTED` (default, recoverable) or `HASHED` (verifier only, shown once); ignored for `SECRET_REFERENCE` |

An absent `version` query parameter is `400 malformedRequest` (`params.field = version`, `params.reason = versionRequired`); a missing body entirely is `400 malformedRequest` (`params.reason = bodyRequired`).

### Mutation — `200` / `201` / `202` {#mutation}

Every write on the client itself (`POST`, `PUT`, and every `actions/*`) answers with the fields below; `POST` adds the first secret's fields — see [Client created](#client-created-201):

| Field | Type | Meaning |
|---|---|---|
| `apiClient` | object | The client as it now stands — the [API client](#api-client-200-201) shape above |
| `runtimeDeployment` | object | What the push told the gateways, when the write triggered one — the shared [Write responses](/api-reference/apiops-common-contract#write-responses) shape (`state`: `IN_SYNC` \| `DEGRADED` \| `PENDING`, `environments[]`); absent when nothing was pushed |

## Errors

Every error follows the [Common Contract's error envelope](/api-reference/apiops-common-contract#error-response) — branch on `errorKey`, never on `message`.

| Error key | When |
|---|---|
| `malformedRequest` | A body was missing (`params.reason = bodyRequired`), a required field was missing (`ownerRequired`, `versionRequired`, `modeRequired` — `params.field` names it), a `secret` was sent on `PUT` (`secretOnCreateOnly`), `ownerKey`/`ownerType` was given without its pair (`ownerKeyRequiresOwnerType` / `ownerTypeRequiresOwnerKey`), the admin (platform) project was addressed (`platformScopeNotSupported`), or an underlying validation rule was refused — `params.reason` then carries the service's own key |
| `resourceNotFound` | An unknown or out-of-project `apiClientKey` or `ownerKey` |
| `versionConflict` | The stored `version` no longer matches what the caller sent — `params.reason = apiClientRevisionConflict` (client) |
| `lifecycleConflict` | `params.reason` names the cause: `apiClientIllegalTransition` (a suspend/resume/revoke move the current state refuses), `apiClientNotReady` (the client does not have what it needs to be in service), `apiClientRevokedReadOnly` (an update of a revoked client), `apiClientSecretRotationRefused`, `secretVersionAlreadyRevoked`, `clientIdImmutable` / `apiClientKeyImmutable` (an update tried to change an immutable identifier) |
| `idempotencyKeyRequired` | `POST /api-clients` or `POST .../secret-versions` was missing its `Idempotency-Key` header |
| `idempotencyKeyReused` | The same key was sent with a different request body |
| `idempotencyReplayExpired` | The same key and body already completed — `params.resource` names what it created |
| `idempotencyInProgress` | The same key and body's first call is still running |
| `permissionDenied` | Authenticated, but the caller lacks Identity **Manage** (writes) or **View** (reads) |

See [Common Contract → Error keys](/api-reference/apiops-common-contract#error-keys) for the complete closed set and the status-code table.

## Permissions & Licensing

- Reads (`GET`) require the **Identity** permission at **View**; writes (`POST`/`PUT`) require it at **Manage**. No AI Gateway license module gates any endpoint on this surface.
- API clients are project-owned; the admin (platform) project has none of its own and every endpoint refuses a platform-scoped call with `400 malformedRequest` (`params.reason = platformScopeNotSupported`).
- A project outside the caller's authorized scope is always `404 resourceNotFound`, never `403` — see [Common Contract → Telling 402, 403 and 404 apart](/api-reference/apiops-common-contract#telling-402-403-and-404-apart). The same rule applies to a client whose *stored* project does not match the one in the path: it is answered with the identical `404` a nonexistent key would get, never a distinguishing status.

## Example

Create a client owned by a consumer — it is active at once, with its first secret — rotate the secret, then revoke the client:

```bash
# 1. Create — ACTIVE, deployed, with a generated first secret
curl -X POST "https://apinizer.example.com/apiops/projects/finance/api-clients" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 5e2a1c7b-9d4f-4a3e-8b1c-2f6d9a0e3c81" \
  -d '{
    "owner": { "type": "CONSUMER", "key": "acme-integration-user" },
    "description": "Nightly settlement batch job",
    "allowedGrantTypes": ["client_credentials"],
    "tokenExpiresInAmount": 1,
    "tokenExpiresInUnit": "HOURS",
    "secret": { "generate": true, "label": "initial", "storageMode": "ENCRYPTED" }
  }'
# 201 Created, Location: /apiops/projects/finance/api-clients/acme-nightly-batch-4f9a2c8d
# response.secret holds the plaintext ONCE; store it now. response.apiClient.version is the version to send next

# 2. Rotate the secret — send the client's current version
curl -X POST "https://apinizer.example.com/apiops/projects/finance/api-clients/acme-nightly-batch-4f9a2c8d/secret-versions?version=1" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 9a0c3e7f-1b2d-4c5e-9f6a-8d7c1e0b4a92" \
  -d '{
    "generate": true,
    "label": "rotation-1",
    "graceWindowSeconds": 3600
  }'
# 201 Created — response.secret holds the new plaintext ONCE

# 3. Revoke it later — irreversible; read the client back first for its current version
curl -X POST "https://apinizer.example.com/apiops/projects/finance/api-clients/acme-nightly-batch-4f9a2c8d/actions/revoke" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "version": 2, "reason": "Batch job decommissioned" }'
# 200, or 202 + Location when handed to the durable sweeper
```
