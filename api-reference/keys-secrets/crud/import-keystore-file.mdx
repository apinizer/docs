---
title: "Import Keystore File"
description: "Uploads a .jks, .p12 or .pfx file directly instead of Base64-encoding it into a JSON body, and writes it to every environment you name. Creates a new keystore, or updates an existing one when override is set."
---

## Endpoint

```
POST /apiops/projects/{projectName}/keystores/import-file/
```

:::info
This uploads the **raw file**. To restore a keystore from an Apinizer package produced by [Export Keystore](/api-reference/keys-secrets/crud/export-keystore), use [Import Keystore](/api-reference/keys-secrets/crud/import-keystore) instead.
:::

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |
| Content-Type | multipart/form-data | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |

### Form Fields

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| keystoreFile | file | Yes | — | The keystore file (`.jks`, `.p12` or `.pfx`) |
| keystoreName | string | Yes | — | Name of the keystore to create or update |
| password | string | Yes | — | Keystore password |
| environmentList | string | Yes | — | Comma-separated environment names the file is written to |
| keyStoreType | string | No | inferred | `JKS` or `PKCS12`. When omitted, it is inferred from the file extension |
| keystoreDescription | string | No | — | Description |
| alias | string | No | — | Alias stored with the material |
| override | boolean | No | false | When `true`, updates an existing keystore of that name; otherwise a new one is created |

## Response

### Success Response (200 OK)

```json
{
  "status": "SUCCESS"
}
```

When the keystore was stored but could not be deployed to its environments, the response says so:

```json
{
  "status": "SUCCESS",
  "resultMessage": "Keystore was saved successfully but deployment to environments failed. Details: ...",
  "deploymentResult": {
    "success": false,
    "detailList": []
  }
}
```

### Error Response (400 Bad Request)

```json
{
  "status": "FAILURE",
  "resultMessage": "Keystore (name: partner-store) is already exist! Send override=true to update it."
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "Unknown keyStoreType (BCFKS)! Supported values: JKS, PKCS12"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "password value can not be empty!"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "Environment (Staging) is not found or user does not have privilege to access it!"
}
```

#### Common Causes

- A keystore of that name already exists and `override` was not set
- `override=true` was sent but no keystore of that name exists
- `keyStoreType` is neither `JKS` nor `PKCS12`
- `password` or `environmentList` is empty, or an environment cannot be reached by the user

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

## cURL Example

### Example 1: Upload a PKCS12 Keystore

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/keystores/import-file/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "keystoreFile=@partner-store.p12" \
  -F "keystoreName=partner-store" \
  -F "password=YOUR_PASSWORD" \
  -F "environmentList=Production,UAT"
```

### Example 2: Upload a JKS Keystore with an Explicit Type

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/keystores/import-file/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "keystoreFile=@partner-store.keystore" \
  -F "keystoreName=partner-store" \
  -F "password=YOUR_PASSWORD" \
  -F "keyStoreType=JKS" \
  -F "environmentList=Production"
```

### Example 3: Rotate an Existing Keystore

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/keystores/import-file/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "keystoreFile=@partner-store-2027.pfx" \
  -F "keystoreName=partner-store" \
  -F "password=YOUR_PASSWORD" \
  -F "environmentList=Production" \
  -F "override=true"
```

## Notes and Warnings

- **The type is inferred from the extension**: `.p12` and `.pfx` are read as PKCS12, anything else as JKS. An explicit `keyStoreType` always wins, which is what an unconventional extension needs.
- **One file, every named environment**: the uploaded file is written to each environment in `environmentList`. To give environments different keystores, call the endpoint once per environment.
- **An empty environment list is rejected**: a keystore written to no environment reaches nothing, while the call would still read success.
- **The file name is remembered**: its extension is reused when the keystore is downloaded again through [Export Keystore File](/api-reference/keys-secrets/crud/export-keystore-file).
- **The bytes are stored as uploaded**: the file that comes back out is the file that went in.

## Permissions

- User must have **`SECRETS` + `EXPORT_IMPORT`** permission in the project
