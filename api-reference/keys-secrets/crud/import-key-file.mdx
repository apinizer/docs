---
title: "Import Key File"
description: "Uploads key material as a file instead of embedding it in a JSON body, and writes it to every environment you name. Creates a new key, or updates an existing one when override is set."
---

## Endpoint

```
POST /apiops/projects/{projectName}/keys/import-file/
```

:::info
This uploads the **raw material**. To restore a key from an Apinizer package produced by [Export Key](/api-reference/keys-secrets/crud/export-key), use [Import Key](/api-reference/keys-secrets/crud/import-key) instead.
:::

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |
| Content-Type | multipart/form-data | Yes |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |

### Form Fields

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| keyFile | file | Yes | — | The key file. PEM, or Base64 that decodes to PEM |
| keyName | string | Yes | — | Name of the key to create or update |
| keyType | string | Yes | — | `SECRET_KEY`, `PRIVATE_KEY` or `PUBLIC_KEY` |
| environmentList | string | Yes | — | Comma-separated environment names the material is written to |
| keyDescription | string | No | — | Description |
| alias | string | No | — | Alias stored with the material |
| override | boolean | No | false | When `true`, updates an existing key of that name; otherwise a new key is created |

## Response

### Success Response (200 OK)

```json
{
  "status": "SUCCESS"
}
```

When the key was stored but could not be deployed to its environments, the response says so:

```json
{
  "status": "SUCCESS",
  "resultMessage": "Key was saved successfully but deployment to environments failed. Details: ...",
  "deploymentResult": {
    "success": false,
    "detailList": []
  }
}
```

### Error Response (400 Bad Request)

```json
{
  "status": "FAILURE",
  "resultMessage": "Key (name: signing-key) is already exist! Send override=true to update it."
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "Unknown keyType (RSA)! Supported values: SECRET_KEY, PRIVATE_KEY, PUBLIC_KEY"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "environmentList value can not be empty!"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "Environment (Staging) is not found or user does not have privilege to access it!"
}
```

or

```json
{
  "status": "FAILURE",
  "resultMessage": "Key content is neither PEM nor valid Base64 for key type PRIVATE_KEY! Send the PEM content Base64-encoded."
}
```

#### Common Causes

- A key of that name already exists and `override` was not set
- `override=true` was sent but no key of that name exists
- `keyType` is not one of the three supported values
- `environmentList` is empty, or names an environment the user cannot reach
- The uploaded file is neither PEM nor Base64 that decodes to PEM

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

## cURL Example

### Example 1: Create a Key from a PEM File

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/keys/import-file/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "keyFile=@signing-key.pem" \
  -F "keyName=signing-key" \
  -F "keyType=PRIVATE_KEY" \
  -F "environmentList=Production,UAT"
```

### Example 2: Replace an Existing Key

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/keys/import-file/" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "keyFile=@signing-key-rotated.pem" \
  -F "keyName=signing-key" \
  -F "keyType=PRIVATE_KEY" \
  -F "environmentList=Production" \
  -F "override=true"
```

## Notes and Warnings

- **One file, every named environment**: the uploaded material is written to each environment in `environmentList`. To give environments different material, call the endpoint once per environment.
- **An empty environment list is rejected**: material written to no environment reaches nothing, while the call would still read success.
- **PEM or Base64**: the same shapes [Create Key](/api-reference/keys-secrets/crud/create-key) accepts. Base64 content is decoded and must yield PEM.
- **The file name is remembered**: its extension is reused when the key is downloaded again through [Export Key File](/api-reference/keys-secrets/crud/export-key-file).
- **Deployment is reported, not assumed**: a key that saved but failed to reach its environments returns success together with the deployment detail, rather than a bare success.

## Permissions

- User must have **`SECRETS` + `EXPORT_IMPORT`** permission in the project
