---
title: "API Proxy Promotion"
description: "This section contains endpoints for promoting an API proxy from one project to another on the same installation."
---

Promotion carries an API proxy definition between projects of the same installation — typically from
a development project to a test or production project. It is a two-step flow: read the source
project's proxies with their full detail, then write the selected proxy into the target project.

## Endpoints

- [List API Proxies for Promotion](/api-reference/api-proxies/promotion/list-api-proxies-for-promotion) - Read the source project's proxies with client route, routing, and deployment records
- [Save API Proxy for Promotion](/api-reference/api-proxies/promotion/save-api-proxy-for-promotion) - Create or update the proxy in the target project, optionally deploying it

## Promotion vs. Export/Import

Both move a proxy between locations, but they solve different problems:

| | **Promotion** | **Export / Import** |
|---|---|---|
| Scope | Between projects of the **same** installation | Between installations, or as a backup |
| Transport | JSON payload over two API calls | Package file (`.zip`), optionally encrypted |
| Dependencies | Global policies are materialized in the target | `withDependencies` resolves the full dependency graph |
| Environment wiring | Rebuilt from the target project's environments | Name-based remapping, unresolved entries reported |
