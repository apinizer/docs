---
title: "Discover LLM Provider Models"
description: "Asks an AI Gateway LLM provider for the models it serves and lists them, without saving anything. You can use the list to choose the models to add to the supported models of the provider."
---

## Endpoint

```
POST /apiops/projects/{projectName}/llm-providers/{providerName}/discover-models/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| Authorization | Bearer \{token\} | Yes |
| Content-Type | application/json | Only if a body is sent |

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |
| providerName | string | Yes | LLM provider name (the provider must already exist) |

### Request Body

**Optional.** The call runs from the API Manager. It does not go through a gateway worker, and it saves nothing.

- **Omitted or empty body**: the stored provider is used as it is.
- **Body supplied**: it is an LLM provider object, as on [Test LLM Provider Connection](/api-reference/llm-providers/test-llm-provider-connection). It replaces the whole stored connection for this call only. `name` may be blank, but if present it must match `providerName`.

A secret field that you leave out of the body (`apiKey`, `apiSecret`, `serviceAccountJson`) is taken from the stored provider only when the connection target is unchanged. When you change the endpoint, the authentication scheme, the header name, the provider type or the deployment type, send the credential again. Send `apiKey`, and also `"apiSecret": ""` and `"serviceAccountJson": ""` for the secrets that the provider does not use. Otherwise the call answers `400` with `credentialReentryRequired`. See the guard on [Test LLM Provider Connection](/api-reference/llm-providers/test-llm-provider-connection#secret-guard).

```json
{
  "name": "deepseek-primary",
  "providerType": "DEEPSEEK",
  "endpoint": "https://api.deepseek.com/v1",
  "authScheme": "BEARER",
  "authHeaderName": "Authorization",
  "apiKey": "sk-a-key-to-try",
  "apiSecret": "",
  "serviceAccountJson": "",
  "deploymentType": "CLOUD"
}
```

## Response

### Success Response (200 OK)

The example is shortened. The text in `detail` varies.

```json
{
  "status": "SUCCESS",
  "resultCount": 2,
  "resultList": [
    {
      "modelId": "deepseek-chat",
      "displayName": "DeepSeek Chat",
      "ownedBy": "deepseek",
      "contextWindow": 64000,
      "maxOutputTokens": 8192,
      "alreadyAdded": true
    },
    {
      "modelId": "deepseek-reasoner",
      "displayName": "DeepSeek Reasoner",
      "ownedBy": "deepseek",
      "alreadyAdded": false
    }
  ],
  "success": true,
  "detail": "Models listed",
  "httpStatus": 200,
  "latencyMs": 412,
  "environmentName": "apimanager",
  "discoveredAt": "2027-01-12T10:15:30.123Z",
  "missingModelIds": []
}
```

#### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| resultList | array | The models that the provider reports |
| resultList[].modelId | string | Model ID |
| resultList[].displayName | string | Display name, when the provider reports one |
| resultList[].ownedBy | string | Owner of the model, when the provider reports one |
| resultList[].contextWindow | integer | Context window, when the provider reports it |
| resultList[].maxOutputTokens | integer | Maximum output tokens, when the provider reports it |
| resultList[].alreadyAdded | boolean | `true` when the model is already in the stored `supportedModels` of the provider |
| resultList[].labels | array of string | Classifier labels, for a classifier model |
| success | boolean | `true` when the provider answered the model list |
| detail | string | Short description of the outcome, or the reason of a failure |
| httpStatus | integer | HTTP status of the provider answer. `0` means a network error |
| latencyMs | integer | Duration of the call in milliseconds |
| environmentName | string | Always `apimanager` |
| discoveredAt | string | Time of the discovery, ISO-8601 |
| missingModelIds | array of string | Stored models that the provider no longer reports. Filled only after a successful discovery |

A discovery that the provider refused or could not answer is still `200 OK`, with `success: false`, the reason in `detail` and in `resultMessage`, and the provider status in `httpStatus`. Check `success`.

### Error Response (400 Bad Request)

The provider does not exist, the name in the path and the name in the body differ, or the connection target changed and a secret was left out.

```json
{
  "status": "FAILURE",
  "resultMessage": "Connection target changed — re-enter the credential before testing (credentialReentryRequired)"
}
```

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

## cURL Example

```bash
curl -X POST \
  "https://demo.apinizer.com/apiops/projects/MyProject/llm-providers/deepseek-primary/discover-models/" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Permissions

- User must have **`AI_DEVELOPMENT` + `MANAGE`** permission in the project

## Notes and Warnings

- **Nothing is saved**: To add a model, send it in `supportedModels` with [Update LLM Provider](/api-reference/llm-providers/update-llm-provider).
- **No secret in the answer**: The response never contains a credential.
