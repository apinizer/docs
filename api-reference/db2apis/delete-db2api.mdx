---
title: "Delete DB2API"
description: "Deletes a DB2API definition of a project by name, together with every API Proxy that was created from it. Apinizer undeploys the API Proxies first, then deletes them."
---

## Endpoint

```
DELETE /apiops/projects/{projectName}/db2apis/{db2ApiName}/
```

## Authentication

Requires a Personal API Access Token.

### Header

```
Authorization: Bearer YOUR_TOKEN
```

## Request

### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| projectName | string | Yes | Project name |
| db2ApiName | string | Yes | Name of the DB2API |

The call has no body.

## Response

### Success Response (200 OK)

```json
{
  "status": "SUCCESS",
  "deploymentResult": {
    "success": true
  }
}
```

The definition and every API Proxy created from it are deleted. This is the same delete as in the Manager screen.

### Error Response (400 Bad Request)

The name is unknown in the project. The call answers the same `400` as the read call of the definition.

```json
{
  "status": "FAILURE",
  "resultMessage": "DB2API (name: customer-db) was not found!"
}
```

### Error Response (401 Unauthorized)

```json
{
  "status": "FAILURE",
  "resultMessage": "Token is not valid!"
}
```

### Error Response (403 Forbidden)

The user may delete the definition but lacks the permission to delete one of its API Proxies. Nothing is deleted: Apinizer checks every API Proxy before it touches the first one. The body follows the [Common Contract](/api-reference/apiops-common-contract#error-response).

```json
{
  "status": "FAILURE",
  "errorKey": "forbiddenInsufficientPermission",
  "message": "error.forbiddenInsufficientPermission",
  "correlationId": "7f1c9e2a-8f43-4d2e-9a11-6b5d0c3e2f77"
}
```

## cURL Example

```bash
curl -X DELETE \
  "https://demo.apinizer.com/apiops/projects/MyProject/db2apis/customer-db/" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Permissions

- **`API_CREATOR` + `MANAGE`** in the project, and
- for each API Proxy created from the definition, `MANAGE` in the category of that API Proxy: `API_MANAGEMENT` for a REST, SOAP or other API Proxy, `AI_DEVELOPMENT` for an AI, MCP or A2A API Proxy.

The Manager screen applies the same rule.

## Notes and Warnings

- **API Proxies are deleted too**: Apinizer undeploys every API Proxy of the definition from its environments, then deletes it. You cannot keep them.
- **No undo**: The definition and the API Proxies cannot be restored.
