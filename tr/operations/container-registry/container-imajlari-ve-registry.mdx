## Apinizer Container İmajları

Apinizer imajları Docker Hub'da iki organizasyonda yayımlanır. Organizasyonu kuracağınız sürüm belirler:

| Organizasyon | Sürüm tipi | Örnek sürüm | Kullanım amacı |
|--------------|------------|-------------|----------------|
| `apinizercloud` | Major sürüm (`YYYY.MM.0`) | `2026.10.0` | Yeni özellikleri içeren ana sürüm. 4 ayda bir yayımlanır. |
| `apinizerpatch` | Patch sürümü (`YYYY.MM.N`, N ≥ 1) | `2027.01.1` | Bir major sürümün hata düzeltmelerini ve güvenlik güncellemelerini içerir. Yeni bağımlılık ve uyumsuz değişiklik içermez. |

:::info

Bu ayrım 2027.01 major sürümüyle başlar: 2027.01.1 ve sonraki patch sürümleri `apinizerpatch` organizasyonundadır. 2026 yılı sürümlerinin tamamı (patch sürümleri dahil, örn. `2026.10.4`) `apinizercloud` organizasyonundadır.

:::

Her iki organizasyonda imaj adları aynıdır:

| Bileşen | İmaj adı |
|---------|----------|
| API Manager | `<ORGANIZASYON>/apimanager` |
| Worker | `<ORGANIZASYON>/worker` |
| Cache | `<ORGANIZASYON>/cache` |
| Integration | `<ORGANIZASYON>/integration` |
| API Portal | `<ORGANIZASYON>/apiportal` |

`<ORGANIZASYON>` ifadesini sürüm tipine göre `apinizercloud` veya `apinizerpatch` ile, `<APINIZER_VERSION>` ifadesini kurduğunuz veya yükselttiğiniz sürümle değiştirin. Örnek: `apinizercloud/worker:2026.10.0`, `apinizerpatch/worker:2027.01.1`.

## Deployment Dosyalarında İmaj Alanı

Kurumsal registry kullanıldığında `image` alanı, kurumunuzun verdiği registry host ve path yapısına göre güncellenir:

```yaml
image: <REGISTRY_HOST>/<REGISTRY_PATH>/<ORGANIZASYON>/apimanager:<APINIZER_VERSION>
```

**Örnek:**

```yaml
image: repo.apinizer.com/docker-proxy/apinizercloud/apimanager:2026.10.0
```

Diğer bileşenler için yukarıdaki tabloda yer alan imaj adları aynı kalıpla kullanılır.

:::info

Tüm Kubernetes worker node'larında registry yapılandırması tutarlı olmalıdır. Yapılandırma değişikliğinden sonra imaj çekimini node üzerinde test edin.

:::
