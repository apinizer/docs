## Veritabanı Koleksiyon İsimleri

Aşağıdaki tablo, Apinizer'da kullanılan MongoDB koleksiyonlarını ve bunların içerdiği verileri gösterir:

| Sayfa Adı | Veritabanındaki Koleksiyon İsmi | Açıklama |
|---|---|---|
| [Uygulama Logları (Application Logs)](/tr/develop/izleme-analiz/uygulama-loglari) | `apinizer_log` | API Proxy'e gelen ve dönen mesajlar için akışın işletilmesi sırasında oluşan yazılımsal loglara ait kayıtlar |
| [Denetim Kayıtları (Audit Records)](/tr/admin/audit-compliance/denetim-kayitlari) | `audit_event` | Kullanıcıların sistem üzerinde yaptığı değişikliklerin kayıt edildiği koleksiyon. Gerçekleştirilen işlemler tarih, operasyon tipi, kullanıcı, nesne ID, nesne adı ve denetim objesinin tipi parametreleriyle kayıt altına alınır |
| [ACL Denetim Kayıtları (ACL Audit Records)](/tr/admin/audit-compliance/acl-denetim-kayitlari) | `history_acl` | API Proxy'ye ya da API Proxy Grup'a erişim için yetki verilen ya da yetkisi alınan tüketici kayıtlarının tutulduğu koleksiyon. İşlem tarihi, işlem tipi, sebebi, hangi kullanıcı için geçerli olduğu, hangi API Proxy/API Proxy Grup ve metot için geçerli olduğu gibi bilgiler bu koleksiyonda tutulur |
| [Alarm (Alert)](/tr/monitor/alarm) | `alert_history` | Apinizer üzerinde belirli koşullarda action kullanılarak oluşturulan alarmların işlem saati, action içerisindeki mesaj bilgileri ve hangi obje üzerinden tetiklendiği gibi bilgiler |
| [Token İstekleri (Token Requests)](/tr/develop/politikalar/token-service/genel-bakis) | `log_tokentraffic` | Token alma istekleri için gelen ve dönen mesajların ilgili kısımlarına ait kayıtlar |
| [Anomali Dedektörü (Anomaly Detector)](/tr/monitor/anomali-tespit-edici) | `anomaly_detector_result` | API trafiğinde anomali bulmak için tutulan kayıtlar |
| [Çalışma Süresi Monitörü (Uptime Monitor)](/tr/monitor/api-saglik-kontrolu) | `uptime_monitor_result` | Uptime Monitoring işlemlerinin sonuçlarına ait log kayıtları |
| [İş Akışı (Task Flow)](/tr/integrations/api-integrator-task-flow-builder/taskflow-monitor) | `taskflow_execution_log` | Integration Task Flow adımlarındaki eylemlerin işletilmesi sırasında oluşan loglara ait kayıtlar |
| [Rapor Üretici (Report Generator)](/tr/analytic/analytics-reports/rapor-uretici) | `report_configuration_result` | Rapor tanımlarının çalışması sırasında oluşan yazılımsal loglara ait kayıtlar |
| [Trace](/tr/develop/izleme-analiz/adim-adim-izleme) | `log_apiproxytraffic` | API Proxy trafiğinde Trace açık olduğunda, API trafiği ile ilgili bilgileri kaydeden koleksiyon. Bir API'nin kullanımına ilişkin temel trafik bilgilerini ve hangi proxy üzerinden işlendiğine dair detayları barındırır |
| [Trace](/tr/develop/izleme-analiz/adim-adim-izleme) | `log_apiproxytraffic_policy_execution` | API Proxy trafiğinde Trace açık olduğunda, politika uygulama süreçleri ile ilgili bilgileri içeren yapı. Politika(lar) uygulanmadan önce ve sonra ne durumda olduğuna dair bilgileri temsil eder |
| [Trace](/tr/develop/izleme-analiz/adim-adim-izleme) | `log_apiproxytraffic_routing` | API Proxy trafiğinde Trace açık olduğunda, yönlendirme, yeniden deneme ve failover gibi olayları temsil eden yapı. Bir API isteğinin hangi yönlendirmelerden geçtiğini, herhangi bir hata durumunda yeniden deneme veya failover süreçlerinin nasıl işlediği gibi bilgileri tutar |
| - | `user_token_blackList` | Kullanıcıların çoklu giriş yapmaları durumunda, her giriş işleminin ayrı bir kayıt olarak tutulduğu koleksiyon |
| [Bildirimler (Notifications)](/tr/integrations/konnektorler/notification-konnektor) | `notification_user` | Kullanıcı bildirimlerinin tutulduğu koleksiyon |
| [TCP Bağlantı Testi Geçmişi](/tr/operations/database-buyume-yonetimi/tcp-connectivity-test-history-collection-temizleme) | `tcp_connectivity_test_history` | TCP bağlantı testi sonuçlarının depolandığı koleksiyon |
| [API Manager Giriş Logları](/tr/operations/database-buyume-yonetimi/persistent-audit-event-collection-temizleme) | `persistent_audit_event` | API Manager giriş denemesi kayıtlarının depolandığı koleksiyon |
| [API Portal Giriş Logları](/tr/operations/database-buyume-yonetimi/portal-login-logs-collection-temizleme) | `portal_login_logs` | API Portal giriş denemesi kayıtlarının depolandığı koleksiyon |
| [Güvenlik Olayları (Security Events)](/tr/admin/audit-compliance/guvenlik-olaylari) | `log_apisecurityevent` | Ağ geçidinde engellenen veya hata veren isteklerin gövdesiz güvenlik metadata kaydı; başarılı istekler hiç kaydedilmez |
| [Güvenlik Olayları (Security Events)](/tr/admin/audit-compliance/guvenlik-olaylari#api-erişimi) | `log_apiaccess` | Ağ geçidine ulaşan her isteğin (başarılılar dâhil) gövdesiz metadata kaydı. Yalnızca API Erişimi yerel depolaması açıkken yazılır; trafik hacmiyle birlikte büyür |
| [Kota Kullanımı ve Uyarılar](/tr/admin/identity-management/kota-kullanimi-ve-uyarilar) | `quota_alert_notification_log` | Bir kota eşiğine ulaşıldığında gönderilen kota alarm bildirimleri; hangi alarm tanımının tetiklendiği ve gönderim zamanı |
| [Kota Kullanımı ve Uyarılar](/tr/admin/identity-management/kota-kullanimi-ve-uyarilar) | `quota_usage_window_history` | Her kota penceresi kapandıktan sonra arşivlenen kota kullanım pencereleri |
| - | `environment_metric` | Ortam (Namespace) metrikleri |
| - | `llm_health_history` | LLM sağlayıcılarına karşı yapılan periyodik sağlık kontrollerinin sonuçları (durum ve gecikme bilgisi) |
| - | `mcp_health_history` | MCP sunucularına karşı yapılan periyodik sağlık kontrollerinin sonuçları (durum ve gecikme bilgisi) |
| - | `ai_trace` | Trace moduna göre yakalanan AI Gateway trace kayıtları. Kendi süre sonları da vardır (24 saat, 7 gün veya 30 gün) |
| - | `ai_a2a_task` | Agent-to-Agent (A2A) görev kayıtları. Tamamlanmış görevlerin kendi süre sonu da vardır |
| - | `ai_token_usage_daily` | Faturalandırma ve raporlama için kullanılan günlük toplanmış AI token kullanımı |
| [Kimlik Senkronizasyon Geçmişi](/tr/admin/identity-management/identity-providers/credential-sync#senkronizasyon-koşu-geçmişi) | `identity_sync_run_history`, `identity_sync_run_issue` | Kimlik sağlayıcı senkronizasyon koşularının ve madde bazlı sorun satırlarının kalıcı kaydı |
| - | `bulk_limit_assignment_run`, `bulk_limit_assignment_issue` | Toplu limit atama koşularının ve tüketici başına sorun satırlarının kalıcı kaydı |
| - | `lifecycle_purge_run`, `lifecycle_purge_issue` | Temizleme ve silme koşularının ve madde bazlı sorun satırlarının kalıcı kaydı |
| - | `lifecycle_evidence` | Tüketiciler, tüketici kurumları ve portal uygulamaları için belirli yaşam döngüsü sınırlarının daha önce aşılıp aşılmadığını (etkinleştirilme, ortama yüklenme, dışa aktarılma vb.) kaydeden koleksiyon. Her kayıt için tek ve çok küçük bir belge tutulur; her giriş yalnızca bir kez yazılır ve sonrasında güncellenmez |

:::warning

Bazı koleksiyonlar kritik veriler içerir. Özellikle `audit_event`, `history_acl`, `persistent_audit_event` ve `portal_login_logs` koleksiyonlarının temizlenmesi önerilmez. `history_acl` otomatik olarak hiç temizlenemez. `audit_event` (Denetim Kayıtları), `persistent_audit_event` (Giriş Kayıtları) ve `portal_login_logs` (Portal Giriş Logları) için [Uygulama Logu Temizleme Görevleri](/tr/admin/audit-compliance/uygulama-logu-temizleme-gorevleri) üzerinden otomatik silme kullanılabilir, ancak varsayılan olarak kapalıdır. Bu koleksiyonlara müdahale etmeden önce yedek alınması ve dikkatli değerlendirme yapılması gerekir.

:::

:::danger

`lifecycle_evidence` koleksiyonu **temizlenmemeli, silinmemelidir**. Bu koleksiyon için temizleme script'i ve otomatik silme yoktur; zamana dayalı temizlik kapsamına bilinçli olarak alınmamıştır. Kayıtları, bir kaydın silinip silinemeyeceğine karar verilirken kullanılır ve eksik bir giriş "kanıt yok" olarak yorumlanır. Bu kayıtların silinmesi anlamlı bir yer kazandırmaz; yalnızca silme kararlarının eksik bilgiyle verilmesine yol açar.

:::
