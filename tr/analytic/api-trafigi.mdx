## Liste Görünümü

Ekrana **Administration > Analytic > Trafik** veya proje menüsünden **Analytic > Trafik** ile ulaşabilirsiniz. Üst satırda ortam, proje (yalnızca Administration), API Proxy ve hızlı alanlar (varsayılan olarak sonuç tipi, HTTP durum kodu, uç nokta, istemci IP, kullanıcı adı veya anahtar ve Correlation Id); sağda zaman aralığı, yenileme modu ve Excel dışa aktarma yer alır.

| Kolon | Açıklama |
|-------|----------|
| **Status · Time** | HTTP durum kodu (renkli rozet) ve istek zaman damgası |
| **Method · Request** | HTTP metodu, proxy/metot adı; alt satırda API tipi (REST, SOAP, …) ve istek sunucusu |
| **Client** | İstemci IP adresi ve kimlik özeti (API Client, `anonymous` veya legacy kullanıcı adı/anahtar) |
| **Routing** | Yönlendirme hedefi; `blocked at gateway` veya `direct` rozeti |
| **Latency [request · routing · response]** | Toplam süre (ms), faz dağılımı ve çubuk grafik |
| **Size** | İstek ve yanıt gövde boyutları, bayt cinsinden (↑ / ↓) |
| **Actions** | Satır menüsü — detaylı görünüm, JSON, indirme, hızlı test |

## Arama ve Yenileme

Trafik ekranındaki filtreler taslaktır. Liste yalnızca **Ara** düğmesine bastığınızda değişir.

- Ekran açıldığında bir arama çalıştırır.
- Uygulanmamış değişiklikler varken **Ara** düğmesi bu değişikliklerin sayısını gösterir. Aramak için bir filtre alanında Enter'a da basabilirsiniz.
- **Otomatik yenileme** varsayılan olarak **Manuel** değerindedir. Liste yalnızca 1 dakika, 3 dakika veya 5 dakika seçtiğinizde kendiliğinden yenilenir.
- **Şimdi yenile**, uygulanmış filtrelerle yeniden arar.

Bu kuralı izleyen diğer ekranlar için [Rapor Ekranlarında Arama Kuralı](/tr/analytic/analytics-reports/raporlar#rapor-ekranlarında-arama-kuralı) bölümüne bakabilirsiniz.

## Yönlendirme Adresi (Routing Address)

Bu alan ilgili API Proxy'nin yönlendirildiği adres bilgisini tutar. İstek backend'e gittiyse bu satırda backend adresi vurgulu renkte görünür.

İstek, ağ geçidi tarafından backend'e hiç gidilmeden yanıtlandıysa (örneğin bir MCP `initialize`/`tools/list`/`ping` çağrısı, bir keşif belgesi, bir mock yanıt veya ağ geçidinde engellenen bir istek) bu satırda artık boşluk değil, istemcinin çağırdığı ağ geçidi adresi soluk renkte gösterilir; bir MCP API Proxy'de bu, o proxy'nin MCP uç nokta adresidir (örn. `https://api.apinizer.com/apigateway/aigw/petstore-mcp`). Üzerine gelindiğinde "Bu adreste, backend çağrısı yapılmadan ağ geçidi tarafından yanıtlandı." bilgisi görüntülenir. Bu adres, log kaydındaki mevcut istek alanlarından (şema, sunucu adı, port, istek yolu) türetilir; yeni bir log alanı gerektirmez. **— (yönlendirilmedi)** ifadesi yalnızca bu bilgilerin yeniden kurulamayacağı kadar eksik olduğu eski kayıtlarda görünür.

Backend olarak Apinizer'ı kullanan servisler `apinizer://` ön eki ile gösterilir, tam olarak `apinizer://<BİLEŞEN_ADI>/<METOT_ADI>` formatında yazılır.

:::info

Routing adresi kapatılarak backend'e gitmesi engellenen proxy'ler için de bu gösterim geçerlidir.

:::

### Yönlendirme Adresi Değerleri

| Routing Adresi | Koşul |
|----------------|-------|
| `apinizer://mirror.routing/<METOT_ADI>` | API Proxy tipi Swagger 2.x, OpenAPI/Swagger 3.0.x, WSDL, Reverse Proxy veya No-Spec API ve **Routing seçeneği kapatılmış ve Mirror seçeneği açık** |
| `apinizer://specresponse.routing/<METOT_ADI>` | API Proxy tipi Swagger 2.x, OpenAPI/Swagger 3.0.x, WSDL, Reverse Proxy veya No-Spec API ve **Routing seçeneği kapatılmış ve Mirror seçeneği kapalı** |
| `apinizer://db2api.apicreator/<METOT_ADI>` | API Proxy tipi DB2API |
| `apinizer://script2api.apicreator/<METOT_ADI>` | API Proxy tipi Script2API |
| `apinizer://mockapi.apicreator/<METOT_ADI>` | API Proxy tipi Mock API |
| `apinizer://connector/<METOT_ADI>` | API Proxy tipi Connector |
| `apinizer://maintenance` | API Proxy bakım modunda |
| `apinizer://cache/<METOT_ADI>` | Herhangi bir API Proxy tipinde ve **Cache'leme açık** |
| `http://<BACKEND_ADRESİ>/<METOT_ADI>` <br/> `https://<BACKEND_ADRESİ>/<METOT_ADI>` | API Proxy tipi Swagger 2.x, OpenAPI/Swagger 3.0.x, WSDL, Reverse Proxy, No-Spec API veya KPS ve **Routing seçeneği açık** |
| `apinizer://spec` | API Proxy tipi Swagger 2.x, OpenAPI/Swagger 3.0.x, WSDL, Reverse Proxy, No-Spec API ve spec adresine erişim |
| *(Boş)* | İsteğin çeşitli sebeplerle backend adresine gidememesi — ekranda bu durumda yukarıda anlatılan ağ geçidi adresi gösterilir |

:::warning

Websocket ve gRPC istekleri Apinizer'a gelen ve Apinizer'dan çıkan veriler şeklinde tutulmakta olduğundan bu tip API Proxylerde sadece 2 bölge vardır.

:::

### Yönlendirme Rozetleri (Routing Badges)

Yönlendirme Adresi'nin yanında, isteğin backend'e nasıl ulaştığını (veya neden ulaşamadığını) özetleyen bir veya birden fazla rozet gösterilir. Rozet bilgisi log kaydındaki mevcut alanlardan türetilir, yeni bir alan gerektirmez. Bir satırda en fazla bir adres rozeti bulunur, isteğe bağlı bir hata rozetiyle birlikte gösterilebilir:

| Rozet | Anlamı |
|---|---|
| **önbellek isabeti** | Yanıt önbellekten döndü (AI semantik önbelleği dahil); tasarım gereği bu satırlar için backend'e hiç gidilmez |
| **doğrudan** | İstek tek seferde backend'e ulaştı; yeniden deneme veya yük devretme yaşanmadı |
| **yeniden deneme ×n** | Yönlendirici, alışveriş tamamlanmadan önce backend'i belirtilen sayıda yeniden denedi |
| **yük devretme ×n** | Yönlendirici, belirtilen sayıda alternatif bir backend'e yük devretti |
| **araç çağrısı** | MCP `tools/call` satırlarında **doğrudan** rozetinin yerini alır; gösterilen adres aracın backend'idir — Araçları Aç modunda ağ geçidi üzerinden ulaşılan kaynak API Proxy yolu, Passthrough modunda ise MCP sunucusunun host:port'udur |
| **backend hatası** | Backend'e ulaşıldı ama alışveriş yine de başarısız oldu; hata tipini görmek için rozetin üzerine gelin |
| **ağ geçidinde engellendi** | İstek herhangi bir backend'e ulaşmadan bir politika tarafından reddedildi |
| **ağ geçidinde reddedildi** | Bir MCP `tools/call` isteği herhangi bir backend'e ulaşmadan reddedildi (bilinmeyen araç, yetersiz scope, argüman kuralı veya çıktı filtresi nedeniyle) |
| **ağ geçidi hatası** | Ağ geçidi bir backend'e ulaşmadan isteği tamamlayamadı — örneğin bir araç backend proxy'sinin erişilemez olması, başarısız bir araç yürütmesi veya oturum limiti nedeniyle |
| **ağ geçidinde yanıtlandı** | İstek herhangi bir backend çağrısı olmadan başarıyla sonuçlandı; örneğin bir MCP `initialize`/`tools/list`/`ping`, bir keşif belgesi, bir mock yanıt veya bir spec isteği |

:::info

Bu sınıflandırma devreye girmeden önce yazılmış log kayıtları HTTP durum koduna göre geriye dönük eşlenir: **4xx/5xx** durumu **ağ geçidinde engellendi**, diğer tüm durumlar **ağ geçidinde yanıtlandı** olarak gösterilir.

:::

## API Tipi

Bu ekran projedeki tüm API Proxy'lerin trafiğini listelediği için farklı proxy tiplerine ait kayıtlar yan yana görünür. **API Tipi** kolonu her kaydın hangi tipe ait olduğunu gösterir; aynı değerler hızlı alan veya Gelişmiş koşul olarak da kullanılabilir.

**Değerler:** API görünümünde: `REST`, `SOAP`, `GRPC`, `WEBSOCKET`. AI görünümünde: `AI`, `MCP`, `A2A`.

Kolon sıralanabilir; aynı tipe ait kayıtlar bir arada gruplanabilir.

:::info

API Tipi kolonu ve filtresi yalnızca bu ekranda gösterilir. Tek bir API Proxy'nin **Trafik** sekmesinde tip zaten sabittir; aynı değeri her satırda tekrar etmek yalnızca gürültü olur.

:::

## API ve AI Görünümleri

Bu ekranın iki görünümü vardır. Lisansınız hem API Gateway hem AI Gateway'i kapsıyorsa, üst satırın başındaki **API | AI** anahtarı görünümü seçer; yalnızca biri lisanslıysa anahtar gizlenir ve o görünüm açılır.

- **API:** REST, SOAP, gRPC ve WebSocket trafiğini listeler.
- **AI:** AI, MCP ve A2A trafiğini, AI'a özgü kolonları olan bir tabloda listeler.

Yalnızca seçili görünüm yüklenir. Filtrelerdeki tip seçenekleri seçili görünümü izler.

:::warning

**WebSocket** ve **gRPC** kayıtlarında İstek Pipeline, Backend ve Yanıt Pipeline süre kolonları `—` olarak gösterilir. Bu protokoller Apinizer'a gelen ve Apinizer'dan çıkan veri şeklinde loglandığı için üç aşamalı pipeline süresi ölçülmez.

:::

## Filtreleme

Tüm filtreler tek ekrandadır.

- Arama satırında proxy listesi ve hızlı alanlar bulunur. API görünümünde liste **API Proxy**'dir (REST, SOAP, gRPC ve WebSocket). AI görünümünde listeler **LLM Gateway**, **MCP Gateway** ve **A2A Gateway**'dir; her biri yalnız kendi tipini listeler. Yönetim modunda önce **Proje** gelir ve proje değişince kapsam dışında kalan proxy'ler kaldırılır. Proxy listesi yalnızca **Analytic > Trafik** ekranındadır; bir API Proxy'nin Trafik sekmesi zaten o proxy ile sınırlıdır.
- **Diğer filtreler** çubuğa başka bir alan ekler. Alanlar gruplanmıştır (örneğin İstek, İstemci, Yönlendirme, WebSocket ve gRPC) ve listede bir arama kutusu vardır. **Diğer alanlar** loglanan diğer tüm alanları listeler. Değeri olan alan çubukta kalır.
- **Gelişmiş** düğmesi, arama satırının altında bir koşul ağacı açar. Ağaçta koşul varsa düğmenin üstünde bir rozet görünür.
- Hızlı alanlar ve Gelişmiş koşullar birlikte çalışır. Bir kaydın ikisine de uyması gerekir (AND).
- **Ara** düğmesine veya Enter'a basana kadar arama yapılmaz. **Ara** düğmesi, henüz uygulanmamış değişikliklerin sayısını rozet olarak gösterir.
- **Filtreleri temizle**, hızlı alanları boşaltır; proxy seçimini ve Gelişmiş koşulları kaldırır. Sonra yeniden arar. Ortam, proje ve tarih aralığı değişmez.

### Hızlı Filtreler

Hızlı filtreler, en çok kullanılan koşullara kısayoldur. Bir alana değer yazın. **Ara** düğmesine bastığınızda değer koşula dönüşür.

Çubukta kalacak alanları seçmek için **Hızlı filtreleri düzenle** düğmesine tıklayın. Seçiminiz profilinizde, API ve AI görünümü için ayrı ayrı saklanır. İstediğiniz sayıda alan sabitleyebilirsiniz. Sabitlenmeyen alanlara **Diğer filtreler** ile ulaşırsınız. API görünümünün ilk kullanım kümesi: Sonuç Tipi, HTTP Durum Kodu, Uç Nokta, İstemci IP, Kullanıcı Adı veya Anahtar ve Korelasyon Id.

Her alan, tipine uyan operatör listesini sunar:

- Metin: şuna eşit olsun, şundan farklı olsun, içersin, içermesin, şununla başlasın, şununla bitsin, listede olsun, listede olmasın, var olsun, var olmasın, var ve boş olsun, var ve boş olmasın.
- Tanımlayıcı (örneğin Korelasyon Id): şuna eşit olsun, şundan farklı olsun, listede olsun, listede olmasın, var olsun, var olmasın.
- Sayı: karşılaştırma operatörleri ve "şunların arasında".
- Mesaj gövdesi: kelimesini içersin, içersin, içermesin, şuna eşit olsun, şununla başlasın, şununla bitsin.

Çubuk, Gelişmiş koşullar ve Filtre sayfası aynı operatör listelerini gösterir. "Listede olsun" operatöründe değerleri virgülle ayırarak yazın.

### Tarih Aralığı

Üstteki tarih seçicide **Hızlı Seçim** ve **Tarih Aralığı** sekmeleri bulunur.

- **Tarih Aralığı** sekmesinde aralığın başlangıcını ve bitişini yazabilirsiniz. `yyyy-MM-dd HH:mm` veya `yyyy-MM-dd HH:mm:ss` biçimini kullanın. Saatler tarayıcınızın saat dilimindedir.
- **Uygula** düğmesine tıklayın. Metin geçerli bir tarih değilse ekran hata gösterir ve uygulanmış aralığı korur. Başlangıç, bitişten sonra olamaz.

### Kayıtlı Filtreler

Kayıtlı bir [Filtre](/tr/analytic/query-editor/filtreler-filters)'yi ekrana kopyalamak için **Filtre seç** düğmesine tıklayın. Koşullar çubuğun alanlarına gider. Yalnız OR ve NOT grupları **Gelişmiş**'e gider. Filtrenin zaman aralığı ve Yönetim modunda projeleri de gelir. Çalıştırmak için **Ara** düğmesine basın. Kopya Filtreye bağlı değildir. Filtrede sonradan yapılan değişiklikler ekranı etkilemez.

Kayıtlı Filtre, bu görünümde listelenmeyen API Proxy'leri içeriyorsa uygulanmaz. Örneğin API görünümünde bir AI Proxy Filtresi. Diğer görünümü açın veya başka bir Filtre seçin.

Ekrandaki koşulları Filtre olarak kaydetmek için **Kaydet** düğmesine tıklayın. Henüz aramadığınız koşullar da kaydedilir. Ortam ve sıralama kaydedilmez. Daha önce bir Filtre açtıysanız pencere, onu güncellemenizi ya da yeni bir Filtre kaydetmenizi sağlar. Zaman aralığını kaydetmek için **Zaman aralığını filtreyle kaydet** kutusunu işaretleyin. Yalnız "Son 7 gün" gibi göreli bir aralık kaydedilir.

Düğmelerin yanındaki **⋯** menüsünde şu öğeler vardır:

- **Filtre seç…**
- **Filtreyi kaydet** ve **Yeni filtre olarak kaydet…**
- **Filtreler sayfasında aç**: Açtığınız Filtreyi Filtre sayfasında açar.
- **cURL olarak kopyala**: Aramayı trafik API'sine bir istek olarak kopyalar. bash, Windows CMD veya PowerShell seçin.

**Filtre seç** ve **Kaydet** yalnızca **Analytic > Trafik** ekranında bulunur, bir API Proxy'nin Trafik sekmesinde bulunmaz. Yalnızca görüntüleme yetkisi olan kullanıcılar bu düğmeleri görmez. **Kaydet** için ayrıca analitikleri yönetme yetkisi gerekir.

Arama hiçbir kayıt bulmazsa tablo yalnız "Kayıt bulunamadı" gösterir.

### Gelişmiş Arama

İç içe filtreler ve karmaşık sorgular için Gelişmiş koşul ağacını kullanın. Koşulları **AND/OR/NOT** operatörleriyle birleştirebilirsiniz.

**Kriterler:**

- **İstek:**
  - **API Proxy Adı**: Birden fazla API Proxy seçimi
  - **API Proxy Grubu**: Bir API Proxy Grubundaki API Proxy'lerin kayıtları. Bir grubu adıyla seçin. Bir grupta olmayan proxy'lerin istekleri için "Doğrudan (grupsuz)" seçeneğini seçin.
  - **API Proxy Tipi**: Proxy tipine göre filtreleme; seçenekler seçili görünümü izler (bkz. [API Tipi](#api-tipi))
  - **HTTP Metodu**: GET, POST, PUT, DELETE gibi HTTP metotları.
  - **WebSocket Mesaj Tipi**: OPEN, CLOSE, TEXT veya BINARY.
  - **gRPC Çağrı Tipi**: UNARY, CLIENT_STREAMING, SERVER_STREAMING, BIDI_STREAMING, UNKNOWN. Çağrı tipi kayıt anında belirlenemeyen gRPC istekleri **GRPC** değeriyle kaydedilir ve aynı listeden filtrelenir.
  - **Mesaj Yönü**, **gRPC Servisi** ve **gRPC Metodu**: Bir WebSocket veya gRPC mesajının yönü ile bir gRPC çağrısının servisi ve metodu.
  - **HTTP Durum Kodu**: 200, 404, 500 gibi HTTP durum kodları
  - **Sonuç Tipi**: Başarılı, Hatalı, Engellenmiş
  - **Hata Tipi**
  - **Uç Nokta**: API Proxy'nin endpoint'i veya metodu
  - **Korelasyon Id**: Apinizer Correlation ID. Tam bir değer veya değer listesi arayabilirsiniz.
- **İstemci:**
  - **Kullanıcı Adı veya Anahtar**: Doğrulama için kullanılan API Client (legacy kayıtlarda kullanıcı adı/anahtar)
  - **İstemci IP**
- **Yönlendirme:**
  - **Yönlendirme Adresi**: İsteğin gönderildiği adres
  - **Yönlendirme Yeniden Deneme Sayısı** ve **Yönlendirme Failover Sayısı**: Yönlendiricinin backend'i kaç kez yeniden denediği veya başka bir backend'e kaç kez geçtiği
  - **Backend Durum Kodu**: Backend'in döndürdüğü durum kodu
  - **Yönlendirme Hata Nedeni**: Listeden bir hata nedeni seçin
  - **Önbellek**: İsabet veya ıskalama
  - **Canary İsteği**: Evet veya Hayır
  - **Canary Durumu**: Yok, Yapılandırılmamış, Canary'ye Yönlendirildi, Seçilmedi (Rastgele), Devre Kesici Açık (Yedek), Bekleme Süresinde (Yedek) veya Hata Eşiği Aşıldı (Yedek)
  - **Yansıtma Trafiği**: Yalnız yansıtma veya Yansıtma hariç
- **Süre ve boyut:** **İşlem Süresi** ve **Mesaj Uzunluğu**
- **Mesaj:** Dört mesaj gövdesinden birinde **Anahtar Kelime**: İstemciden Alınan İsteğin Gövdesi, Backend API'ye Gönderilen İsteğin Gövdesi, Backend API'den Alınan Yanıtın Gövdesi ve İstemciye Gönderilen Yanıtın Gövdesi

Her kriter, tipine uyan operatörleri sunar. Listeler [Hızlı Filtreler](#hızlı-filtreler) bölümündekilerle aynıdır.

Mesaj gövdesi kriterlerinde bir operatör daha vardır: **kelimesini içersin**. Değeri tam kelimeler olarak eşleştirir, bir kelimenin parçası olarak eşleştirmez. Birden fazla kelime girerseniz kelimeler aynı sırayla yan yana geçmelidir. Örneğin `card` değeri "my card" ile eşleşir, "discard" ile eşleşmez.

:::warning

Mesaj gövdesinde arama çok veri okur. Uzun bir tarih aralığında arama yavaş olabilir. Ekran bu uyarıyı gövde değerinin altında gösterir. Önce tarih aralığını daraltın.

:::


**Diğer alanlar (More fields)**

Gelişmiş aramada **More fields** ölçütü bulunur. Kendi ölçütü olmayan, loglanan her alanı aramak için kullanın.

1. Gruplanmış listeden bir alan seçin: Caller, Request, Backend, AI veya Diagnostics.
2. Bir operatör seçin.
3. Bir değer girin.

- Tüketiciler, API istemcileri, organizasyonlar, API ürünleri ve LLM sağlayıcıları ada göre seçilir.
- Süreler milisaniye olarak girilir. Ölçülmemiş bir routing aşaması süre koşuluyla asla eşleşmez.
- Alanının indeks uzunluğundan uzun bir değer aranamaz (uzunluk girişin altında görünür). Bu alanlar "değil" ve "yok" operatörünü sunmaz.
- AI Trafik araması AI alanlarını listeler. API Trafik araması mirror alanlarını listeler.

### Sorgu Tipleri

Filtreleme yapılan alanlara 2 tip sorgu uygulanmaktadır:


  <Accordion title="Term Query">
    Aranan değer (keyword) ile loglanan verinin **tam olarak eşleştiği** loglar döndürülür.
    
    **Bu sorgunun uygulandığı alanlar:**
    - API Proxy
    - İşlem Sonuç Tipi (Result Type)
    - HTTP Durum Kodu (HTTP Status Code)
    - HTTP Metot (HTTP Method)
    - API Client (legacy kayıtlarda Username or Key)
    - Correlation ID
  </Accordion>

  <Accordion title="Match Query">
    Tüm metin üzerinde arama yapma sorgusudur. Aranan değer, arama yapılmadan önce **analiz edilir**.
    
    **Analiz Süreci:**
    1. Metin dilbilgisi kuralları üzerinden parçalara ayırılır (numara, noktalama işaretleri, vb.)
    2. Parçalar 'Lower Case Token Filter' aşamasından geçerek küçük harflere dönüştürülür
    3. Örnek: `'The 2 QUICK Brown-Foxes jumped over the lazy dog's bone.'` → `[ the, 2, quick, brown, foxes, jumped, over, the, lazy, dog's, bone ]`
    
    **Eşleşme Mantığı:**
    - Parçaların arasında **OR** operatörü vardır
    - Parçalar log dokümanındaki alanda kaç tanesi var, ne sıklıkla kullanılmış gibi kriterler baz alınarak **skor değeri** elde edilir
    - Bu skor değerine göre ilgili dokümanlar döndürülür
    
    **Bu sorgunun uygulandığı alanlar:**
    - Metot/Endpoint Adı (Method/Endpoint Name)
    - İstek Adresi (Request Address)
    - Gönderilen Adres (Routing Address)
    - İstemciden Alınan İsteğin Gövdesi (From Client Body)
    - Backend API'ye Gönderilen İsteğin Gövdesi (To Backend API Body)
    - Backend API'den Alınan Yanıtın Gövdesi (From Backend API Body)
    - İstemciye Gönderilen Yanıtın Gövdesi (To Client Body)
  </Accordion>

  <Accordion title="Wildcard Query">
    Bir wildcard karakter kalıbıyla eşleşen terimleri içeren dokümanlar döndürülür.
    
    **Kullanım:**
    - Arama sonuçlarınızı genişletmek için kelimenin önüne ya da sonuna `*` karakteri eklenmelidir
    - Örnek: `user*` → user ile başlayan tüm kelimeler
    - Örnek: `*admin` → admin ile biten tüm kelimeler
    
    **Bu sorgunun uygulandığı alanlar:**
    - İstek Adresi (Request Address)
    - Gönderilen Adres (Routing Address)
  </Accordion>

  ### Gövde Alanlarında Arama (Body Search)
  <Accordion title="Gövde Alanlarında Arama (Body Search)">
    **From Client Body**, **To Backend API Body**, **From Backend API Body** ve **To Client Body** alanlarında arama yapılırken aşağıdaki kurallar geçerlidir:

    Dört alan aynı şekilde davranır; her biri yalnız kendi mesaj bölgesinde arar (1. istemciden gelen istek, 2. backend API'ye gönderilen istek, 3. backend API'den dönen yanıt, 4. istemciye dönen yanıt).

    **Tek kelime arama:**
    - `doğum` gibi boşluk içermeyen ifadeler **büyük/küçük harf duyarsız** alt-dize araması olarak çalışır — ilgili kelimenin geçtiği tüm kayıtlar döndürülür.
    - `ABC-123`, `user@example.com` veya `"orderId":5` gibi noktalama içeren değerler ayrıca parçalarının öbeği (phrase) olarak eşleştirilir; log metni indekslenirken kelimelere bölünse de bulunur.

    **Boşluklu ifade arama:**
    - `doğum tarihi` gibi boşluk içeren ifadeler, kelimelerin **yan yana** geçtiği kayıtlar için arama yapar — phrase arama davranışı gösterir.
    - Yıldız karakteri eklenerek de kullanılabilir: `*doğum tarihi*`

    **Açık joker kalıpları:**
    - İfade `*` veya `?` içeriyorsa olduğu gibi joker kalıbı olarak kullanılır (büyük/küçük harf duyarsız): `sip*123`.

    :::tip

En doğru sonuçlar için aranan metnin tam yazımını kullanın. Büyük/küçük harf farkı sonucu etkilemez.

:::

    :::note Elasticsearch sürümü

Gövde aramaları desteklenen her Elasticsearch sürümünde büyük/küçük harf farkı gözetmez. **API Client / Kullanıcı Adı veya Anahtar**, başlık değeri ve parametre değeri aramaları Elasticsearch 7.10 ve üzerinde harf farkı gözetmez; Elasticsearch 7.0–7.9'da yalnız saklanan değerin küçük harfli haliyle eşleşir, çünkü bu sürümler harf duyarsızlık seçeneğini desteklemez ve Apinizer aramayı bu seçenek olmadan otomatik olarak yeniler.

:::
  </Accordion>


## Detaylı Görünüm (Detailed View)

Log kaydın sağ tarafında yer alan **Detaylı Görünüm (Detailed View)** tuşuna basıldığında mesajın log bilgileri, istek ve yanıt hattındaki bölümlere göre gruplanarak gelir.

:::info

Detaylı Görünüm, sağdan açılan bir panelde (drawer) görüntülenir. Her API tipi aynı paneli kullanır: REST, SOAP, WebSocket, gRPC, MCP ve LLM Gateway kayıtları aynı biçimde okunur. Panelin son sekmesi, kayıt için AI kullanım verisi varsa **LLM İçgörüleri** başlığını, yoksa kaydın içeriğine göre **MCP Detayları** veya **A2A Detayları** başlığını alır; bunların hiçbiri geçerli değilse sekme gösterilmez.

WebSocket ve gRPC kayıtlarında ilk iki gövde sekmesi **Gelen Mesaj** ve **Giden Mesaj** adını alır. Bu protokoller istek/yanıt çifti kaydetmediği için arka uç yanıt sekmeleri gösterilmez.

:::

:::note
Elasticsearch zamanında yanıt vermezse pencere artık boş açılmaz: "Elasticsearch zamanında yanıt vermediği için log detayı yüklenemedi. Lütfen kısa bir süre sonra tekrar deneyin." mesajı gösterilir. Elasticsearch bir hata döndürürse ilgili HTTP durum koduyla birlikte "Elasticsearch hata döndürdüğü için (HTTP ...) log detayı yüklenemedi. Lütfen Elasticsearch sunucusunu kontrol edip tekrar deneyin." mesajı gösterilir. Kayıt gerçekten silinmiş ya da hiç yazılmamışsa davranış değişmez: pencere eskisi gibi boş içerikle açılır.
:::

## Hızlı Test

Kaydın sağ tarafında yer alan **Hızlı Test** tuşuna basıldığında kayda gelen orijinal mesaj içeriği [Test Konsola](/tr/develop/test-debug-araclari/test-console) yerleştirilmiş şekilde Test Konsol ekranı açılır.

Bu özellik, ilgili kaydın tekrar test edilebilmesi için kolaylık sağlar.

:::warning

**Hızlı Test** tuşunun görünmesi için genel ayarlarda **etkinleştirilmelidir**.

:::

:::note
Kaydın orijinal mesaj içeriği Elasticsearch'ten yeniden yüklenirken Elasticsearch zamanında yanıt vermez ya da hata dönerse, Test Console yine açılır ama açıklayıcı bir hata mesajıyla — içerik sessizce boş gelmez. Bu, Detaylı Görünüm'deki Elasticsearch zaman aşımı davranışıyla aynıdır.
:::

:::warning Gövde log limitine göre kırpılmış olabilir

Hızlı Test'in doldurduğu istek gövdesi, isteğin kendisinden değil **trafik kaydından** gelir. Kayıt yazılırken gövde kırpılmış olabilir:

- API Proxy'nin trafik log ayarlarında ilgili bölge için **gövde boyut limiti** açıksa gövde o karakter sayısında kesilir.
- Kurulum genelindeki mutlak gövde tavanı aşılmışsa gövde yine kesilir.
- AI tipli proxy'lerde konuşmanın yalnız **son N mesajı** loglanır (genel ayarlardaki mesaj limiti); daha eski mesajlar kayıttan çıkarılır.

Gövde eksik görünüyorsa Hızlı Test penceresinin üstünde bir uyarı görünür ve istek gönderilmeden önce onay istenir; çünkü gönderilecek olan, orijinal çağrının birebir aynısı olmayabilir ve sonuç farklı çıkabilir. Aynı uyarı, istemcinin kendisi eksik gövde gönderdiğinde de görünür (örneğin API'nin hata döndürdüğü bozuk bir istek); kaydın kendisi bu iki durumu birbirinden ayıramaz. Sonraki isteklerin tam kaydedilmesini istiyorsanız ilgili trafik log ayarındaki boyut limitini gözden geçirin.
