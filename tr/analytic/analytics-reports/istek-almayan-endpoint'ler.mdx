Bir API Proxy birden fazla ortama yüklenebildiği için metrikleri de yüklendiği ortama göre değerlendirmek gerekir. Bu sebeple tüm analitik ekranlarında öncelikle ortam bilgisi seçilerek metrikler filtrelenir.

:::

## Metrikler Sayfası

Bu rapor **Metrikler** sayfasının **Endpoints** sekmesinde **Endpoints with No Requests** alt-raporu olarak yer alır (dokümantasyonda **İstek Almayan Endpoint'ler**). Ekrana **Administration > Reports > Metrics** veya proje menüsünden **Analytic > Reports > Metrics** ile ulaşabilirsiniz; **Endpoints** sekmesinde **Endpoints with No Requests** düğmesini seçin.

Üst satırdaki ortam, proje (yalnızca Administration) ve tarih aralığı filtreleri tüm alt-raporlarla paylaşılır. Rapora özel filtreler alt-rapor satırındadır; **Search** ile sorgu çalıştırılır.

## Filtreler

Belirli kriterlere göre istek almayan veya az istek alan endpoint'leri tespit edebilirsiniz:

<Steps>
  <Step title="Ortam Seçimi">
    Raporu çalıştırmak için öncelikle bir ortam seçmeniz gerekmektedir. Ortam seçimi zorunludur ve metrikler seçilen ortama göre filtrelenir.

    :::info

Bir API Proxy birden fazla ortama yüklenebildiği için metrikleri de yüklendiği ortama göre değerlendirmek gerekir.

:::
  </Step>

  <Step title="Proje Seçimi (Yönetici)">
    Yönetici kullanıcılar için birden fazla proje seçebilme imkanı sunulmaktadır. Proje seçimi yapıldığında, seçilen projelerdeki API Proxy'ler otomatik olarak yüklenir.

    :::note

Bu filtre sadece yönetici kullanıcılar için görünür.

:::
  </Step>

  <Step title="Proxy">
    Analiz edilecek API Proxy'leri çoklu seçimle sınırlayabilirsiniz. Boş bırakılırsa tüm proxy'ler dahil edilir.
  </Step>

  <Step title="Deployment Status">
    API Proxy dağıtım durumuna göre filtreleyebilirsiniz:

    - **ALL**: Tüm durumlar
    - **Deployed**: Yüklü (aktif) proxy'ler
    - **Undeployed**: Yüklenmemiş proxy'ler
  </Step>

  <Step title="Min. Request Count">
    Seçilen tarih aralığında **Toplam** istek sayısının alt sınırı (dahil). Örneğin `0` ile hiç istek almayan endpoint'ler de kapsama girer.
  </Step>

  <Step title="Max. Request Count">
    Seçilen tarih aralığında **Toplam** istek sayısının üst sınırı (dahil). Min ve Max birlikte düşük trafikli endpoint aralığını tanımlar (ör. 0–100).
  </Step>

  <Step title="Search">
    Filtreleri uygulayıp tabloyu yeniden yüklemek için **Search** düğmesine basın. Paylaşılan filtre satırındaki **Excel Export** aktif sonuç listesini indirir.
  </Step>
</Steps>

## Rapor Tablosu

Rapor sonuçları aşağıdaki kolonlarda gösterilir:

| Alan | Açıklama |
|------|----------|
| **Project** | Endpoint'in ait olduğu proje (yalnızca Administration) |
| **API Proxy** | Endpoint'in bağlı olduğu API Proxy adı |
| **Method/Endpoint** | HTTP metodu ve uç nokta yolu |
| **Successful** | Başarılı istek sayısı |
| **Blocked** | Bloklanmış istek sayısı |
| **Error** | Hatalı istek sayısı |
| **Total** | Toplam istek sayısı (Successful + Blocked + Error) |

:::note

Filtrelere uyan tüm endpoint'ler rapora dahil edilir. Tablodaki sayfalama yalnızca sonuçları ekranda gruplar; rapora dahil edilen kayıt sayısını sınırlamaz.

:::

:::note

Elasticsearch entegrasyonu aktif olmayan ortamlar için rapor çalıştırılamaz. Bu durumda ekranda uyarı mesajı gösterilir.

:::
