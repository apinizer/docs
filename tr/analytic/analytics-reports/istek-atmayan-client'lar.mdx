## Metrikler Sayfası

Bu rapor **Metrikler** sayfasının **Clients** sekmesinde **Clients with No Requests** alt-raporu olarak yer alır (dokümantasyonda **İstek Atmayan Client'lar**). Ekrana **Administration > Reports > Metrics** veya proje menüsünden **Analytic > Reports > Metrics** ile ulaşabilirsiniz; **Clients** sekmesinde **Clients with No Requests** düğmesini seçin.

Üst satırdaki ortam, proje (yalnızca Administration) ve tarih aralığı filtreleri paylaşılır; rapora özel filtreler alt-rapor satırındadır.

## Filtreler

Belirli kriterlere göre istek atmayan veya az istek atan kullanıcıları tespit edebilirsiniz:

<Steps>
  <Step title="Ortam Seçimi">
    Raporu çalıştırmak için öncelikle bir ortam seçmeniz gerekmektedir. Ortam seçimi zorunludur ve metrikler seçilen ortama göre filtrelenir.

    :::info

Bir API Proxy birden fazla ortama yüklenebildiği için metrikleri de yüklendiği ortama göre değerlendirmek gerekir.

:::
  </Step>

  <Step title="Proje Seçimi (Yönetici)">
    Yönetici kullanıcılar için birden fazla proje seçebilme imkanı sunulmaktadır. Proje seçimi yapıldığında, seçilen projelerdeki kullanıcılar analiz edilir.

    :::note

Bu filtre sadece yönetici kullanıcılar için görünür.

:::
  </Step>

  <Step title="Users">
    Analiz edilecek kullanıcıları çoklu seçimle sınırlayabilirsiniz. Boş bırakılırsa tüm kullanıcılar dahil edilir.
  </Step>

  <Step title="Kurum">
    Raporu seçtiğiniz tüketici kurumlarıyla sınırlayabilirsiniz. Listede aktif projenin kurumları ile platform seviyesindeki kurumlar yer alır; bu filtre yalnızca mevcut kapsamı daraltır, genişletmez. Boş bırakılırsa görünen tüm kurumlar dahil edilir.
  </Step>

  <Step title="API Client'ları Dahil Et">
    Açıkken (varsayılan) her tüketicinin API client anahtarları ayrı satırlar olarak listelenir; böylece sahibi hâlâ aktif olsa bile ölü bir anahtar fark edilebilir. Kapatıldığında yalnızca tüketici kimlikleri gösterilir.
  </Step>

  <Step title="Status">
    Kullanıcı durumuna göre filtreleyebilirsiniz:

    - **ALL**: Tüm durumlar
    - **ACTIVE**: Aktif kullanıcılar
    - **INACTIVE**: Pasif kullanıcılar
  </Step>

  <Step title="Min. Request Count">
    Seçilen tarih aralığında **Toplam** istek sayısının alt sınırı (dahil). Örneğin `0` ile hiç istek atmamış kullanıcılar da kapsama girer.
  </Step>

  <Step title="Max. Request Count">
    Seçilen tarih aralığında **Toplam** istek sayısının üst sınırı (dahil). Min ve Max birlikte düşük trafikli kullanıcı aralığını tanımlar (ör. 0–100).
  </Step>

  <Step title="Search">
    Filtreleri uygulayıp tabloyu yeniden yüklemek için **Search** düğmesine basın. Paylaşılan filtre satırındaki **Excel Export** sonuç listesini indirir.
  </Step>
</Steps>

## Rapor Tablosu

Rapor sonuçları aşağıdaki kolonlarda gösterilir:

| Alan | Açıklama |
|------|----------|
| **Project** | Kimliğin ait olduğu proje (yalnızca Administration) |
| **Kimlik Türü** | Tüketici kimliği için **Tüketici**, ona ait bir anahtar için **API Client** |
| **Organization** | Kimliğin bağlı olduğu kurum (varsa) |
| **Username** | Tüketici kullanıcı adı. API client satırında sahibi olan tüketiciyi gösterir |
| **API Client Anahtarı** | API client'ın anahtarı; tüketici satırlarında boştur |
| **Oluşturulma** | Kimliğin oluşturulma zamanı |
| **Son Kullanım** | Trafik logunda bulunan en son istek ya da **Kullanılmamış** |
| **Durum** | Tüketici için Aktif, Pasif veya Süresi Dolmuş; API client için Aktif veya Askıya Alınmış |
| **Successful** | Başarılı istek sayısı |
| **Blocked** | Bloklanmış istek sayısı |
| **Error** | Hatalı istek sayısı |
| **Total** | Toplam istek sayısı (Successful + Blocked + Error) |

## Yalnızca API Client Üzerinden Çağrı Yapan Tüketiciler

Bir tüketici trafiğini kendi kullanıcı adıyla, kimlik kaydı üzerinden ya da sahip olduğu API client anahtarlarıyla gönderebilir. Rapor, bir kimliğin atıl olup olmadığına karar vermeden önce bu üç kaynağı birleştirir.

Bu ayrım iptal kararında önemlidir: kendi kullanıcı adı sessiz olan ama API client'ı çalışan bir tüketici trafik kolonlarında **0** görünür; buna karşılık kullanıcı adının yanında, API client'larından birinin hâlâ kullanıldığını söyleyen bir bilgi simgesi taşır. Böyle bir tüketiciyi iptal etmek canlı bir entegrasyonu bozar; bu simgeyi "kullanımda" olarak okuyun.

API client'ın kendi trafiği, sahibinin satırında değil API client satırında sayılır. Böylece iki soru ayrı kalır: tüketici kimliğinin kendisi hâlâ kullanılıyor mu ve bu anahtar hâlâ kullanılıyor mu.

## "Son Kullanım" ve Kapsam Notu

**Son Kullanım** bilgisi Elasticsearch'teki trafik logundan türetilir; dolayısıyla ancak trafik logunun saklandığı süre kadar geriye gidebilir. **Kullanılmamış** görünen bir kimlik, saklanan pencere içinde hiç istek üretmemiştir; bu, kimliğin hiç kullanılmadığını kanıtlamaz.

Seçtiğiniz tarih aralığı trafik logunun başlangıcından önce başlıyorsa tablonun üstünde bir uyarı çıkar; uyarı, trafik logunun fiilen hangi tarihte başladığını ve bağlantıda eski indeksler siliniyorsa saklama süresini gün olarak belirtir. Aynı not Excel çıktısında ayrı bir **Info** sayfasına yazılır ve Rapor Üretici'de de gösterilir; böylece zamanlanmış rapor da aynı kaydı taşır.

Seçilen ortam ve kapsam için trafik logunda hiç kayıt yoksa rapor bunu açıkça söyler: satırlar yine listelenir, ancak kullanım hakkında bir kanıt sunmaz.

:::note

Elasticsearch entegrasyonu aktif olmayan ortamlar için rapor çalıştırılamaz. Bu durumda ekranda uyarı mesajı gösterilir.

:::
