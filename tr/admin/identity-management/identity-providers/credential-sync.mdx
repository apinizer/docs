Kimlik Bilgisi Senkronizasyonu, [Database Provider](/tr/admin/identity-management/identity-providers/database-provider), [LDAP Active Directory](/tr/admin/identity-management/identity-providers/ldap-active-directory), [API Kimlik Sağlayıcı](/tr/admin/identity-management/identity-providers/api-authentication-provider) ve [OIDC Kimlik Sağlayıcı](/tr/admin/identity-management/identity-providers/oidc-provider) kaynaklarındaki kullanıcıların, zamanlanmış veya elle tetiklenen bir işle otomatik olarak [Kimlik Bilgisi](/tr/admin/identity-management/kimlik-bilgileri) kayıtlarına dönüştürülmesini sağlar. Böylece kimlik bilgileri her sağlayıcı için ayrı ayrı elle oluşturulmak yerine dış kaynaktan merkezi olarak güncel tutulur.

:::

## Senkronizasyon Profili

Bu ortak alanlar her sağlayıcının düzenleme ekranında bir **Senkronizasyon Profili** bölümünde bulunur: Database Provider, API Kimlik Sağlayıcı ve OIDC Kimlik Sağlayıcıda (yalnızca Keycloak sağlayıcı türünde) ayrı bir sekme olarak (OIDC'de sekme adı **Senkronizasyon**); LDAP Active Directory'de ise düzenleme ekranındaki **Senkronizasyon** kartının **Yapılandır** düğmesiyle açılan bir çekmece olarak — bkz. [LDAP Active Directory](/tr/admin/identity-management/identity-providers/ldap-active-directory#senkronizasyon).

| Alan | Açıklama |
|------|----------|
| Senkronizasyonu Etkinleştir | Etkinleştirildiğinde kimlik bilgileri, tanımlanan zamanlamaya göre bu kaynaktan senkronize edilir. Kapalıyken ne zamanlanmış ne de elle senkronizasyon çalışır. |
| Cron İfadesi | Senkronizasyonun ne sıklıkla çalışacağını belirten Quartz cron ifadesidir (örn. `0 0 2 * * ?`). Zorunlu değildir. Boş bırakılırsa yalnızca [Senkronizasyon](#senkronizasyon-durumu-ve-geçmişi) ekranından elle tetikleme yapılabilir. Alan boşken içinde gri bir ipucu metni görünür, bu metin bir değer değildir. |
| Deaktivasyon Modu | Son senkronizasyon koşusunda kaynakta artık bulunmayan kullanıcılara karşılık gelen kimlik bilgilerine uygulanacak işlemdir:<br/>• **Devre Dışı Bırak** *(geri alınabilir)* — kimlik bilgisi pasif hale getirilir, kaydı korunur. Varsayılan değerdir.<br/>• **Sil** *(geri dönüşsüz)* — kimlik bilgisi tamamen silinir.<br/>• **Hiçbiri** *(olduğu gibi koru)* — herhangi bir işlem yapılmaz, sapma kabul edilir. |

Sağlayıcıya özgü ek alanlar aşağıda anlatılmıştır.

### LDAP Active Directory

| Alan | Açıklama |
|------|----------|
| Base DN (bağlantıdan) | Salt okunur alandır. Senkronizasyon, kullanıcıları ve grupları seçili LDAP bağlantısının Base DN'i altında okur. Aramayı daraltmak için nesne sınıfı tanımlarında **User Base DN Niteliği** veya **Group Base DN Niteliği** alanını doldurun. |

:::note

LDAP senkronizasyonu yalnızca kullanıcıları değil, kullanıcıların bağlı olduğu kurum/organizasyon ağacını da senkronize eder. Organizasyonun üst organizasyonu dizin ağacından gelir: DN içinde başka bir OU veya grubun altında duran OU ya da grup, onun altına yerleşir. Active Directory bir grubu başka bir grubun altına koyamaz. Bu yüzden başka bir grubun üyesi olan grup, o grubun altına yerleşir. Bir organizasyonun tek üst organizasyonu olur. Grup birden fazla grubun üyesiyse DN'i en uzun olan grup üst organizasyon olur. Diğer kaynaklarda (Veritabanı, API) yalnızca kullanıcı senkronizasyonu yapılır. LDAP'tan gelen organizasyonun kodu, organizasyon ekranlarında `<sağlayıcı adı>: <grup DN'i>` biçiminde görünür. Kayıtlı kod değişmez; fareyi kodun üzerine getirdiğinizde tam değer görünür. OIDC (Keycloak) kaynağı, **Grupları Senkronize Et** açıldığında kullanıcılara ek olarak grup ağacını da senkronize edebilir — aşağıya bakınız.

:::

### Database Provider

| Alan | Açıklama |
|------|----------|
| Kullanıcı Listeleme Sorgusu | Senkronize edilecek kullanıcıları döndüren, parametre almayan bir SELECT sorgusudur. Dönen kolonlar için şu takma adlar kullanılmalıdır: `username` (zorunlu), `email`, `full_name`. Örnek: `select login as username, mail as email, display_name as full_name from users` |

### API Kimlik Sağlayıcı

| Alan | Açıklama |
|------|----------|
| Kullanıcı Listeleme URL'si | Senkronize edilecek kullanıcı listesini döndüren uç noktadır. |
| HTTP Metodu | Kullanıcı listesi uç noktası çağrılırken kullanılan HTTP metodudur. |
| Zaman Aşımı | İsteğin bu süre (saniye) sonunda sonlandırılacağını belirtir. |
| İstek Gövdesi | Kullanıcı listesi uç noktasına gönderilen isteğe bağlı istek gövdesidir (POST/PUT için). |
| İstek Başlıkları | Kullanıcı listesi isteğiyle birlikte gönderilecek isteğe bağlı HTTP başlıklarıdır (örn. Authorization). |
| Kullanıcı Dizisi JSON Path | Yanıt içindeki kullanıcı dizisine giden JSON Path ifadesidir. Varsayılan değer: `$` |
| Kullanıcı Adı JSON Path | Bir kullanıcı öğesinden kullanıcı adına giden JSON Path ifadesidir. Zorunlu alandır. |
| E-posta JSON Path | Bir kullanıcı öğesinden e-postaya giden JSON Path ifadesidir. |
| Ad Soyad JSON Path | Bir kullanıcı öğesinden ad soyada giden JSON Path ifadesidir. |

### OIDC Kimlik Sağlayıcı (Keycloak)

Yalnızca Sağlayıcı Türü **Keycloak** olan OIDC Kimlik Sağlayıcı kayıtlarında kullanılabilir; **Generic** sağlayıcı türünde senkronizasyon alanları anlamlı değildir (bkz. [OIDC Kimlik Sağlayıcı](/tr/admin/identity-management/identity-providers/oidc-provider)).

| Alan | Açıklama |
|------|----------|
| Realm | Keycloak realm adıdır. |
| Admin API Taban URL | Keycloak sunucusunun taban adresidir. |
| Senkron İstemci ID | Keycloak Admin API'sini çağırmak için kullanılan, service-account yetkilerine sahip istemcidir. |
| Senkron Sayfa Boyutu | Kullanıcılar Keycloak Admin API'sinden sayfalanarak (paged) çekilirken kullanılan sayfa boyutudur. |
| Grupları Senkronize Et | Açıkken Keycloak grup ağacı, kullanıcıların bağlı olduğu [Kurumlar](/tr/admin/identity-management/kurumlar) yapısına da yansıtılır. |
| Rol Senkron Kaynağı | Kullanıcıların rol/grup üyeliğinin hangi kaynaktan çekileceğini belirler: Realm Rolleri, İstemci Rolleri veya Gruplar. |

:::note

Kullanıcı adı kontratı: senkronizasyon, Keycloak'taki kullanıcı adını (`username`) doğrudan Kimlik Bilgisi kaydının kullanıcı adına yazar. OIDC politikalarındaki token doğrulaması ise varsayılan olarak `preferred_username` claim'ini okur — bu iki değer aynı kullanıcı için eşleşmelidir, aksi halde doğrulanan token hiçbir Kimlik Bilgisi kaydıyla eşleşmez.

:::

| Ad | Kimlik sağlayıcının adıdır. Açıklaması adın altında görünür. Senkronizasyonu kapalı kaynakta **Senkronizasyon kapalı** rozeti görünür. |
| Zamanlama | İşin durumu rozetle gösterilir (Zamanlanmış, Çalışıyor, Duraklatılmış, Beklemede, Tamamlandı veya Hata). Cron ifadesi rozetin altında görünür. Senkronizasyonu açık ama cron ifadesi boş olan kaynakta **Yalnız elle** rozeti görünür. |
| Son Senkronizasyon | Son koşunun tamamlanma zamanıdır. |
| Sonuç | Son koşunun sonucu rozetle gösterilir: **Başarılı**, **Uyarı** veya **Başarısız**. Gerekçeyi görmek için imleci rozetin üzerine getirin. Kaynağın bir koşusu kuyruktayken veya çalışırken bu hücrede çalışma rozeti görünür. |
| Eklenen/Güncellenen, Deaktif Edilen, Atlanan, Hata | Son koşuda işlenen kayıt sayılarıdır. Sıfır değer gri yazılır. Sıfırdan büyük **Deaktif Edilen** sayısı turuncu rozetle gösterilir. Sıfırdan büyük **Hata** sayısı kırmızı rozetle gösterilir. |

### Senkronizasyonu Başlatma

Her satırda bir **Senkronize Et…** düğmesi bulunur. Bu düğme senkronizasyonu zamanlamayı beklemeden başlatır. Başlatma iki adımdır: kapsamı seçtiğiniz bir iletişim kutusu ve ikinci bir onay.

:::warning

Senkronizasyonu kapalı (Senkronizasyonu Etkinleştir alanı kapalı) bir kaynakta **Senkronize Et…** düğmesi pasiftir. Kaynağın bir koşusu kuyruktayken veya çalışırken de düğme pasiftir. Nedeni görmek için imleci düğmenin üzerine getirin.

:::

:::tip

**Tam** ve **Yalnız kullanıcı** koşusu tüketicileri devre dışı bırakabilir. Sonuçtan emin değilseniz, önce sağlayıcının düzenleme ekranında bir deneme koşusu çalıştırın: LDAP için **Dizin Önizleme &gt; Tam tarama (deneme koşusu)**, Veritabanı ve API için **Deneme koşusu** seçeneğiyle **Kaynağı Önizle**, OIDC için **Dizini Önizle**.

:::

1. Kaynağın satırında **Senkronize Et…** düğmesine tıklayın. Senkronizasyon iletişim kutusu açılır.
2. İletişim kutusunun üstündeki bağlantı bölümünü kontrol edin. Bu bölüm kaynağın adını, açıklamasını ve kaynağın nereden okunduğunu gösterir:
   - LDAP: bağlantı, sunucu adresi, güvenlik (LDAPS veya StartTLS), Base DN, Bind DN, User Base DN, Group Base DN ve üyelik modu.
   - Veritabanı: bağlantı, JDBC URL ve veri tabanı kullanıcısı.
   - API: kullanıcı listesi adresi, HTTP yöntemi ve kurum listesi adresi (tanımlıysa).
   - OIDC: Issuer URL, realm, Admin API taban URL'si, istemci ID ve grup senkronizasyonu ayarı.

   Bu bölüm parola veya gizli bilgi göstermez. Bağlantıları görme yetkiniz yoksa bazı satırlar görünmez ve iletişim kutusu bunu belirtir.
3. **Ne senkronize edilsin?** altında kapsamı seçin. LDAP ve OIDC kaynaklarında üç kapsam vardır:
   - **Tam** (Önerilen): kullanıcılar, gruplar/kurumlar ve üst kurumlar okunur. Sonra kaynaktan çıkan kayıtlar işlenir.
   - **Yalnız kullanıcı**: tüketiciler oluşturulur veya güncellenir. Kurum ağacı değişmez.
   - **Yalnız grup**: yalnız kurum ağacı güncellenir. Tüketiciler değişmez.

   Veritabanı ve API kaynakları yalnız tam senkronizasyonu destekler. Bu kaynaklarda iletişim kutusu kapsamlar yerine bir not gösterir.
4. **Son koşu** ve **Beklenen süre** satırlarını okuyun. Beklenen süre, kaynağın önceki bir koşusundan gelir; mümkünse aynı kapsamdaki koşu kullanılır. Önceki koşu yoksa beklenen süre **bilinmiyor** olarak görünür.
5. Bilgi notunu okuyun. Not, kapsama göre değişir:
   - **Tam** ve **Yalnız kullanıcı**: koşunun sonunda, kaynakta artık olmayan tüketiciler kaynağın deaktivasyon moduna göre devre dışı bırakılır veya silinir.
   - **Yalnız grup**: koşunun sonunda, kaynakta artık olmayan kurumlar işlenir. Tüketiciler değişmez.
6. **Senkronizasyonu başlat** düğmesine tıklayın. İkinci bir onay açılır. Onay; kapsamı, kaynağı, koşunun neyi değiştirdiğini ve beklenen süreyi gösterir.
7. Koşuyu başlatmak için **Evet, başlat** düğmesine tıklayın. Koşu başlatmadan iletişim kutusuna dönmek için **Hayır, geri dön** düğmesine tıklayın.

Bir koşu kuyruktayken veya çalışırken, satırının **Sonuç** hücresinde **Çalışıyor · Yalnız kullanıcı** veya **Kuyrukta · Tam** gibi bir rozet görünür. Rozetin altındaki satır, aşamayı (**Kaynak okunuyor** veya **Değişiklikler uygulanıyor**) ve o ana kadar işlenen kullanıcı sayısını gösterir. Sayfa bu bilgiyi kendisi yeniler; aşama ve sayı yaklaşık 15 saniyede bir değişir. Koşu bitince satır yeni sonucu gösterir.

:::note

Satırlar çalışan bir senkronizasyonu aşağıdaki **Senkronizasyon Geçmişi** tablosunun ilk sayfasından öğrenir. O tabloyu sonraki bir sayfaya geçirirseniz, ilk sayfaya dönene kadar çalışma rozeti görünmez.

:::

:::tip

Senkronize edilmiş bir [kimlik bilgisi](/tr/admin/identity-management/kimlik-bilgileri) veya [kurum](/tr/admin/identity-management/kurumlar) kaydının detay ekranında da bir **Senkronize Et** düğmesi bulunur. Bu düğme kimlik yönetme yetkisi olan kullanıcılara görünür. Düğme yalnız o kaydı değil, kaydın bağlı olduğu kaynak sağlayıcının tamamını tam senkronizasyonla senkronize eder.

:::

## Senkronizasyon Koşu Geçmişi

:::info

Yukarıdaki tablo yalnızca **son** koşunun özetini gösterir — her yeni koşu bir öncekinin üzerine yazılır. Bunun yanında, her koşu (zamanlanmış veya elle tetiklenmiş; başarılı, uyarılı, başarısız ve yapılandırma hatası yüzünden hiç başlayamamış olanlar dahil) kalıcı olarak da kaydedilir ve **Senkronizasyon Geçmişi** kartında ayrı bir satır olarak listelenir.

:::

Senkronizasyon Geçmişi kartı iki ekranda görüntülenir:

- **Kimlik &gt; Sağlayıcılar &gt; Senkronizasyon** ekranının altında — projedeki **tüm kaynakların** koşuları, **Kaynak** sütunuyla birlikte.
- Her sağlayıcının görüntüleme (view) ekranının altında ([Database Provider](/tr/admin/identity-management/identity-providers/database-provider), [LDAP Active Directory](/tr/admin/identity-management/identity-providers/ldap-active-directory), [API Kimlik Sağlayıcı](/tr/admin/identity-management/identity-providers/api-authentication-provider), [OIDC Kimlik Sağlayıcı](/tr/admin/identity-management/identity-providers/oidc-provider)) — yalnızca **o kaynağın** koşuları, Kaynak sütunu olmadan.

Tablo sütunları:

| Sütun | Açıklama |
|-------|----------|
| Kaynak *(yalnızca genel ekranda)* | Koşunun ait olduğu kimlik sağlayıcının adı ve türü (LDAP / Veritabanı / API / OIDC). Bu ad **koşu anındaki** isimdir — kaynak sonradan yeniden adlandırılsa ya da silinse bile geçmiş satırı okunabilir kalır. |
| Başlangıç | Koşunun başladığı zaman. |
| Süre | Koşunun toplam süresi. |
| Tetikleyici | **Zamanlanmış** veya **Elle** rozeti. Elle başlatılan koşuda, koşuyu başlatan kullanıcının adı rozetin altında görünür. |
| Kapsam | Koşunun kapsamı rozetle gösterilir: **Tam**, **Yalnız kullanıcı**, **Yalnız grup** veya **Uzlaştırma uygulama**. |
| Sonuç | Sonuç rozetle gösterilir: **Başarılı**, **Uyarı** veya **Başarısız**. Bitmemiş bir koşuda **Kuyrukta** veya **Çalışıyor** görünür. |
| Eklenen/Güncellenen, Deaktif Edilen, Atlanan, Hata | Koşuda işlenen kayıt sayıları. Sıfır değer gri yazılır. Sıfırdan büyük **Deaktif Edilen** sayısı turuncu rozetle gösterilir. Sıfırdan büyük **Hata** sayısı kırmızı rozetle gösterilir. |
| Hata/Uyarı | Koşunun kullanıcı düzeyindeki kayıtlarının (uyarı ve hata) sayısı, **3 hata/uyarı** gibi bir rozetle gösterilir. Hata ve uyarı panelini açmak için rozete tıklayın. |
| Gerekçe | Koşunun sonucuna dair açıklama. |

Tablo sunucu taraflı sayfalanır (10 / 20 / 50 satır seçenekleriyle). Ekranın üst tarafındaki [Senkronizasyon Durumu ve Geçmişi](#senkronizasyon-durumu-ve-geçmişi) tablosu bu değişiklikten etkilenmez, aynen çalışmaya devam eder.

### Koşunun Hata ve Uyarıları

**Hata/Uyarı** sütunundaki **N hata/uyarı** rozetine tıklayın. Hata ve uyarı paneli ekranın sağında açılır ve ekranın en az yarısını kaplar. Tablo, panelin arkasında yerinde kalır.

Panelde şunlar bulunur:

- **Başlık**: kaynağın adı, başlangıç zamanı, süre ve koşunun sonuç, kapsam ve tetikleyici rozetleri.
- **Özet kutuları**: Eklenen/Güncellenen, Deaktif Edilen, Uyarı ve Hata.
- **Gerekçe**: koşu sonucunun açıklaması, bilgi notu olarak.
- **Önem filtresi**: **Tümü**, **Uyarı** veya **Hata**; her birinin yanında kayıt sayısı.
- **Kayıtlar**: her kayıt için bir kart. Kartta önem rozeti, zaman, kullanıcı ve gerekçe bulunur.

Panel, koşunun ilk 50 kaydını gösterir. **Uyarı** ve **Hata** kutuları ile filtre sayıları bu kayıtları kapsar. Koşu daha fazla kayıt yazdıysa, panel toplamın kaçının ekranda olduğunu gösterir. Sunucu kayıtların yalnız bir kısmını sakladıysa, bir uyarı bunu belirtir.

:::note Uyarı sonucu ne anlama gelir

**Uyarı** durumu, koşunun hatasız tamamlandığı ama kaynaktan **hiç kullanıcı okunamadığı** anlamına gelir. Bu durumda, olası bir kaynak kesintisinin tüm kimlik bilgilerini toplu olarak deaktif etmesini önlemek için (bkz. [Davranış ve Güvenlik Notları](#davranış-ve-güvenlik-notları)) uzlaştırma adımı o koşuda hiç çalışmaz — ne ekleme/güncelleme ne de deaktivasyon yapılır.

:::

:::info Başarısız ve elenmiş koşular da kaydedilir

Kaynağa hiç bağlanılamayan veya yapılandırma hatası yüzünden ön kontrolde elenen koşular da geçmişe yazılır. Bir senkronizasyonun neden çalışmadığını araştırırken genellikle aranan bilgi bu satırlardadır.

:::

### Saklama Süresi

Senkronizasyon Geçmişi kayıtları, [Uygulama Logu Temizleme Görevleri](/tr/admin/audit-compliance/uygulama-logu-temizleme-gorevleri) ekranındaki **Kimlik Senkronizasyon Geçmişi** satırı ile yönetilir. Bu ayar **varsayılan olarak kapalıdır** — yönetici açıkça bir süre (saat veya gün cinsinden) girip etkinleştirmedikçe hiçbir koşu kaydı otomatik olarak silinmez. Hem saatlik hem günlük temizleme görevi bu ayarı okur.

### Denetim Kaydında Kaynak Bilgisi

Senkronizasyonun değiştirdiği kimlik bilgisi (credential) kayıtları [Denetim Kayıtları](/tr/admin/audit-compliance/denetim-kayitlari) ekranında artık jenerik bir sistem kullanıcısı yerine `sync:<KAYNAK TÜRÜ>:<kaynak adı>` biçiminde görünür — örneğin `sync:LDAP:corp-ad` veya `sync:OIDC:keycloak-prod`. Böylece bir kimlik bilgisinin senkronizasyon yoluyla mı yoksa bir kullanıcı tarafından mı değiştirildiği, hangi kaynaktan geldiği de belli olacak şekilde ayırt edilebilir. Bu değer Denetim Kayıtları ekranının **Kullanıcı** alanında aranabilir.

Elle tetiklenen bir koşuda, koşuyu başlatan yöneticinin adı bu denetim kaydına **yazılmaz** — o bilgi yukarıdaki Senkronizasyon Geçmişi tablosunun **Tetikleyici** sütununda gösterilir.

## Davranış ve Güvenlik Notları

:::info

- Elle oluşturulmuş (senkronizasyon dışı) bir kimlik bilgisinin kullanıcı adı kaynakta da mevcutsa, bu kayıt senkronizasyon tarafından **üzerine yazılmaz**; çakışmanın giderilmesi için yönetici müdahalesi gerekir.
- Bir kimlik bilgisi zaten başka bir kaynak tarafından yönetiliyorsa (örneğin LDAP), farklı bir kaynak (örneğin Veritabanı) bu kaydı devralmaz.
- Aynı kullanıcı adı başka bir projede zaten kayıtlıysa, senkronizasyon bu kullanıcı adıyla başka bir projede yeni bir kimlik bilgisi oluşturmaz.
- Kaynaktan kullanıcı listesi alınamazsa (bağlantı hatası vb.) veya kaynak hiç kullanıcı döndürmezse, olası bir kaynak kesintisinin toplu deaktivasyona yol açmaması için o koşuda deaktivasyon adımı atlanır.

:::
