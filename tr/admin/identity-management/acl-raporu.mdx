## Raporu Nerede Bulursunuz

Proje menüsünde ACL Raporu **Kimlik** altındadır. Rapor aktif projeyi kapsar.

Yönetici olarak **Yönetim > API Yönetişimi > ACL Raporu** menüsünden açabilirsiniz (**Envanter Raporları** bölümünde). Rapor tüm projeleri kapsar ve **Proje** filtresi sunar.

## Arama

ACL Raporu açıldığında bir arama çalıştırır. Sonrasında tablo yalnızca **Ara** düğmesine bastığınızda değişir. **Ara** düğmesinin yanındaki çubuk, henüz uygulanmamış filtre değişikliklerinin sayısını gösterir.

## Engelli Endpoint'ler

Raporun hangi endpoint'leri listeleyeceğini **Endpointler** filtresiyle seçersiniz:

| Seçenek | Sonuç |
|---------|-------|
| **İzinli endpointler** | Tüketicinin çağırabildiği endpoint'leri listeler. Varsayılan seçenek budur. |
| **Engelli endpointler** | Tüketicinin çağıramadığı endpoint'leri listeler. |
| **Yetkili API proxy'lerin tüm endpointleri** | İkisini birlikte listeler. |
| **Yetki verilmemiş API proxy'lerin endpointleri** | Her tüketici için, rapor kapsamındaki API proxy'lerden tüketicinin yetkisi olmayanların endpoint'lerini listeler. |

Liste engelli endpoint veya yetkisi olmayan endpoint içerebiliyorsa tabloya bir **Erişim** sütunu eklenir. Sütun her satır için **İzinli**, **Engelli** veya **Yetki yok** gösterir.

**Yetki verilmemiş API proxy'lerin endpointleri** seçeneği ekranda, Excel export'ta ve Rapor Üretici'de çalışır. Bu satırlarda **İstek Sayısı** sütunu 0 gösterir. Rapor, **Rapor Üretici Maks. Kayıt** ayarının izin verdiğinden fazla endpoint listeleyecekse reddedilir (Sistem Ayarları > Raporlama). Raporu tüketici, kurum veya API proxy ile daraltın.

## İstek Sayıları

**Seçilen Alanlar** içinde **(Kullanım) İstek Sayısı** seçeneğini seçerseniz tabloya bir **İstek Sayısı** sütunu eklenir. Sütun, her tüketicinin her endpoint'e gönderdiği istek sayısını gösterir.

Alanı seçtiğinizde iki filtre daha görünür:

- **İsteklerin ortamı**: Raporun trafik logunu okuduğu ortam. İlk ortam sizin için seçilir.
- **İsteklerin dönemi**: Raporun saydığı tarih aralığı.

Sayılar trafik logundan gelir. Reverse proxy satırı, tüketicinin API proxy'ye gönderdiği tüm istekleri gösterir. Sayı yoksa hücrede `-` görünür.

:::note

Rapor, istek sayılarını okumak için Elasticsearch'e ihtiyaç duyar. Ortamı veya dönemi değiştirdikten sonra **Ara** düğmesine basın.

:::

## HTTP Metodu ve Limit Planı

**Seçilen Alanlar** içinde iki alan daha vardır. İkisi de varsayılan olarak seçilidir:

- **HTTP Metodu**: Endpoint'in HTTP metodu, örneğin `GET`. Reverse proxy satırında boştur, çünkü reverse proxy'nin kendi metodu yoktur.
- **Limit Planı**: Tüketicinin limit planları.
  - Tüketiciye doğrudan atanmış planların adları. **Custom**, plan yerine satır içi bir limit olduğunu gösterir.
  - Tüketicinin kendi ataması olmayan bir limit ailesi için, tüketicinin uygulamasından veya kurumundan devraldığı plan. `<plan> (Inherited from <ad>)` biçiminde gösterilir; ad, planın geldiği uygulama veya kurumdur. Aynı limit ailesine birden fazla seviye plan atamışsa en yakın seviye geçerlidir.
  - Tüketici bir limit ailesini koşulsuz kapatmışsa o aile için devralınan plan gösterilmez.
  - Tüketicinin planı yoksa hücre boştur.

Rapor limit planlarını yalnız okur. Hiçbir şey değişmez.

## Excel Export

Excel export, tabloyla aynı filtreleri kullanır. **HTTP Metodu** ve **Limit Planı** sütunları veri sütunlarından sonra, **Durum** sütunundan önce gelir. Her satır için **İzinli**, **Engelli** veya **Yetki yok** gösteren bir **Durum** sütunu vardır. **(Kullanım) İstek Sayısı** seçiliyse bir **İstek Sayısı** sütunu da bulunur. Sayısı olmayan satır dosyada 0 gösterir.

Rapor Üretici'deki ACL raporunun önizlemesinde, CSV dosyasında ve e-posta tablosunda da aynı iki sütun vardır.
