**Ne İşe Yarar?**

* API ürünlerine erişen tüketici uygulamalarını portal kapsamında merkezi yönetir
* Uygulamaları **organizasyona** bağlayarak hesap (kişi) ile uygulama sahipliğini ayırır
* Credential ve API Product abonelik sayılarını listede ve detayda görünür kılar
* Metadata, key üretimi / revoke ve abonelik iptali ile operasyonel kontrol sağlar
* Consumer silme taleplerini onaylama, arşivleme veya reddetme ile yaşam döngüsünü güvenli kapatır

**Kimler Kullanır?**

* **Portal Yöneticileri:** Tüm uygulamaları görmek, düzenlemek ve silme taleplerini karara bağlamak için
* **Portal Developer rolleri:** Yetkisi olan kapsamda uygulama yönetimi için
* **Destek / Operasyon:** Kurum ve uygulama bazında credential / abonelik durumunu doğrulamak için

:::info
Test → Prod promote, TEST/PROD credential ayrımı ve sihirbazlar Manager uygulama sayfasında yoktur. Bunlar [Uygulama Promote](/tr/api-portal/uygulama-promote) ve Portal Ayarları → **Prod Promote** kapsamındadır. Canlı kota/trafik için [Trafik ve Kullanım](/tr/api-portal/trafik-ve-kullanim).
:::

## Ekrana Erişim

* **Portal → Applications** (route: `/admin/portal-app`) — aktif portal kapsamında
* Aynı bileşen **Identity → Applications** altında da açılabilir (`?source=identity`); bu modda Project / Portal kolonları görünür, API Products sekmesi gizlenir
* Yetki: Admin, Portal Manager, Portal Developer (Portal menüsü)

## Liste

Üstte **Create** ile yeni uygulama diyalogu açılır.

### Filtreler

| Filtre | Açıklama |
|--------|----------|
| **Search by App name** | Ada göre arama |
| **Search by member account / developer** | Üye hesap e-posta / ad üzerinden ACTIVE org üyelikleriyle bağlı uygulamaları bulur |
| **Organization** | Tek veya çoklu kurum filtresi |
| **Tür: Tümü** | Portal / Dahili. Seçim yapılmadığında iki tür de listelenir; Manager listesi türü gösterir, türe göre daraltılmış değildir |

### Kolonlar

| Kolon | Açıklama |
|-------|----------|
| **App** | Ada tıklayınca view; açıklama tooltip’te |
| **Tür** | Portal / Dahili rozeti; türü kayıtlı olmayan uygulama Portal olarak okunur |
| **Organization** | Kurum rozeti → org overview |
| **Credentials / API Products** | `list-stats` ile adet rozetleri |
| **Created Date** | Oluşturma zamanı |
| **Reference Id** | Benzersiz referans |

**Rozetler (ad üzerinde):**

* **Deletion requested** — consumer silme talebi (`PENDING_DELETION`)
* **Archived** — arşivlenmiş uygulama

`ACTIVE` / `SUSPENDED` için listede özel rozet yoktur. Suspend Manager UI’da yoktur (yalnızca backend).

### Satır menüsü (⋮)

* **View** · **Edit** · **Remove** (anında hard delete)
* `PENDING_DELETION` iken ayrıca: **Approve & delete** · **Approve & archive** · **Reject**

## Oluşturma

Create diyaloğu alanları:

| Alan | Zorunlu | Not |
|------|---------|-----|
| **App (Name)** | Evet | Max 255 |
| **Tür (Type)** | Evet | Portal (varsayılan) / Dahili — yalnız oluşturmada seçilir, sonrasında salt okunur |
| **Reference Id** | Evet | Varsayılan UUID |
| **Description** | Hayır | |
| **Organization** | Evet | Hesap (Account) alanı yoktur |

Metadata, credential ve ürün aboneliği oluşturma diyalogunda yoktur; edit/view’da yönetilir. `portalId` / `projectId` aktif portal bağlamından atanır — **Dahili** uygulama hariç: o bir portala ait olmadığı için `portalId` boş kaydedilir.

### Dahili uygulamalar

Dahili uygulama, yönetici tarafından kuruluşun kendi kullanımı için oluşturulan uygulamadır; portalın değil, Manager'ın kendi yüzeyine aittir.

* **Yalnız** buradan oluşturulur. Portal yüzeyi, istek ne gönderirse göndersin oluşturduğu uygulamayı her zaman Portal olarak damgalar
* Portal yüzeyli sorguların hiçbirinde dönmez: tüketicinin **My Apps** listesi, kuruluşun uygulama listesi, raporlar ve Portal Management API `GET /portal-app` ucu bu uygulamaları dışarıda bırakır
* Portal yüzeyinden gönderilen güncelleme isteği reddedilir; uygulama üretime de yükseltilemez
* Kuruluşun `maxAppCount` kotasını **tüketmez** — o limit yalnız Portal uygulamaları için geçerlidir

## Görüntüleme (View)

Üstte ad, Organization rozeti, Created Date; **Edit** / **Delete**.

Özet kartlar: **Credentials** sayısı, **API Products** sayısı (Identity modunda ürün kartı gizlenir).

### Information

* **Details:** ad, tür, uygulama anahtarı (kopyalama düğmesiyle), açıklama, organization, created, referenceId (Identity’de project)
* **Linked Resources:** credential / ürün sayıları
* **Metadata (salt okunur):** Key, Value (secret ise `••••••••`), Secret evet/hayır

### Credentials & Products

* Credential chip’leri (pasif olanlar secondary)
* Ürün chip’leri: ad · plan tipi · abonelik durumu (Identity’de ürünler yok)

### Usage Report

Uygulama kapsamlı özet metrik paneli (ürün filtresi + tarih aralığı; başarılı / blok / hata / süre). Platform geneli için [API Trafik Raporu](/tr/api-portal/api-trafik-raporu) ve [Trafik ve Kullanım](/tr/api-portal/trafik-ve-kullanim).

## Düzenleme (Edit)

**Save and Deploy** ile kaydedilir.

| Alan / bölüm | Düzenlenebilir mi? |
|--------------|--------------------|
| Name, Description | Evet |
| Organization, Reference Id | Hayır (salt okunur şerit) |
| Tür, Uygulama Anahtarı | Hayır (salt okunur şerit; sunucu kayıtlı değeri geri yazar ve farklı değer taşıyan isteğe 400 döner) |
| **Metadata** | Satır ekle/sil; key zorunlu ve benzersiz; value; secret + göster/gizle |
| **API Keys / Credentials** | **Generate**; tablo: apiKey, enabled, created, expire; **Revoke** |
| **API Products** | Plan/durum görünür; **Unregister** → `UNSUBSCRIBED` (yeni abonelik bu ekrandan açılmaz) |

## Yaşam döngüsü

| Durum | Nasıl oluşur? | Manager’da ne yapılır? |
|-------|---------------|-------------------------|
| **ACTIVE** | Varsayılan / Reject sonrası | Create, edit, doğrudan Remove |
| **PENDING_DELETION** | Consumer silme talebi (credential’lar pasifleşir) | Approve & delete / Approve & archive / Reject |
| **ARCHIVED** | Approve & archive | Veri korunur; abonelikler unsubscribed |
| **SUSPENDED** | Yalnızca backend | Manager UI yok |

**Approve & delete:** uygulama + credential + ACL + abonelik + gateway undeploy kalıcı kaldırılır. Veriyi korumak için arşiv tercih edilir.
