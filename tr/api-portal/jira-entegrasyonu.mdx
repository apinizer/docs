**Ne İşe Yarar?**

* Portal ile Jira arasında REST bağlantısını (URL, kullanıcı, API token) yönetir
* Klasik Jira talep formunun (`/jira-issue`) proje, issue tipi, label ve custom field eşlemesini sağlar
* Destek sağlayıcısı Jira seçildiğinde Features bayrağıyla birlikte çalışır
* Destek Paketleri’nden bağımsızdır

**Kimler Kullanır?**

* **Portal Yöneticileri:** Jira bağlantısını kurmak ve test etmek için
* **Destek / ITSM Ekipleri:** Taleplerin doğru Jira projesine düşmesini sağlamak için

## Ekrana Erişim

* **Portal → Settings → Jira Integration** (`/admin/portal-jira-config`)
* Bağlantı kaydı `JiraConfig` koleksiyonundadır (aktif portal kapsamında)
* **Save and Deploy** ile kaydedilir

## Built-in ve Jira birlikte nasıl çalışır?

```
Features → enableJiraIntegration ──► Support sağlayıcı olarak JIRA seçilebilir
                                  └──► Portal’da jira-issue (Support Request) sayfası seed edilebilir

Jira Integration (bu sayfa) ──► URL / auth / project / type / labels / custom fields
                             └──► Portal /jira-issue oluşturma + liste

Destek sekmesi (supportEnabled) ──► Portal “Support” menüsü görünür
supportProvider ──► Support menü hedefi: /support-ticket (Built-in) veya /jira-issue (Jira)
```

| Ayar | Rolü |
|------|------|
| **Features → Jira Integration** (`enableJiraIntegration`) | Jira sağlayıcının seçilebilmesi için zorunlu; kapanınca provider Built-in’e düşer |
| **Destek → Enable + Provider** | Support menüsünü açar; hedef route’u belirler |
| **Bu sayfa (JiraConfig)** | Klasik `/jira-issue` formunun kullandığı bağlantı |

:::warning
**İki farklı akış vardır:**

1. **Built-in Support** (`/support-ticket`): Talepler Apinizer’da saklanır; Manager **Support Tickets** ile yönetilir.
2. **Portal Support menüsü → Jira** (`/jira-issue`): Kullanıcı klasik Jira formunu kullanır; issue **doğrudan Jira’da** açılır. Bu yolda Apinizer `SupportTicket` kaydı oluşturulmaz.

“Her talep her zaman Apinizer’da tutulur” ifadesi Jira menü yönlendirmesi için geçerli değildir.
:::

## Entegrasyon Alanları

| Alan | Zorunlu | Açıklama |
|------|---------|----------|
| **Status** | — | Active/Passive. UI “Connected” rozeti için `status === true` ve URL dolu olması kullanılır; klasik create yolu status’ü REST gate olarak zorunlu kılmaz |
| **Jira API Url** | Evet | Örn. `https://your-org.atlassian.net` (sonunda `/` olmadan). Cloud’ta description ADF formatına gidebilir |
| **Description** | UI’da required sınıfı olabilir | Yalnızca yönetici notu; Jira’ya gitmez |
| **Username** | Evet | Atlassian e-posta |
| **API Token** | Evet | Basic Auth şifresi |
| **Project Key** | Evet | Klasik `/jira-issue` create’te kullanılır |
| **Issue Type** | Evet | Örn. Task |
| **Category Custom Field ID** | Hayır | Portal kategori → Jira custom field |
| **API Product Custom Field ID** | Hayır | |
| **API Product Endpoint Custom Field ID** | Hayır | |
| **Jira Label** (`labelList`) | Hayır | Enter ile ekle; tablo ile sil |

Destek sekmesindeki **Support project key / Issue type / Status mapping** alanları bu tablodan ayrıdır; Support Ticket API / mapping için kullanılır. Navbar Jira’ya `/jira-issue` yönlendirdiğinde pratikte **bu sayfadaki** Project Key / Issue Type geçerlidir.

## Kurulum Özeti

1. Atlassian’da API token üretin.
2. Features → **Jira Integration**’ı açın.
3. Bu sayfada URL, kullanıcı, token, Project Key, Issue Type’ı kaydedin (**Save and Deploy**).
4. Destek sekmesinde modülü açın ve sağlayıcıyı **Jira Integration** seçin (veya Built-in’de kalın).
5. Portal’da Support menüsünden akışı doğrulayın.

Custom field ID bulma: [Atlassian Custom Fields](https://confluence.atlassian.com/adminjiraserver/adding-custom-fields-1047552713.html).
