Global politikalar API Proxy'lerden bağımsız olarak Global Politikalar arayüzlerinden ya da bir API Proxy'nin [Geliştirme Sekmesi içinden](/tr/develop/api-proxy-konfigurasyonu/politika-yonetimi) oluşturulabilir.

## Global Politikaların Özellikleri

- **Bağımsızlık**: Global politikalar, API Proxy'lerden bağımsız olarak oluşturulabilir ve yönetilebilir.
- **Yeniden Kullanılabilirlik**: Bir global politika, birden fazla API Proxy tarafından kullanılabilir.
- **Merkezi Güncelleme**: Bir global politikada yapılan güncellemeler, bu politikayı kullanan tüm API Proxy'leri etkiler.
- **Etkileşim**: Bir API Proxy silindiğinde, o API Proxy tarafından kullanılan global politikalar bundan etkilenmez. Bununla birlikte, global politikada yapılan herhangi bir güncelleme, o politikayı kullanan bütün API Proxy'leri etkiler.

Global Politikalarla yapılabilecek işlemler:

- [Global Politikaları İçe Aktar](/tr/admin/secrets-management/export-import)
- [Global Politikaları Dışa Aktar](/tr/admin/secrets-management/export-import)

## AI Gateway Politikaları

Global Politikalar arayüzü yalnız klasik API proxy politikalarını değil, **AI Gateway politikalarını** da merkezi olarak listeler ve yönetir. Bazı AI politikaları AI, MCP ve A2A Gateway'lerinin hepsinde kullanılabilirken (örneğin kişisel veri maskeleme, istem koruması, veri sızıntısı koruması — bkz. [Gelişmiş Korumalar](/tr/ai-gateway/gelismis-korumalar)), bazıları yalnızca AI Gateway'lere özeldir (örneğin token kotası, semantik önbellek, bağlam zenginleştirme). AI politikaları klasik API Proxy Gruplarına eklenmez; AI, MCP ve A2A Gateway'lerine uygulanır.

Bu sayfa AI politikalarının **merkezi yönetim ve toplu deploy** yüzeyidir. Her AI politikasının **ne yaptığı** ve nasıl yapılandırıldığı ise AI Gateway bölümünde anlatılır:

- [Gelişmiş Korumalar](/tr/ai-gateway/gelismis-korumalar) — kişisel veri maskeleme, istem ve veri sızıntısı koruması ile diğer güvenlik politikalarının davranışı
- [Erişim Kontrolü ve Roller](/tr/ai-gateway/erisim-kontrolu-rbac) — AI politikalarını kimlerin yönetip dağıtabileceği

## Politikayı Kullanan Proxy'ler

Her global politikanın düzenleme ekranında, o politikayı kullanan proxy'lerin listesi bulunur. Liste hem klasik API Proxy'leri hem de AI, MCP ve A2A Gateway'leri kapsar; her satırda şunlar görünür:

- **API Proxy**: Proxy'nin adı. Adın üzerine tıkladığınızda ilgili proxy'nin düzenleme ekranı açılır; AI, MCP ve A2A Gateway'lerinde kendi ekranları açılır.
- **Tipi**: Proxy'nin türü.
- **Proje**: Proxy'nin bulunduğu proje.
- **Kullanım Noktası**: Politikanın proxy içinde hangi akışa bağlı olduğu — istek, yanıt veya hata. Politika tek bir metoda bağlıysa o metodun adı da gösterilir; metot adı yazmıyorsa politika proxy'nin tüm metotlarında çalışır. Aynı politika birden fazla noktaya bağlıysa hepsi alt alta listelenir.
- **Ortam**: Proxy'nin o an deploy edilmiş olduğu ortamlar. Proxy hiçbir ortama deploy edilmemişse "Deploy edilmemiş" yazar.
- **Açıklama**: Proxy'nin açıklaması.

Listede yalnızca yetkili olduğunuz projedeki proxy'ler görünür.

Bir global politikayı silmek istediğinizde, politika bu listedeki proxy'lerden herhangi biri tarafından kullanılıyorsa silme işlemi engellenir ve kullanan proxy'ler size gösterilir.

## Bir Proxy İçinden Global Politikayı Düzenleme

Bir global politika, kullanıldığı proxy'nin içine kopyalanmaz; proxy merkezdeki tanıma bağlanır. Bu nedenle politikayı **iki farklı yerden** düzenlemek **iki farklı** sonuç verir:

- **Global Politikalar ekranından düzenlerseniz** değişiklik merkezî tanımda yapılır ve politikayı kullanan tüm proxy'leri etkiler. Politika kullanımdaysa kaydetmeden önce bunu bildiren bir onay penceresi açılır ve kullanan proxy'ler listelenir.
- **Bir proxy'nin Geliştirme sekmesinden düzenlerseniz** merkezî tanım korunur. Kaydederken bir uyarı penceresi açılır ve devam etmek için politikanın adını yazmanız istenir. Onayladığınızda politika o proxy'ye özel bir kopya hâline gelir ve merkezî tanımla bağı kopar: sonraki merkezî güncellemeler artık bu proxy'ye yansımaz, bu proxy'de yaptığınız değişiklikler de diğer proxy'leri etkilemez.

Bu davranış klasik API Proxy'lerde olduğu gibi AI, MCP ve A2A Gateway politikalarında da geçerlidir.

:::info

Uyarı penceresi yalnızca **global** bir politikayı proxy içinden düzenlerken çıkar. Proxy'ye özel politikalarda böyle bir uyarı yoktur; onlar zaten yalnızca o proxy'yi ilgilendirir.

:::

## Global Politikalar Deploy İşlemi

Global politika üzerinde herhangi bir değişiklik yapıldığında, bu politikayı kullanan API Proxy'lerin ve API Proxy Grupların durumu "Redeploy Required" olarak değişir. Bunları tek tek deploy etmek yerine, bu sayfadaki deploy özelliği ile bu politikayı kullanan tüm API Proxy'lerin ve API Proxy Grupların belirli bir çalışma ortamına *(environment)* toplu olarak deploy edilmesini sağlanır.

Deploy işlemi başlatıldığında, bir onay dialogu açılır. Bu dialog'da aşağıdaki bilgiler ve seçenekler bulunur:

- **Politika/Ayar Grubu Adı**: Deploy edilecek global politikanın adı gösterilir. Bu bilgi, toplu işlem olduğundan onay mekanizmasında görüntülenir.
- **API Proxy ve API Proxy Group Seçimi**: Deploy işleminin API Proxy'lere mi, API Proxy Gruplarına mı uygulanacağını seçebilirsiniz. Her iki seçenek de işaretlenebilir.
- **Filtreleme Seçeneği**: Deploy edilecek API Proxy ve API Proxy Gruplarını filtrelemek için aşağıdaki seçeneklerden birini seçebilirsiniz:
  - **Hepsine**: Bu global politikayı kullanan tüm API Proxy ve API Proxy Grupları deploy edilir.
  - **Sadece deployed durumunda olanlara**: Sadece seçili ortamda deployed durumunda olan ve redeploy gerektirmeyen API Proxy ve API Proxy Grupları deploy edilir.
  - **Sadece deployed ve redeploy required durumda olanlara**: Sadece seçili ortamda deployed durumunda olan ve redeploy gerektiren API Proxy ve API Proxy Grupları deploy edilir.
- **Deploy Edilecek Nesne Sayıları**: Seçilen filtreleme seçeneğine göre deploy edilecek API Proxy ve API Proxy Group sayıları gösterilir.

Filtreleme seçeneği değiştirildiğinde, deploy edilecek nesne sayıları otomatik olarak güncellenir. Deploy işlemi başlatıldığında, seçilen filtreleme seçeneğine göre belirlenen API Proxy ve API Proxy Grupları deploy edilir.

Deploy işlemi tamamlandığında, kullanıcıya deploy işleminin sonucunu gösteren **Deployment Results** adında bir sonuç ekranı sunulur.

## Yerel Politikayı Globalleştirme

API Proxy'nin Geliştirme sekmesinde iken oluşturacağınız herhangi bir politikada sağ üst alanda bulunan "Politikayı, Global Politika Olarak Ekle *(Add The Policy As a Global Policy)*" butonuna basıp açılan "İsim " alanına bir isim girerek burada oluşturduğunuz politikanın global bir politika olmasını sağlayabilirsiniz.
