Bu rehber, farklı önbellek türlerini ve geçersiz kılma yollarını tek yerde toplar. Ayrıntılar için kaynak sayfalara bakın; burada yalnızca mevcut dokümantasyonda geçen bilgiler özetlenir.

## Önbellek türleri

- **[API Proxy — Settings (genel yanıt önbelleği)](/tr/develop/api-proxy-konfigurasyonu/settings#önbellek-ayarları):** API Proxy'den dönen başarılı yanıtların önbelleğe alınması; istekler Backend API'ye gitmeden önbellekten yanıtlanabilir. Yalnızca durum kodu `400` altındaki başarılı yanıtlar önbelleğe alınır; AI, MCP ve A2A tipindeki API Proxy'lerde genel yanıt önbelleği uygulanmaz.
- **[API Proxy — Endpoint (REST metot/endpoint önbelleği)](/tr/develop/api-proxy-konfigurasyonu/endpoint-konfigurasyonu):** **Önbellek Ayarları** açıldığında metot/endpoint bazlı önbellek; anahtar tipi, kapasite, TTL ve geçersizleme alanları endpoint formunda tanımlanır.
- **[API Call politikası önbelleği](/tr/develop/politikalar/api-cagrisi):** Politikanın yaptığı harici REST çağrısının yanıtını saklar; **CACHE** sekmesinde etkinleştirilir, **Apply By (Cache By)** değişkeni, kapasite, TTL ve depolama tipi ile yönetilir.
- **[Önbellek (Cache) politikası](/tr/develop/politikalar/onbellekleme):** Politika zincirinde bağımsız **LOOKUP**, **POPULATE** ve **INVALIDATE**; API Call politikasının dahili önbelleğinden farklı olarak hangi değerin ne zaman okunup yazılacağını akışta siz belirlersiniz.
- **[API Proxy Group — Cache Settings](/tr/concepts/temel-kavramlar/api-proxy-group):** Grup seviyesinde önbellek ayarları; grup üyelerine uygulanır. API Proxy seviyesi ayarlar grup seviyesinden önceliklidir.
- **[Settings — Idempotency](/tr/develop/api-proxy-konfigurasyonu/settings#idempotency-ayarları):** `Idempotency-Key` ile dağıtık önbellekte kayıt; mükerrer isteklerde saklanan yanıtın dönülmesi içindir — genel yanıt önbelleği ile aynı mekanizma değildir.
- **[Yükleme / yeniden yükleme (Deploy / Redeploy)](/tr/develop/yukleme-ve-surum-yonetimi):** Önbellek kaydı türü değil; yüklenmiş API Proxy yapılandırmasının ortama yansıması. Değişiklikler **Yeniden Yükle (Redeploy)** ile çalışma zamanında geçerli olur; yeniden yükleme kesintisiz yapılır ve gelen istekler yeni ayarlara göre yanıtlanır.

## API Proxy — Settings yanıt önbelleği

[Settings](/tr/develop/api-proxy-konfigurasyonu/settings) sekmesindeki **Önbellek Ayarları**, proxy genelinde yanıt önbelleğini yönetir. İstemci istekleri, anahtar eşleşmesi ve TTL koşulları sağlandığında Backend'e gitmeden yanıtlanabilir.

Öne çıkan kurallar:

- Yalnızca başarılı yanıtlar (`400` ve üzeri 4xx/5xx önbelleğe alınmaz).
- **Sadece HTTP Get İsteklerini Önbelleğe Al** ile yalnızca GET yanıtları sınırlandırılabilir.
- Geçersiz kılma: istekte **Cache-Control** ile `no-cache`, `no-store` veya `max-age=0`; isteğe bağlı kimlik doğrulama zorunluluğu.

AI, MCP ve A2A proxy tiplerinde bu ayar yok sayılır; semantik önbellek için [Semantik Önbellek](/tr/ai-gateway/semantik-onbellek) sayfasına bakın.

## API Proxy Group

[API Proxy Group](/tr/concepts/temel-kavramlar/api-proxy-group) grup seviyesinde **Cache Settings** içerir; CORS, Idempotency ve Bakım Modu ile birlikte grup üyelerine ortak yapılandırma sağlar.

:::info

Grup içindeki her API Proxy kendi ayarlarını da tanımlayabilir; **API Proxy seviyesi ayarlar grup seviyesi ayarlardan önceliklidir.**

:::

Matriste grup satırı, proxy/endpoint önbelleğinden ayrı bir yönetim yüzeyi olarak düşünülmelidir; alan düzeyi ayrıntılar grup kavram sayfasında özetlenir, teknik alanlar Settings/Endpoint ile paralel kabul edilir.

## API Call politikası

**API Call** politikasının önbelleği, yalnızca o politikanın hedeflediği harici çağrının yanıtını saklar. Önbellek açıkken istek önce cache kontrolünden geçer; başarılı yanıt cache'e yazılır ([çalışma prensibi](/tr/develop/politikalar/api-cagrisi#çalışma-prensibi)).

**Önbellek (Cache) politikası** ile fark:

| | API Call — CACHE | Önbellek politikası — INVALIDATE |
| --- | --- | --- |
| **Kapsam** | Politika içi REST çağrısı yanıtı | Politika zincirinde sizin tanımladığınız anahtar/değer |
| **Silme** | TTL; manuel temizlik için dokümantasyon **Cache Policy** (INVALIDATE) önerir | Akışta **INVALIDATE** ile anahtar bazlı silme |
| **Anahtar** | **Cache By** değişkeni | **Anahtar Öneki** + **Anahtar Değişkenleri** (proje/ortam/proxy otomatik eklenmez) |

Proxy **Settings** yanıt önbelleği, istemciye dönen nihai API Proxy yanıtını hedefler; API Call önbelleği backend'e giden ara çağrıyı hedefler — üçü birbirinin yerine geçmez.

:::warning

**Genel yanıt önbelleğini** istekte **Cache-Control** ile geçersiz kılmak, **Önbellek politikası INVALIDATE** adımını veya **API Call** politika önbelleğini otomatik olarak temizlemez. **Idempotency** kayıtları da ayrı bir önbellek kullanımıdır (`Idempotency-Key`, saklama süresi gün cinsinden).

Kota, kimlik doğrulama token'ları ve oturum (session) verileri bu sayfalarda anlatılan yanıt/politika önbelleği geçersiz kılma yöntemlerinin kapsamında değildir; bunları proxy yanıt önbelleği ile karıştırmayın.

:::
