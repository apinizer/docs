## DB-2-API Listesi

Ana menüde **Geliştirme → API Oluşturucu → DB-2-API** öğesini seçin. Tabloda şu sütunlar bulunur: **Ad**, **Bağlantı Havuzu Tanımı**, **Veritabanı Tipi**, **Uç Noktalar** ve **URL**. **Veritabanı Tipi** sütunu, uç noktaların kullandığı bağlantı havuzlarının veritabanı tiplerini gösterir.

Listeyi daraltmak için tablonun üstündeki filtreleri kullanın:

| Filtre | Açıklama |
|---|---|
| **Ada göre ara** | Adı girdiğiniz metni içeren DB-2-API'leri gösterir. |
| **SQL metnine göre ara** | Bir uç noktanın SQL'inde girdiğiniz metin geçen DB-2-API'leri gösterir. |
| **Uç nokta yoluna göre ara** | Bir uç noktanın yolunda girdiğiniz metin geçen DB-2-API'leri gösterir. |
| **Tüm bağlantı havuzları** | Bir bağlantı havuzu tanımı seçin. |
| **Veritabanı Tipi** | Bir veritabanı tipi seçin. Örneğin Oracle, MySQL, PostgreSQL veya MongoDB. |

Filtrelenmiş listeyi dışa aktarmak için Excel düğmesine tıklayın. Dosyada şu sütunlar bulunur: **Name**, **Description**, **Project**, **Database Type**, **Connection Pool Definitions** ve **Endpoints**.

### Yönetişim Listesi

Sistem yöneticileri ve sistem analizörleri tüm projelerdeki API Creator'ları görebilir. **Yönetim > API Yönetişimi > API Creator'lar** menüsünü açın. Bu menü öğesi için API Creator lisansı gerekir.

Sayfada üç sekme bulunur: **DB-2-API**, **Mock API** ve **Script-2-API**. Her sekme salt okunur bir listedir. Oluşturma, içe aktarma ve **⋮** menüsü işlemleri yoktur. View sayfasını açmak için ada tıklayın. Listede ek olarak **Proje** sütunu ve **Proje** filtresi bulunur. Sekmenin filtrelenmiş listesini dışa aktarmak için Excel düğmesine tıklayın.

Bir veritabanı bağlantısının detay sayfasındaki **Kullanıldığı Yerler** paneli, bağlantıyı kullanan DB-2-API'leri listeler. Bkz. [Bağlantı Yönetimi](/tr/integrations/baglanti-yonetimi/genel-bakis#kullanıldığı-yerler-paneli).

## Yeni DB-2-API Oluşturma

DB-2-API oluşturma iki adımlı bir sihirbazdır: **Tanım** ve **Gözden Geçir**.

<Steps>
  <Step title="Menüden DB-2-API Sayfasına Gidin">
    Ana menüde **Geliştirme → API Oluşturucu → DB-2-API** (*Development → API Creator → DB-2-API*) ögesi seçilir.
  </Step>
  
  <Step title="Yeni API Oluşturun">
    Açılan arayüzde sağ üstteki **Yeni** tuşuna tıklanır.
    
    <img src="/images/develop/api-proxy-olusturma/db-api-olustur-butonu.png" alt="DB-2-API Oluştur butonu" width="800" />
  </Step>
  
  <Step title="API Bilgilerini Doldurun">
    **Tanım** adımında *API*'nin **Ad** (zorunlu, benzersiz olmalı) ve **Açıklama** alanları doldurulur ve **Devam Et** tuşuna tıklanır. Sağdaki panel DB-2-API'nin nasıl çalıştığını anlatır: istemci Apinizer üzerinden bir REST API çağırır, Apinizer SQL deyimini veri tabanında çalıştırır ve OpenAPI tanımı otomatik oluşturulur.
    
    <img src="/images/develop/api-proxy-olusturma/db2api-new.png" alt="DB-2-API bilgilerini doldurma" width="800" />
  </Step>

  <Step title="Gözden Geçirin ve Oluşturun">
    **Gözden geçir** adımında tip, ad ve açıklama gösterilir. **DB-2-API Oluştur** tuşuna tıklanınca *API* oluşturulur ve endpoint'lerin eklendiği editör açılır.
  </Step>
</Steps>

Editörde solda API (ad, açıklama ile uç nokta, bağlantı havuzu ve API Proxy sayıları; düzenleme simgesi ad ve açıklamayı değiştirir) ve altında **Endpoint'ler** listesi, sağda ise seçili endpoint görünür. Üstte **Değişkenler** ve **Spec'leri göster** simgeleri ile **⋯** menüsü bulunur. **⋯** menüsünde **API Proxy** (API Proxy Oluştur, Proxyleri Yönet), **Aktarım** (Dışa Aktar, Çoğalt), **Geçmiş** (Denetim ve Geri Yükleme) ve **Sil** yer alır.

## SQL'i Test Etme

Endpoint'e istek gönderildiğinde nasıl bir sonucun alınacağı görülmek istenebilir. Eğer endpoint için çalıştırılacak sorgunun parametreleri varsa test verileri (Test Value) girilerek **Bu sorguyu dene (Try this query)** butonuna basılır.

Gerçek bir istek göndermek için endpoint'in üstündeki **Dene (Try it)** tuşunu kullanın. İstek, bu DB-2-API'den oluşturulmuş bir API Proxy üzerinden gider; bu yüzden en az bir API Proxy bulunmalı ve yüklenmiş olmalıdır.

Test sonucu dönen şablon, Apinizer'da stabil olan Response nesnesidir. Eğer sorguyla eşleşen birden fazla kayıt varsa sadece ilk kayıt örnek yanıt içinde verilmektedir.

<img src="/images/develop/api-proxy-olusturma/db-api-sql-test.png" alt="SQL test etme" width="800" />

:::info

Test için **null** değer gönderilmek istenirse, parametre olarak **null** yazılması yeterlidir.

:::

## DB-2-API'den API Proxy Oluşturma

En az bir tane *Method/Endpoint* olduğunda **⋯** menüsünden **API Proxy → API Proxy Oluştur (Create API Proxy)** seçeneğiyle DB-2-API için bir API Proxy oluşturulur.

:::warning

DB-2-API'den API Proxy oluşturmak için en az bir *Method/Endpoint* olmalıdır. O zamana kadar menü ögesi pasiftir ("Önce bir uç nokta ekleyin.").

:::

**API Proxy Oluştur** penceresinde **Proxy adı**'nı girin, **İstemci Rotası**'nı (göreli yollar, metotlar, host'lar ve başlıklar; en az birini seçin) belirleyin ve **Yüklenecek ortamlar** altında yüklenecek ortamları seçin. **Oluştur ve yükle** tuşuna tıklamak API Proxy'yi oluşturur ve seçili ortamlara yükler. Hiçbir ortam seçmezseniz API Proxy oluşturulur ama yüklenmez.

Bu adımdan sonra yapılabilecekler API Proxy dokümanı ile birebir aynıdır. Detayına gitmek için [API Proxy Oluşturma](/tr/develop/api-proxy-olusturma) sayfasına bakabilirsiniz.

:::info

Bir DB-2-API'dan birden fazla API Proxy oluşturabilirsiniz.

:::

## Yükle (Deploy)/Yeniden Yükle (Redeploy)

DB-2-API'deki API Proxy'leri görüntülemek ve yönetmek için **⋯** menüsünden **API Proxy → Proxyleri Yönet (Manage API Proxies)** seçeneğine tıklayarak açılan pencereden görüntülenir ve yönetilir. Açılan pencerede DB-2-API ile oluşturulan API Proxy'ler Yükle/Kaldır ve Yeniden Yükle işlemleri bu bölümde yapılır.

API Proxy'i deploy etmek için **Proxyleri Yönet** penceresi açılarak deploy simgesine basılır.

<img src="/images/develop/api-proxy-olusturma/db-api-proxy-yonetme.png" alt="API Proxy yönetme" width="600" />

Yukarıdaki işlemden sonra onaylama yapmak gereklidir. Yükleme işlemiyle ilgili bilgileri oluşturup **(Yükle) Deploy** butonuna tıklanır.

<img src="/images/develop/api-proxy-olusturma/db-api-deploy.png" alt="Deploy ekranı" width="600" />

DB-2-API'ye yeni bir *Method/Endpoint* eklendiğinde veya mevcut *Method/Endpoint*'lerden birisi güncellendiğinde, tüm API Proxy'lerin yeniden yüklenmesi gerekir.

Yeni bir *Method/Endpoint* eklediğinizde veya mevcut bir *Method/Endpoint*'i güncellediğinizde aşağıdaki gibi bir bilgilendirme gelecektir.

<img src="/images/develop/api-proxy-olusturma/db-api-yeniden-yukleme-bildirimi.png" alt="Yeniden yükleme bildirimi" width="600" />

**Yeniden Yükle (Redeploy Required)** diyerek değişikliklerin API Proxy'lere uygulanması sağlanır.

<img src="/images/develop/api-proxy-olusturma/db-api-redeploy.png" alt="Redeploy ekranı" width="600" />

Yukarıdaki işlemden sonra onaylama yapmak gereklidir. Yeniden yükleme işlemiyle ilgili bilgileri oluşturup **(Yeniden Yükle) Redeploy** butonuna tıklanır.

<img src="/images/develop/api-proxy-olusturma/db-api-redeploy-onay.png" alt="Redeploy onay ekranı" width="600" />

DB-2-API sayfasından API Proxy'nin ismindeki link tıklanarak API Proxy'e gidilir.

<img src="/images/develop/api-proxy-olusturma/db-api-proxy-link.png" alt="DB-2-API'dan API Proxy'ye link" width="600" />

Benzer şekilde, API Proxy sayfasından DB-2-API sayfasına gitmek için aşağıdaki gibi API Proxy'deki DB-2-API ismine tıklayarak gidilir.

<img src="/images/develop/api-proxy-olusturma/db-api-geri-link.png" alt="API Proxy'den DB-2-API'ye link" width="600" />

## DB-2-API Silme

Bir DB-2-API silindiğinde ona bağlı olan tüm API Proxy'ler önce kaldırılır (Undeploy) sonra silinir.
