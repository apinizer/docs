Apinizer ile var olan bir API'yi ya da web servisini Backend API olarak kullanıp önüne bir API Proxy koyabilir, ya da backend olmadan bir API Proxy oluşturup API olarak sunabilirsiniz. API Proxy, beş adımlı bir sihirbazla oluşturulur:

| Adım | Ne yapılır |
|------|------------|
| [1. Proxy tipi](#1-proxy-tipi) | Proxy tipini seçin ya da tanım adresini yapıştırıp tipi Apinizer'ın bulmasına bırakın. |
| [2. Tanım / Backend](#2-tanim-backend) | Tanım belgesini URL, dosya veya API Spec ile verin ya da backend adresini girin. |
| [3. Genel](#3-genel) | Ad, açıklama, sürüm, kategori, kullanım şekli ve paylaşım tipini girin. |
| [4. İstemci yolu](#4-istemci-yolu) | İstemcilerin proxy'ye hangi path, metot, host veya header ile ulaşacağını belirleyin. |
| [5. Özet](#5-ozet) | Girdiklerinizi kontrol edin ve kaydedin. |

Sihirbazı açmak için ana menüde **API Gateway → API Proxy'ler** _(API Gateway → API Proxies)_ sayfasına gidin ve sağ üstteki **Yeni** _(Create)_ düğmesine tıklayın.

Sihirbazın üstündeki adım çubuğu nerede olduğunuzu gösterir. Tamamlanan adımlar onay işaretiyle işaretlenir. Bir adımın zorunlu alanları dolmadan **İleri** _(Next)_ düğmesi açılmaz ve sonraki adımlara geçilemez. Tamamlanan adımlara adım çubuğundan geri dönebilirsiniz. 2. adımdan itibaren sağda, seçtiğiniz tipi, istemci → proxy → backend akışını ve girdiğiniz değerlerin özetini gösteren bir panel görünür.

:::info Hızlı Başlangıç

Aynı akışı örnek bir API üzerinden adım adım görmek için [Hızlı Başlangıç](/tr/develop/quick-start) sayfasına bakın. Bu sayfa her adımdaki alanları ayrıntılı anlatır.

:::

## 1. Proxy tipi {#1-proxy-tipi}

<img
  src="/images/develop/api-proxy-olusturma/create-wizard-1-type.png"
  alt="Sihirbazın 1. adımı: tanım adresi alanı ve proxy tipi kartları"
  width="1000"
/>

Adımın üstünde bir **algılama alanı** bulunur. Bir tanım URL'si ya da backend adresi yapıştırıp **Ayrıştır** _(Parse)_ düğmesine tıklarsanız (veya Enter'a basarsanız) Apinizer tipi kendisi seçer ve sizi doğrudan 2. adıma götürür. Aynı alana tanım dosyası sürükleyip bırakabilir, **Dosya Yükle** _(Upload File)_ ile dosya seçebilir ya da **API Tanım Belgesi Seç** _(Select API Spec)_ ile kayıtlı bir tanımı kullanabilirsiniz. Tanınan biçimler: OpenAPI / Swagger, WSDL, `.proto`, `ws://` / `wss://` ve `http(s)://` backend adresi. Dosya olarak `.json`, `.yaml`, `.wsdl`, `.xml`, `.proto` ve `.zip` kabul edilir.

Tipi kendiniz seçmek isterseniz alttaki kartlardan birine tıklayıp **İleri**'ye basın. Karta çift tıklamak da sonraki adıma geçirir.

| Tip | Açıklama |
|-----|----------|
| **OpenAPI'den REST API** | Swagger 2.x veya OpenAPI 3.x tanımından REST API Proxy oluşturur. Tanımı URL ile, dosya yükleyerek ya da bir API Spec seçerek verirsiniz. Endpoint'ler ve yönlendirme adresleri tanımdan okunur. Ayrıntılar için [Swagger 2.0](https://swagger.io/docs/specification/2-0/what-is-swagger/) ve [OpenAPI](https://swagger.io/docs/specification/about/) belgelerine bakın. |
| **WSDL'den SOAP API** | [WSDL](https://en.wikipedia.org/wiki/Web_Services_Description_Language) ile tanımlanmış hedef servis için SOAP proxy oluşturur (SOAP 1.1 / 1.2). Operasyonlar ve servis adresleri WSDL'den okunur. Ayrıntılar: [SOAP API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/soap-api-proxy-olusturma). |
| **WSDL'den REST API** | WSDL ile tanımlanmış hedef servis için REST proxy oluşturur. İstemciler REST (JSON) ile çağırır, Apinizer SOAP backend'i çağırır. Ayrıntılar: [SOAP-REST API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/soaprest-api-proxy-olusturma). |
| **gRPC API** | Gelen gRPC isteklerini backend gRPC sunucusuna iletir ve yanıtları istemciye döndürür. Proto dosyasını URL ile ya da dosya yükleyerek verirsiniz. Proto dosyası olmadan gRPC trafiğini iletmek için **Reverse Proxy** kaynağını seçin. Ayrıntılar: [gRPC API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/grpc-api-proxy-olusturma). |
| **No-Spec API** | Tanım dosyası olmayan, örneğin code-first geliştirilmiş bir API için kullanılır. Yönlendirme adreslerini sihirbazda girersiniz, endpoint'leri proxy oluşturulduktan sonra elle tanımlarsınız. Apinizer bu tanımlardan Swagger/OpenAPI tanım dosyasını kendisi üretir. |
| **Reverse Proxy** | HTTP / HTTPS reverse proxy oluşturur. Gelen istekleri, eşleşen bir endpoint olup olmadığına bakmadan backend'e iletir ve yanıtı istemciye döndürür. Tanım dosyası ya da endpoint tanımı gerekmez, backend'in kök adresi (root context) yeterlidir. |
| **WebSocket** | Backend WebSocket servisine Apinizer üzerinden erişmek için `ws://` / `wss://` proxy oluşturur. Ayrıntılar: [WebSocket API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/websocket-api-proxy-olusturma). |
| **Connector** | İstemcilerin çağırdığı REST API'yi bir connector'a bağlar. Böylece HTTP isteği Kafka, RabbitMQ, ActiveMQ, e-posta, Elasticsearch, FTP, Graylog, Syslog, Logback veya SNMP gibi başka bir hedefe dönüştürülür. Ayrıntılar: [Connector API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/connector-api-proxy-olusturma). |

:::note

Lisansınızda KPS varsa **KPS (SOAP Proxy)** ve **KPS (REST Proxy)** kartları da görünür.

:::

## 2. Tanım / Backend {#2-tanim-backend}

<img
  src="/images/develop/api-proxy-olusturma/create-wizard-2-specification.png"
  alt="Sihirbazın 2. adımı: tanım kaynağı, URL alanı ve yönlendirme adresleri"
  width="1000"
/>

Bu adımın adı seçtiğiniz tipe göre değişir. Tanım belgesi kullanan tiplerde **Tanım** _(Specification)_, diğerlerinde **Backend** olarak görünür. 1. adımda bir adres yapıştırdıysanız adımın üstünde Apinizer'ın neyi algıladığı yazar, örneğin "Algılandı: OpenAPI tanımı".

### Tanım tipleri: kaynak seçimi

OpenAPI, WSDL ve gRPC tiplerinde önce tanımın kaynağını seçin:

| Kaynak | Açıklama |
|--------|----------|
| **URL** | Tanım belgesine erişilen adresi girip **Ayrıştır** _(Parse)_ düğmesine tıklayın. Örnekler: `https://petstore.swagger.io/v2/swagger.json`, `http://www.dneonline.com/calculator.asmx?WSDL` |
| **Dosya Yükle** _(Upload File)_ | Tanım belgesi bilgisayarınızdaysa dosyayı yükleyip **Ayrıştır**'a tıklayın. |
| **API Spec** | [API Tanım Belgesi Editörü](/tr/develop/api-tasarimi/spec-designer) ile önceden oluşturulmuş bir tanımı **API Tanım Belgesi Seç** ile seçin. Yalnızca OpenAPI tipinde vardır. |
| **Reverse Proxy** | Yalnızca gRPC tipinde vardır. Proto dosyası olmadan gRPC trafiğini iletir. |

Bir tanımı URL'den veya dosyadan okumak için projede **API Management** veya **AI Development** kategorisinde **Manage** yetkisi gerekir. API Proxy'yi kaydetmek için ise **API Management** kategorisinde **Manage** yetkisi gerekir. Yetkisi olmayan istek HTTP 403 ile reddedilir.

Bir WSDL algılandığında **Oluşturma şekli** _(Create as)_ seçeneğiyle **SOAP API** ya da **REST API** seçebilirsiniz. WSDL tiplerinde ayrıştırmadan önce **Eğer WSDL'de varsa WS-A ayarını etkinleştir** ve **Eğer WSDL'de varsa WS-RM ayarını etkinleştir** kutuları görünür. Bu ayarlar ayrıştırma sırasında okunduğu için, gerekiyorsa **Ayrıştır**'dan önce işaretleyin.

Yapıştırdığınız `http(s)://` adresinin bir backend servisi mi yoksa bir OpenAPI tanımı mı olduğu anlaşılamazsa **Bu adres** _(This address is)_ seçeneği çıkar. **Bir backend servisi** ya da **Bir OpenAPI tanımı** seçeneğinden doğru olanı seçin.

### Spec Yetkilendirmesi

Bazı tanım dosyaları yalnızca kimliği doğrulanmış istemcilere açılır. Tanım URL'niz böyleyse, URL kaynağında **Ayrıştır**'dan önce **Spec Yetkilendirmesi Kullan** _(Use Spec Authorization)_ seçeneğini işaretleyin. **Temel Kimlik Doğrulama (İsteğe Bağlı)** alanları ve **Özel Başlık ve Sorgu Parametreleri** _(Custom Headers & Query Parameters)_ tablosu görünür. Seçenek Reverse Proxy ve WebSocket tiplerinde yoktur.

- **Temel Kimlik Doğrulama** _(Basic Authentication)_: **Kullanıcı Adı** ve **Şifre** girerseniz Apinizer `Authorization: Basic ...` başlığını kendisi oluşturur. Basic Auth ile korunan tanım adresleri için pratik bir kısayoldur.
- **Özel Başlık ve Sorgu Parametreleri**: Her satıra **Anahtar Adı**, **Değer** ve **Tip** girin. **Tip** `header` ise değer istek başlığı olarak, `query` ise URL'ye sorgu parametresi olarak eklenir. Başka değerler dikkate alınmaz.
- Basic Auth ve tablodaki başlıklar birlikte kullanılabilir. İkisi birleştirilerek gönderilir.
- Spec Yetkilendirmesi URL tabanlı tiplerde (OpenAPI, WSDL, gRPC) kullanılabilir. WSDL içe aktarmalarında (XSD import gibi) alt şema dosyaları da aynı yetkilendirme bilgileriyle indirilir. OpenAPI'de `$ref` ile başvurulan dosyalara yalnızca tablodaki satırlar gönderilir, Basic Auth gönderilmez.

### SSL / Sertifika Ayarları

Tanım URL'den alınırken kullanılacak güvenli bağlantı ve sertifika ayarları **SSL / Sertifika Ayarları** panelindedir. Panel, URL kaynağında ayrıştırmadan önce görünür ve açılıp kapatılabilir.

| Alan | Açıklama |
|------|----------|
| **Bağlantı Zaman Aşımı** _(Connection Timeout)_ | Tanım URL'sinin yanıtı için beklenecek en uzun süre, saniye cinsinden. Varsayılan 30 sn, aralık **5–120 sn**. |
| **SSL/TLS Ayarlarını Özelleştir** _(Customize SSL/TLS Settings)_ | Kapalıyken sistem varsayılanları (JVM **cacerts**) kullanılır. Açıkken **SSL Doğrulamayı Atla** seçeneği ve sunucu sertifikasını TrustStore veya PEM sertifikayla doğrulamak için **Sunucu Sertifika Doğrulama** bölümü görünür. |
| **SSL Doğrulamayı Atla** _(Skip SSL Verification)_ | **SSL/TLS Ayarlarını Özelleştir** açıkken görünür. Açıkken sunucu sertifikası doğrulanmaz ve **Sunucu Sertifika Doğrulama** bölümü gizlenir. Self-signed veya özel CA kullanılan ortamlar için uygundur. |
| **Sunucu Sertifika Doğrulama** _(Server Certificate Verification)_ | **SSL/TLS Ayarlarını Özelleştir** açıkken ve **SSL Doğrulamayı Atla** kapalıyken görünür. Seçenekler: **Sistem Varsayılan (JVM)** (varsayılan), **Truststore (Key Store kaydı)** ve **Sertifika (PEM)**. |

**Truststore (Key Store kaydı)** veya **Sertifika (PEM)** seçildiğinde **Mevcut Seç**, TrustStore **Yükle** (.jks, .p12, .pfx) ve şifre ya da **PEM Sertifika Yükle** (.pem, .crt, .cer) seçenekleri açılır.

:::tip

Yüklediğiniz TrustStore veya PEM dosyasını başka ekranlarda da kullanmak isterseniz **Keystore Havuzuna Ekle** (TrustStore için) veya **Sertifika Havuzuna Ekle** (PEM için) seçeneğini işaretleyip **Havuz İsmi** alanına bir ad verin. Bu seçenekler projede Secrets kategorisinde **Manage** yetkisi olan kullanıcılara görünür.

:::

:::info

Yeniden ayrıştırmada (reparse), oluşturma sırasında seçilen kayıtlı TrustStore veya sertifika ve **SSL Doğrulamayı Atla** seçimi önceden doldurulur. Tek seferlik yüklenen dosyalar, bağlantı zaman aşımı ve Spec Yetkilendirmesi saklanmaz, yeniden girilmelidir.

:::

:::warning

**Customize SSL/TLS Settings** açıkken seçilen SSL/TLS ayarları kullanılamazsa (bozuk dosya, yanlış parola, eksik kayıt) tanımın indirilmesi reddedilir. Kayıtlı TrustStore veya sertifika, mevcut projeye ya da Administration'a ait olmalı veya projesiz olmalıdır. Başka bir projenin kaydı, eksik kayıt gibi reddedilir. **Skip SSL Verification** açıkken kullanılamayan kayıt atlanır ve dosya sertifika kontrolü yapılmadan indirilir. API Proxy'yi başka bir projeye kopyalar veya taşırsanız yeniden ayrıştırmada eski projenin kaydı reddedilir (hata anahtarı `specDownload.sslContextFailed`). Bu durumda SSL/TLS seçimini yeniden yapın. Kayıtlı bir kayıt seçerek `POST /api/api-proxies/create-from-url` çağıran API istemcileri `projectId` göndermelidir. `projectId` göndermeyen System Admin, Administration kapsamını kullanır.

:::

### Yönlendirme adresleri

Tanım ayrıştırıldığında **Yönlendirme Adresleri** _(Routing Addresses)_ listesi tanımdan doldurulur. Bunlar backend API'nin erişim adresleridir. Kaydedilecek adresleri **Durum** kutusuyla seçin. İşaretlenmeyen adresler kaydedilmez. Adresleri satırda düzenleyebilir, **+** ile yeni adres ekleyip çöp kutusu simgesiyle silebilirsiniz. Yük dengeleme için birden fazla adres kullanılabilir.

Tanım kullanmayan tiplerde bu adımda backend bilgisini girersiniz:

- **No-Spec API**: Yönlendirme adreslerini elle ekleyin.
- **Reverse Proxy** ve **WebSocket**: Backend adresini girin.
- **Connector**: **+** düğmesiyle açılan pencerede connector tipini seçip yapılandırın.

**İleri** düğmesi; tanım ayrıştırıldıktan (ya da API Spec seçildikten) ve en az bir yönlendirme adresi seçildikten sonra açılır. Reverse Proxy'de backend adresi, Connector'da connector seçimi yeterlidir.

## 3. Genel {#3-genel}

<img
  src="/images/develop/api-proxy-olusturma/create-wizard-3-general.png"
  alt="Sihirbazın 3. adımı: ad, açıklama, sürüm, kategori, kullanım şekli ve paylaşım tipi"
  width="1000"
/>

| Alan | Açıklama |
|------|----------|
| **Adı** _(Name)_ | API Proxy'nin adı. Arayüzlerde bu ad görünür. Zorunludur ve benzersiz olmalıdır. Siz yazarken ad kontrol edilir ve alanın sağ üstünde adın kullanılabilir olup olmadığı görünür. Ad başka bir API Proxy'de kullanılıyorsa **İleri** düğmesi açılmaz. |
| **Açıklama** _(Description)_ | API Proxy'nin tanımı. |
| **Backend API Versiyon** _(Backend API Version)_ | API Proxy'ye tanımlanan Backend API'nin sürümü. |
| **Kategori Listesi** _(Category List)_ | API Proxy'leri yönetmeyi kolaylaştırmak için oluşturulan kategoriler. API Proxy'nin hangi kategorilere ait olduğunu belirler. |
| **Kullanım Şekli** _(Usage)_ | Backend API'nin kime ait olduğunu belirtir. Zorunludur. **Üretici** _(Publisher)_: Backend API firmanın/kurumun kendisine aittir. **Tüketici** _(Consumer)_: Backend API başka bir firmaya/kuruma aittir ve ona erişmek için proxy oluşturulur. **Üretici & Tüketici** _(Publisher & Consumer)_: Başka bir firmaya/kuruma ait Backend API için oluşturulan proxy, üçüncü taraflara da açılır. **Belirtilmemiş** _(Unspecified)_: varsayılan değerdir. |
| **Paylaşım Tipi** _(Sharing Type)_ | Backend API'nin nasıl paylaşılacağını belirtir. Zorunludur. Değerler: **Dış** _(External)_ (varsayılan), **İç** _(Internal)_, **Dış ve İç** _(External and Internal)_, **Belirtilmemiş** _(Unspecified)_. |

:::tip

Tanım ayrıştırıldıysa **Adı**, **Açıklama** ve **Backend API Versiyon** alanları tanımın başlığı, açıklaması ve sürümüyle önceden doldurulur. Örneğin petstore tanımında ad "Swagger Petstore", sürüm "1.0.7" olur. Bu değerleri değiştirebilirsiniz.

:::

## 4. İstemci yolu (Client Route) {#4-istemci-yolu}

<img
  src="/images/develop/api-proxy-olusturma/create-wizard-4-client-route.png"
  alt="Sihirbazın 4. adımı: relative path, metot, host ve header ile istemci yolu"
  width="1000"
/>

Client route, istemcilerin bu API Proxy'ye nasıl ulaşacağını belirler. En az bir relative path, metot, host veya header tanımlanmadan **İleri** düğmesi açılmaz.

**Uç nokta** _(Endpoint)_ bölümünde relative path'leri girersiniz. Hemen altındaki **Ortam başına uç nokta** _(Endpoint per environment)_ listesi, her ortamın erişim adresine path'inizi ekleyerek istemcilerin çağıracağı tam adresi gösterir.

| Alan | Açıklama |
|------|----------|
| **Relative Path'ler** _(Relative Paths)_ | API Proxy'nin erişim adresinin bir parçası. Gelen isteği doğru API Proxy'ye yönlendirmek için kullanılır. **Path ekle** _(Add a path)_ ile birden fazla path girilebilir. |
| **Metod'lar** _(Methods)_ | API Proxy'nin kabul ettiği HTTP metotları: GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS, QUERY. Hiçbiri seçilmezse her metot kabul edilir. |
| **Host'lar** _(Hosts)_ | İsteğin geldiği host adı. **Host ekle** _(Add a host)_ ile eklenir. Boş bırakılırsa her host kabul edilir. |
| **Header'lar** _(Headers)_ | İstekte bulunması gereken header adı ve değeri. **Header ekle** _(Add a header)_ ile eklenir. Boş bırakılırsa header koşulu yoktur. |

Metot, host ve header, isteğe bağlı **İstek eşleştirme** _(Request matching)_ bölümündedir. Bölüm açılıp kapatılabilir. Başlık satırında o anki seçimin özeti görünür, örneğin "Her metot · Her host · Başlık koşulu yok".

Örnek tam erişim adresi:

| Parça | Değer |
|-------|-------|
| Apinizer adresi | `https://demo.apinizer.com` |
| Ortam adresi | `/apigateway` |
| Relative path | `/petstoreProxy` |
| Endpoint | `/findByStatus` |
| **Tam erişim adresi** | `https://demo.apinizer.com/apigateway/petstoreProxy/findByStatus` |

Proje ayarlarında **Geçit Adresinin Durumu** _(Relative Path Status)_ açıksa projenin **Geçit Adresi** relative path alanının önünde gösterilir ve kaydedilirken path'e otomatik eklenir.

Aynı relative path'i kullanan proxy'ler host, header veya metotla ayrışmıyorsa çakışma oluşur.

:::note gRPC ve WebSocket

- **gRPC**: Relative path, proto dosyasındaki `/paketadi.servisadi` biçiminde olmalıdır. Apinizer bu değeri proto dosyasından önceden doldurur. Örneğin aşağıdaki proto için değer `/hello.HelloService` olur.

  ```proto
  syntax = "proto3";
  package hello;
  service HelloService {
  }
  ```

- **WebSocket**: Relative path'in nasıl girileceği için [WebSocket API Proxy Oluşturma](/tr/develop/api-proxy-olusturma/websocket-api-proxy-olusturma) sayfasına bakın.

:::

Ayrıntılı bilgi için [API Proxy Client Route Kullanım Kılavuzu](/tr/develop/api-proxy-olusturma/client-route-ayarlari) sayfasına bakın.

## 5. Özet {#5-ozet}

<img
  src="/images/develop/api-proxy-olusturma/create-wizard-5-review.png"
  alt="Sihirbazın 5. adımı: girilen bilgilerin özeti ve Kaydet düğmesi"
  width="1000"
/>

Son adımda girdiğiniz her şey dört bölümde listelenir: **Proxy tipi**, **Tanım** / **Backend**, **Genel** ve **Client Route**. Bir bölümü değiştirmek için yanındaki **Düzenle** _(Edit)_ düğmesine tıklayın, sihirbaz o adıma döner. Her şey doğruysa **Kaydet** _(Save)_ düğmesine tıklayın. API Proxy oluşturulur ve düzenleme sayfası açılır.
