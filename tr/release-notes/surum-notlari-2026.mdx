- ### Giden MCP ve A2A Bağlantılarında Arka Uç Kimlik Doğrulama Keşfi, API Key ve Token Exchange
MCP sunucu satırındaki, A2A ajan satırındaki ve MCP ile A2A çağrı politikalarındaki **Auth Keşfet** düğmesi hedefe hangi kimlik doğrulamanın gerektiğini sorar ve form değerlerini önerir. MCP sunucusu için korunan kaynak meta verisini (RFC 9728) ve yetkilendirme sunucusu meta verisini (RFC 8414 veya OpenID Connect) okur. A2A ajanı için Agent Card'daki güvenlik şemalarını okur. Formu kaydedene kadar hiçbir şey kaydedilmez. Yeni kimlik doğrulama şemaları eklendi: **API Key (Header)** anahtarı adını verdiğiniz bir header'da gönderir ve `Authorization` header'ı göndermez, **Basic Kimlik Doğrulama** kullanıcı adı ve parola gönderir, **OAuth2 Token Exchange (RFC 8693)** ise çağıranın doğrulanmış token'ını dış bir yetkilendirme sunucusunun token ucunda hedef için bir token ile değiştirir; böylece kullanıcı bağlamı arka uca ulaşır. Apinizer token servisi de token exchange grant'ını kabul eder. [MCP Gateway.](/tr/ai-gateway/mcp-gateway#arka-uc-kimlik-dogrulama) [A2A Gateway.](/tr/ai-gateway/a2a-gateway#giden-kimlik-dogrulama) APNZ-6889

- ### Tüketici Yönetim API'si
APIops (Management API) artık tüketiciler için `/apiops/projects/{projectName}/consumers`, tüketici organizasyonları için `/consumer-organizations` adresinde bir yazma yüzeyine sahiptir. Tüketici, kurulumun atadığı tüketici anahtarıyla adreslenir. Tüketici oluşturabilir, güncelleyebilir, silebilir, parolasını değiştirebilir, erişim verebilir ve geri alabilir, gizli materyal, JWK ve token ayarlarını bağlayabilirsiniz. Oluşturma `201` ve `Location` header'ı ile yanıtlanır. Güncelleme bir JSON Merge Patch'tir: göndermediğiniz alan kayıtlı değerini korur, boş liste veya boş metin alanı temizler, `"expireDate": null` son kullanma tarihini kaldırır. Kullanıcı adı ve tüketici anahtarı değişmez. Parola yalnızca parola değiştirme eylemiyle, organizasyon yalnızca taşıma eylemiyle değişir. Canlı bir kimlik kaynağının (LDAP, OIDC, veritabanı veya API senkronu) yönettiği tüketici düzenlenemez. Gizli değerler yalnızca yazılabilir. Organizasyon yazmaları gateway'e gönderme sonucunu `runtimeDeployment` içinde döndürür. [Bkz.](/api-reference/consumers) APNZ-7013

  - Etkinleştirme ve devre dışı bırakma eylemleri eklendi; kimlik kaynağının yönettiği tüketicilerde de çalışır.
  - Tüketici okuması artık `ipList`, `roleNames` ve `metadata` döndürür. Gizli metadata girdisi değeri olmadan gelir; bu nedenle listeyi güncellemede geri gönderirseniz, değeri yeniden göndermediğiniz sürece girdi boş kaydedilir. Yeni okumalar: `GET /token-settings` ve `GET /secrets` (başvurulan sertifika, anahtar, keystore ve JWK'nın adı ve kapsamı; materyalin kendisi hiçbir zaman dönmez).
  - Erişim satırları `expireTime`, `environments`, `disallowedEndpoints` ve `disallowedApiProxies` alanlarını taşır. Erişim verirken bu alanları gönderebilirsiniz. Yeni düzenleme işlemleri: `PUT /access/api-proxies/{apiProxyName}` ve `PUT /access/proxy-groups/{proxyGroupName}`.
  - Yeni `POST /actions/sync-match` eylemi, tüketiciyi kaynağın adıyla bir LDAP, veritabanı veya API kimlik kaynağı kullanıcısına bağlar. Tüketici senkron yönetimli olur.
  - Yeni `/consumer-roles` uç noktaları rolleri ada göre listeler, okur, oluşturur, günceller, yeniden adlandırır ve siler. Kullanımda olan bir rolü silmek `409` döndürür; `force=true` ile silme, rolü tüketicilerden, uygulamalardan ve API proxy yetkilendirme ayarlarından da kaldırır; ekran da aynısını yapar. `roleNameList` içindeki rol adı artık önce tüketicinin kendi projesinde, sonra admin projesinde çözülür; başka bir projenin rolü çözülmez. [Bkz.](/api-reference/consumer-roles) APNZ-7021

- ### Erişim Yalnızca ACL'de Tanımlanır; Tipli Erişim Modeli Kaldırıldı
Erişimin artık tek sahibi var: **Erişim Kontrolü** ekranındaki Erişim Kontrol Listesi (ACL) satırları. Erişim yetkileri (access entitlement) ve API istemcisi yetkilendirme kısıtları (Sahibini izle, Tümünü reddet, Alt kümeye izin ver) kaldırıldı; bunlar yalnızca ACL'nin bir kopyası olduğu için hiçbirinden veri taşınmadı. API istemcisinin **Yetkilendirme** sekmesi ile Erişim Kontrolü ekranındaki istemci mod, erişim ve kapsam rozetleri kaldırıldı. Erişim yetkisi REST uçları, API istemcisi kısıt uçları ve tüketici, uygulama ve API istemcilerindeki APIops `/entitlements` alt kaynakları kaldırıldı. [Bkz.](/tr/admin/identity-management/kimlik-bilgileri#api-istemcisinin-yetkilendirilmesi) APNZ-6985

Gateway, bir API istemcisini tek bir ACL sahibinin satırlarıyla yetkilendirir. Eski bir kimlik bilgisinden türetilmiş istemcide sahip, gateway o kimlik bilgisini hâlâ tanıdığı sürece o kimlik bilgisidir; diğer tüm istemcilerde istemcinin sahibidir (tüketici ya da uygulama). Kaynak kimlik bilgisinde satırı olmayan türetilmiş istemci HTTP 403 (`POLICY_AUTH_CREDENTIAL_PROXYNOTALLOWED`) ile reddedilir; artık uygulamasının satırlarına geri düşmez. Abonelik başlığı (`X-Apinizer-Subscription-Key`) yalnızca o sahibin satırları arasından seçim yapar. Sözleşmeler hem ACL sahibinde hem istemcinin sahibinde denetlenir; ikisinden biri sona ermişse istek reddedilir.

Onaylanan bir portal aboneliği artık her zaman ACL satırı yazar; kimlik bilgisi olmayan bir uygulama için de (satırlar uygulamanın kimliği altına yazılır). Abonelik iptali, hesap iptali, uygulama silme ve API ürünü silme bu satırları kaldırır ve gateway'lerden undeploy eder.

**Erişim Yetkilendirmesi** tipi Dışa/İçe Aktarma sihirbazından kaldırıldı. Hâlâ Erişim Yetkilendirmesi dosyaları içeren eski bir paket normal şekilde içe aktarılır: bu dosyaların her biri atlanır ve sonuçta bir uyarı görünür (`accessEntitlement.removed`; APIops içe aktarma yanıtında da döner). [Bkz.](/tr/admin/secrets-management/export-import)

- ### Context Window Kontrolü Routing'e Taşındı ve Modelin Değerini Kullanır
AI proxy'nin **Routing** sekmesindeki yeni **Context window taşması** kartı, model seçildikten sonra isteği kontrol eder. Sınır; modelin context window değeri eksi isteğin `max_tokens` değeri eksi 512 token güvenlik payıdır; yalnızca metin sayılır. **İsteği reddet** (varsayılan; seçim yapılmamış proxy'ler için de), **Konuşmayı kısalt** (en eski turlar silinir; istemcinin system mesajları ve son user mesajı korunur, yanıt `X-Apinizer-AI-Truncated` header'ı taşır) veya **Sağlayıcıya bırak** seçeneklerinden birini seçersiniz. Reddedilen istek sağlayıcıya ulaşmadan HTTP 400 (ERR-311) alır. Failover'da gövdeyi sığdıramayan aday atlanır. Context window değeri olmayan model kontrol edilmez. **Davranış değişikliği:** Token Rate Limit politikasından **Context Window Kaynağı** alanı kaldırıldı. Model Kataloğu kullanan proxy'ler artık varsayılan **İsteği reddet** davranışına geçer ve 429 (ERR-263) yerine 400 (ERR-311) döner. [Bkz.](/tr/ai-gateway/yonlendirme-failover#context-window-tasmasi) APNZ-7010
