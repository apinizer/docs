## Sürüm 2027.01.0

:::warning Yükseltmeden önce

- **Başka bir projenin DB-2-API, Script-2-API veya Mock API tanımına yönlenen API proxy artık kaydedilemez.** Bir API proxy yalnız kendi projesinin tanımına yönlenir. API proxy'yi kendi projenizin bir tanımından yeniden oluşturun veya **Replace Existing** ile içe aktarın. İçe aktarma, referansı kaldırır ve raporlar.
- **Metin ölçütlerinde "is equal to" ve "not equal" artık değerin tamamını karşılaştırır ve büyük/küçük harfi yok sayar.** Önceden değerin bir parçasını karşılaştırıyordu. Bu ölçütleri kullanan kayıtlı raporlar ve anomali dedektörleri farklı sonuç verebilir. Client IP "is equal to" ölçütü, 10.0.0.1 için artık 10.0.0.10 adresini getirmez. `*` joker karakteri eskisi gibi çalışır.
- **AI sayım alarmları, seçilen Period değerini arama penceresi olarak kullanır.** Bu kural PII tespiti, guardrail isabeti, sağlayıcı failover, kota soft-cap ve kota alarmları için geçerlidir: minute = 1 dakika, day = 24 saat, month = 30 gün. Mevcut alarmlar, Period değerini değiştirene kadar bir saatlik pencerelerini korur.
- **Alarm, Anomaly Detector, Uptime Monitor, Quota Alert, Task Flow ve Promotion aksiyon şablonlarında `${AD}` yalnız nesnenin projesindeki veya Administration projesindeki değişkene çözülür.** Başka bir projenin değişkeni yazıldığı gibi kalır. Rapor şablonu aynı kuralı izler.
- **Bir projenin Quota Alert tanımı yalnız kendi projesinin veya Administration kapsamının sayaçlarını değerlendirir ve bildirir.** Diğer projelerin sayaçları tanımı artık tetiklemez ve sayaç listesinde görünmez. Administration kapsamındaki Quota Alert tanımları değişmez.
- **Kayıtlı "Organization Based" ACL raporları organizasyon bazlı çalışır; bu nedenle düzenleri değişir.**
- **Trafik logundaki istek ve yanıt gövde boyutu alanları karakter yerine bayt sayar.**
- **Yükseltmeden sonra bir ortama eklenen bağlayıcı, siz açana kadar log yazmaz.** Trafik log ayarlarını açın, **Active for this environment** seçeneğini açın ve kaydedin. Yükseltme, mevcut bağlayıcılar için açık kayıtlar yazar. Bağlayıcı ayarlarının APIops ile güncellenmesi tüm bağlayıcı haritasının yerine geçer; listelemediğiniz bağlayıcılar log yazmayı bırakır. Önce Manager'ı yükseltin, migration'ın bitmesini bekleyin, sonra Gateway Engine örneklerini yeniden başlatın. [Bkz.](/tr/analytic/api-traffic-log-ayarlari)
- **"API Traffic Exist in Database" alarm tetikleyicisinin adı "Unsent Traffic Logs Exist in Database" olarak değişti.** Tetikleyici tipini kullanan bildirim metinleri yeni adı gösterir.

:::

- ### API Proxy Group Sayfasında Traffic Sekmesi
API Proxy Group sayfasında bir **Traffic** sekmesi bulunur. Sekme, grup üzerinden gelen istekleri API Proxy Traffic sekmesiyle aynı filtreler, kayıt ayrıntıları ve Excel dışa aktarımıyla listeler. [Bkz.](/tr/develop/api-proxy-group-olusturma) APNZ-4492

- ### Log Erişiminin Denetimi
Log aramaları, log kaydı görüntülemeleri ve log dışa aktarımları; kullanıcıyı ve bir filtre özetini içeren denetim olayı yazar. Kapsam: trafik, AI trafiği, denetim kayıtları, giriş ve token kayıtları, test konsolu denetimi, güvenlik olayları, uygulama logları, API ve AI trace'leri. DB-2-API **Try SQL** işlemi de denetlenir. v2 profilini kullanan SIEM hedefleri, bu kayıtların log tipini, filtrelerini, zaman aralığını, ortamını ve sonuç sayısını alır. [Bkz.](/tr/admin/system-settings/siem-log-yonlendirme) APNZ-4703

- ### Used By Paneli ve Silme Reddinde Kullanan Kayıtların Adları
Başka kayıtların kullandığı bir kayıt silinemez. Ret mesajı, kaydı kullananları adıyla belirtir: en fazla beş ad ve "ve N tane daha". Diğer projelerdeki kullanımlar sayılır. Bağlantılar (Kafka, Webhook ve diğer bağlantı tipleri dahil), LDAP ayarları, sertifikalar, key store'lar, kriptografik anahtarlar, bilgi tabanları ve IP grupları her kullanıma karşı denetlenir. Üst kayıtla birlikte silinen kayıtlar değişmez. Hâlâ kullanımda olan bir LLM modelini kaldırma isteği de aynı şekilde reddedilir ve kullananları adıyla belirtir. APNZ-7050

- ### Menüdeki Yeni Yerler
Yönetim > Kimlik > ACL Report, Yönetim > API Yönetişimi > Inventory Reports > ACL Report altına taşındı. Yönetim > Gateway Altyapısı > Route Analizi, Yönetim > API Yönetişimi > Route Analizi altına taşındı. Admin API Growth ve Endpoint Growth raporları Metrikler sekmelerinden Yönetim > API Yönetişimi > Inventory Reports altına taşındı; eski yer imleri yönlendirilir. API Growth liste görünümü kaldırıldı; liste Yönetim > API Yönetişimi > API Proxies altındadır. API Yönetişimi ayrıca tüm projelerin API Proxy, Proxy Group, Global Policy, Integration ve API Creator kayıtlarını; AI Yönetişimi ise LLM Gateway, MCP Gateway ve A2A Gateway listelerini salt okunur gösterir. Bir projenin ACL Report sayfası Kimlik altında kalır.

- ### HTML Tablolu Rapor E-postası
`{{report.resultTable}}` değişkeni, raporun ilk 25 satırını e-postaya HTML tablo olarak ekler; her rapor tipi için çalışır. Metrik raporları Total satırını ekler. [Bkz.](/tr/monitor/alarm) APNZ-7030

- ### Provider Health: İlk Token Süresi
Provider Health, son 24 saat için sağlayıcı başına TTFT p50/p95 değerlerini gösterir. Hücre, en çok streaming isteği alan ortamın gerçek değerlerini ortam adıyla gösterir. Bir ipucu, her ortamın değerlerini listeler; birleşik değer yoktur. LLM Gateway **Least Latency** yük dengeleme, streaming isteklerin ilk token süresini kullanabilir. Metrics › AI › Performance, model başına TTFT p50 · p95 değerlerini gösterir; trace süre çubuğu ilk token'ı işaretler. İsteğe bağlı streaming sağlık kontrolü varsayılan olarak kapalıdır, LLM token'ı harcar ve her zamanlanmış kontrolde ilk token süresini kaydeder. [Bkz.](/tr/ai-gateway/raporlar) APNZ-6901

- ### MongoDB Disk Percentage Alarmı
Alarmlara **MongoDB Disk Percentage** tetikleyicisi eklendi. Apinizer'ın MongoDB verisini tutan dosya sisteminin doluluğu bir yüzde eşiğini aştığında tetiklenir. Bir mongos üzerinden shard başına bir satır verir. [Bkz.](/tr/monitor/alarm) APNZ-1634

- ### ACL Report: Engellenen Endpoint'ler ve İstek Sayıları
ACL Report, bir consumer'ın engellendiği endpoint'leri listeleyebilir. Seçilen ortam ve dönem için her consumer'ın endpoint başına istek sayısını tabloda ve Excel'de gösterebilir. Access Control diyalogları tüm endpoint'lere tek seferde izin verebilir veya hepsini engelleyebilir. Yeniden ayrıştırma (re-parse), erişimi olan consumer'lar için yeni endpoint'leri engelli tutabilir. Zamanlanmış ACL raporları **Endpoints** filtresini ve **Requests** sütununu sunar. İstek sayılı bir ACL raporu, kaydederken bir ortam ve bir filtre tarih aralığı ister. [Bkz.](/tr/admin/identity-management/acl-raporu) APNZ-5799 APNZ-6441 APNZ-6387

- ### Manager, Integration ve Cache Çağrıları için OpenTelemetry Dışa Aktarımı
Manager ve Integration, trace ve metrikleri OTLP ile dışa aktarabilir. `APINIZER_OTEL_ENVIRONMENT` değişkenini, OpenTelemetry ayarlarını izleyecekleri ortama ayarlayın. REST istekleri, zamanlanmış işler ve adımlarıyla task flow çalıştırmaları kendi instrumentation scope'ları altında (`com.apinizer.manager`, `com.apinizer.integration`) span olarak görünür. Native OTLP dışa aktarımı, gateway'in Cache'e yaptığı her çağrı için bir client span kaydeder (işlem, cache adı, sonuç; anahtar ve değer asla). Asenkron politikaların ve A2A/MCP arka plan görevlerinin Cache çağrıları isteğin trace'i altında görünür. Cache metrikleri, collector'ın `prometheus` receiver'ı ile `:9091/metrics` adresinden toplanır. [Bkz.](/tr/develop/izleme-analiz/opentelemetry-disa-aktarimi) APNZ-6535

- ### Rapor ve Dashboard Ekranlarında Tek Arama Kuralı
Rapor ve dashboard ekranları açılışta kısa bir varsayılanla bir kez çalışır. Sonrasında sonuçlar yalnız **Search**'e bastığınızda değişir ve çubuk, uygulanmamış kaç değişiklik olduğunu gösterir. Endpoints ve Consumers with No Requests ekranları yalnız Search'ten sonra çalışır. API Growth ve Endpoint Growth, son 30 gün ve Daily aralıkla açılır. APNZ-6999

- ### Growth Raporlarında Routing Adresine Göre Gruplama
API Growth ve Endpoint Growth, sayıları routing adresine göre gruplayabilir: backend host, LLM sağlayıcı veya MCP/A2A sunucusu. API Growth Excel dosyası aynı gruplamayı kullanır. API Proxy Groups listesinin Excel dosyasında, her grubun dağıtıldığı ortamları gösteren bir **Environment** sütunu vardır. APNZ-4314 APNZ-5186

- ### Report Generator Dışa Aktarım Sınırı
Report Generator Export, sabit 25 MB yerine **Email Attachment Max Size** ayarını izler ve hata, ayarlanan boyutu gösterir. APNZ-4427

- ### Integration için İsteğe Bağlı Tetikleyici
Bir integration'ın tetikleyicisi isteğe bağlıdır. Integration'ı yalnız Execute ile veya endpoint'i üzerinden çalıştırmak için **Run on schedule** seçeneğini kapatın. APNZ-4660

- ### Integration Sunucu Durumu
Integration sunucu durumu **Reachable**, **Not Reachable** veya **Not configured** olarak görünür; detay sayfası durumu açıklar. APNZ-3686

- ### Application Logs İndirme
İndirme için en fazla 7 günlük bir zaman aralığı gerekir ve en fazla 100.000 kayıt içerir. Daha büyük sonuç kesilir ve ekran bunu belirtir. [Bkz.](/tr/admin/audit-compliance/application-logs)

- ### Bildirim Tarih Formatı ve Kaynağı
Bildirim tarih değişkenlerinin (alarm, anomali, uptime, rapor, promotion) tarih formatını System Settings'ten seçebilirsiniz. Varsayılan `yyyy-MM-dd HH:mm:ss` olarak kalır. Her uygulama içi bildirim kaynağını kaydeder (Alert, Anomaly Detector, Uptime Monitor, Quota Alert, Report, Task Flow, Promotion). Notifications sayfası kaynağa göre filtreleyebilir ve Excel'e aktarabilir. APNZ-3913 APNZ-6081

- ### Seçili Proxy ve Gruplar için Quota Alert
Bir Quota Alert, seçili API proxy'lerle veya proxy gruplarıyla sınırlanabilir; böylece yalnız onların kota sayaçları değerlendirilir. Aksiyon editörü, alarmın doldurduğu `{{quota.alert.*}}` değişkenlerini listeler. APNZ-3894

- ### Queries Satır Menüsü
Kayıtlı bir sorgunun satır menüsü, sorguyu kullanabilen izleme özellikleri için **With this query** aksiyonlarını sunar. APNZ-3605

- ### APIops ile Report Generator Raporu Çalıştırma
APIops artık bir Report Generator raporunu adıyla çalıştırabilir ve başlıklarını, satırlarını ve Total satırını JSON olarak alabilir. [Bkz.](/api-reference/reports/run-report-configuration) APNZ-6064

- ### APIops Proxy Raporu
APIops API proxy raporu, her proxy'nin oluşturulma tipini gösterir ve Reverse Proxy kayıtlarını işaretler. Her grubun üye proxy'lerini adıyla listeler. Spec'i gizli olan bir proxy artık spec URL'lerini göstermez. APNZ-3560

- ### status_code ve Grup Etiketli Prometheus Metrikleri
`apinizer_api_traffic_error_count_tagged` sayacı, istemciye gönderilen HTTP durumunu taşıyan bir `status_code` etiketine sahiptir. 100–599 dışındaki değerler "other" olarak raporlanır. İstek ve yanıt gövde boyutu metrikleri (`apinizer_api_traffic_request_size`, `apinizer_api_traffic_response_size`) bayt raporlar. Toplama yapmayan bir seçici, proxy, grup ve durum kodu başına bir seri döndürür; bu yüzden `sum by (...)` ile toplayın. `:9091` üzerindeki metrik uç noktasında kimlik doğrulama yoktur. [Bkz.](/tr/operations/yonetici-kilavuzlari/gateway-metrics-entegrasyonu/gateway-metrics-genel-bakis) APNZ-5172 APNZ-5173 APNZ-5977

- ### AI OTLP Trace'i Routing Kararını Gösterir
Bir AI isteğinin OTLP trace'i, koşullu route kararını da gösterir. Trace ağacı, içerik yazmama kuralı ve ulaşılamayan collector davranışı gerçek bir collector'a karşı doğrulandı. APNZ-6903

- ### Elasticsearch Hataları ve Devre Dışı Bağlantılar
Dashboard, metrik, portal analitiği ve AI raporları, Elasticsearch hata ile yanıt verdiğinde "veri yok" veya sıfır yerine Elasticsearch hatası gösterir. Bir log bağlantısı devre dışıyken, onu kullanan okumalar "Elasticsearch connection disabled" döndürür. Bir bağlantıyı APIops ile devre dışı bırakmak raporlarda hemen etkili olur. Birkaç ortamın paylaştığı bir connector artık iki kez sayılmaz.

- ### Anomaly Detector ve Uptime Monitor
SUM tabanlı anomali koşulları sıfır trafiği No Data sayar; "below X" SUM dedektörleri, dedektör veri yokluğunda bildirim yapacak şekilde ayarlanmadıkça sıfır trafikte sessiz kalır. Uptime kontrol saklama süresi, günlük özet çalışana kadar bugünün kontrollerini tutar ve son 24 saatin kontrollerini asla silmez. Özeti başarısız olan bir monitör son 120 günün kontrollerini tutar. Uptime logları, sonuçları ve bildirimleri hedef URL'yi kullanıcı adı, parola ve sorgu değerleri maskelenmiş olarak gösterir; bildirim şablonlarındaki `${monitor.uptime.targetUrl}` dahildir.

- ### Raporlar ve Filtreler
Bir projenin raporu; önizleme, hemen çalıştırma, dışa aktarma ve zamanlamada yalnız o projeyi okur. Route Conflict ve ACL Audit raporları raporun projesiyle sınırlıdır. Bir rapor veya anomali dedektörü yalnız kendi projesinin veya Administration projesinin sorgusunu ya da filtresini bağlayabilir. Zamanlanmış işi kaybolan raporlar **Not scheduled** gösterir. APIops kayıtlı sorgu sonuçları, toplam süresi olmayan kayıt için `totalMs` alanını dışarıda bırakır; Manager böyle kayıtlar için Cache Hit "Unknown" ve gecikme "-" gösterir.

- ### Yetkiler
Analyzer rolü, tüm projelerin Uptime ve Anomaly sonuçlarını okumaya devam eder; ancak bunları, alarm geçmişini, rapor sonuçlarını ve API proxy trace'lerini silemez. Bunları silmek için sistem yöneticisi olmak veya projede ilgili özelliğin manage yetkisine sahip olmak gerekir. Bir raporu silmek için sistem yöneticisi olmak veya raporun projesinde ANALYTICS manage yetkisine sahip olmak gerekir. Global policy silme, silmeden önce yetkiyi denetler. APNZ-7049

- ### DB-2-API, Script-2-API ve Mock API Güvenliği
DB-2-API Try SQL ve API proxy trace kayıtları, tanımın veya proxy'nin proje yetkisini ister. Try SQL yalnız projenin veya Administration'ın havuzlarında çalışır. DB-2-API tanımları, APIops ve içe aktarma dahil her kaydetme yolunda yalnız kendi projesinin veya Administration'ın havuzlarını kullanır. DB-2-API, Script-2-API veya Mock API kaydetmek projesini korur ve yalnız o projenin API proxy'lerini değiştirir. Bir API proxy yalnız kendi projesinin tanımına yönlenir; içe aktarmada diğer referanslar kaldırılır ve raporlanır. APIops promotion, başka bir projenin API proxy'sini veya proxy grubunu ezmez ya da taşımaz. Bir kaydetme kuralı değişikliği reddettiğinde APIops API proxy güncelleme uç noktaları 500 yerine 400 döndürür. Try SQL denetim kaydı, düzenlenmiş SQL metnini ve veritabanı hata metnini saklamaz.

- ### Kullanımdaki Bağlantılar Silinemez
Bir ortamın kullandığı bağlantı (Elasticsearch, Graylog, Syslog, Kafka, RabbitMQ, ActiveMQ, Logback, Webhook, FTP) artık silinemez. Bir alarm, monitör, rapor, integration, portal, veritabanı kimlik doğrulaması veya log ayarının kullandığı Email, SNMP, Linux Script veya DB pool bağlantısı da silinemez. APIops silme aynı kuralı izler. APNZ-7050

- ### Dashboard Aktif Alarmlar Kartı
Manager bir izleme motorunun sonuçlarını okuyamadığında, aktif alarmlar kartı diğer motorları gösterir ve başarısız olanı adıyla belirtir. Monitör listeleri boş liste yerine hata gösterir.

- ### Tarih Aralıksız Kullanıcı Denetimi
Tarih aralığı olmayan bir kullanıcı denetimi listesi veya Excel'i, her kaydı değil, filtreler uygulanmış son bir saati döndürür.

- ### Assertion'sız Uptime
Assertion'ı olmayan bir Uptime monitörü, erişilemeyen hedef için Down bildirir.
