## Sürüm 2027.01.0

<span style={{ display: 'inline-block', backgroundColor: '#86efac', color: '#056d4f', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>YENİ ÖZELLİKLER</span>

- ### WebSocket API Proxy Socket.IO İstemcilerini Taşır
WebSocket API proxy artık Socket.IO istemcilerinin HTTP long-polling isteklerini taşıyabilir. Proxy'nin bağlantı ayarlarında **Socket.IO Uyumluluğu** seçeneğini seçin ve **Okuma Zaman Aşımı** değerini girin. Polling isteğinde istek ve yanıt politikaları, Rate Limit Control List ve Limit Planı çalışır. Backend Socket.IO oturumunu doğruladıktan sonra heartbeat çerçeveleri artık tek tek trafik kaydı yazmaz. Bağlantıyı kapatan kayıt bir heartbeat özeti taşır. APIops WebSocket ayarları çağrısında yeni `socketIoEnabled` alanı vardır. [Bkz.](/tr/develop/yonlendirme/websocket-yonlendirme#socketio-uyumlulugu) APNZ-6140

<span style={{ display: 'inline-block', backgroundColor: '#bfdbfe', color: '#1e40af', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>DEĞİŞİKLİKLER VE İYİLEŞTİRMELER</span>

- ### Politika ve Routing Sırları Şifreli Saklanır
API Manager artık API proxy'nin politikalarındaki ve routing'indeki sırları, politika gruplarının, proxy gruplarının ve global politikaların sırlarını şifreli saklar. Sırrı hangi kayıt getirirse getirsin kural aynıdır: editör, APIops promotion ya da içe aktarma paketi. Yükseltme, önceki sürümlerin yazıldığı gibi sakladığı değerleri şifreler. Kaydedilen API proxy'yi yanıt olarak dönen bazı kayıt işlemlerinde, istekle yazıldığı gibi gelen sır artık yanıtta şifreli görünür. API proxy kaydı, AI proxy olmayan bir API proxy'nin REST to SOAP metot kopyasındaki AI politikasını artık reddeder. APIops ve REST yanıtları, bir değerin çözülmüş kopyasını tutan alanları (örneğin başlık değerinin çözülmüş hâli) artık taşımaz. Yükseltmeden önce yükseltme notlarını okuyun. [Bkz.](/tr/upgrade/apinizer-surum-yukseltme) APNZ-7186

- ### Test Konsolu Geçmişi İsteği Yazıldığı Gibi Saklar
Test Konsolu Geçmişi, Test Konsol Denetim Kayıtları ve denetim kaydı isteği artık yazdığınız gibi saklar; `${NAME}` başvurusu başvuru olarak kalır. Gönderilen istek önceki gibi çözülür. Gönder, kod parçacığı, JOSE anahtar testi ve Uptime Monitor değişkenleri yalnız çağıranın projesinden (Uptime için monitörün projesinden) ve Yönetim projesinden çözer. Bu sürümden önce kaydedilen Geçmiş kayıtları değişmez. [Bkz.](/tr/develop/test-debug-araclari/test-console#geçmiş) APNZ-7186

- ### URL'sinde Değişken Olan Test veya Kontrolün Hata Metni
URL'sinde değişken olan bir Test Konsolu isteği ya da Uptime Monitor kontrolü hedefe ulaşmazsa geçmiş, Manager logu, Uptime sonuç geçmişi, sonuç dışa aktarımı ve bildirim artık yalnız hata türünün adını taşır; örneğin `UnknownHostException`. Test Konsolu ekranı hatanın tamamını göstermeye devam eder. Değişkensiz URL değişmez. [Bkz.](/tr/monitor/api-saglik-kontrolu) APNZ-7186

- ### Kod Parçacığı SOAPAction Taşır
SOAP metodu seçtiğinizde Test Konsolu kod parçacığı artık SOAPAction bilgisini taşır (SOAP 1.1 için `SOAPAction` başlığı, SOAP 1.2 için `Content-Type` başlığındaki action). Ekrandan kaydedilen test artık API proxy metodunun test listesinde görünür. [Bkz.](/tr/develop/test-debug-araclari/test-console#code-snippet) APNZ-7186

- ### Gizli Değer Taşıyan Kaydı Kopyalamak Okuma Yetkisi İster
Paylaşılan bir kaydı okuma yetkisi olmayan kullanıcı, kayıt gizli değer taşıyabilen bir değer içeriyorsa kaydı kopyalayamaz. Bu kural Uptime monitörleri, Anomaly Detector'lar, Task Flow'lar, e-posta bağlantıları ve Mock API'ler için geçerlidir. Hata anahtarı `duplicate.secretNotReadable` olur. APNZ-7186

- ### Politika Editörleri Akışa Döner, Global Politika Penceresi Kaldırıldı
Akıştan açılmamış bir politika editörü URL'si artık, tarayıcının Geri ve İleri düğmeleriyle de, akışa döner. API proxy içindeki "global politika değişti" penceresi, politika formundaki **Select From Global Policies** bağlantısı ve gömülü global politika listesinin **Geri** düğmeleri kaldırıldı. Global politikayı **Add Policy** ile ekleyin. Global politika proxy içinde salt okunur açılır. APNZ-7191

<span style={{ display: 'inline-block', backgroundColor: '#e65a2a', color: '#ffffff', padding: '0.25rem 0.75rem', borderRadius: '9999px', fontSize: '0.875rem', fontWeight: '500' }}>HATA DÜZELTMELERİ</span>

- ### WebSocket API Proxy Düzeltmeleri
WebSocket API proxy'de başarılı backend bağlantısı (HTTP 101) artık Başarılı olarak kaydedilir; bu yüzden panoların ve raporların hata sayısı her bağlantı için bir azalır. Yükseltme içermeyen istek artık 500 yerine HTTP 404 ve `ERR-006` alır. Root context ve birden çok relative path varken eşleşen en uzun yol, REST API proxy'deki gibi kesilir. Yoldaki ve routing adresindeki kaçışlı karakterler (örneğin `%2F`, `%20`, `%25`) ile sorgu, backend'e gönderildiği gibi ulaşır. Backend bağlantıyı kapattığında backend tarafının kapanış kaydı yoğun log yükünde de korunur. [Bkz.](/tr/develop/yonlendirme/websocket-yonlendirme) APNZ-6140

- ### DB-2-API SQL ARRAY Kolonunu JSON Dizisi Olarak Yanıtlar
Sonucunda SQL ARRAY kolonu olan bir DB-2-API isteği artık JSON dizisi döner. Satırlardan oluşan dizi satır olarak yazılır; yanıt gövdesi artık boş kalmaz. NULL REF_CURSOR kolonu `null` yazılır. JSON olarak yazılamayan yanıt artık boş HTTP 200 yerine, hatalı sorgunun metniyle HTTP 500 döner. APNZ-7244


- ### Worker SIGTERM'de 15 Saniye İçinde Sırayla Durur
Worker SIGTERM alınca artık 15 saniye içinde sırayla durur: çalışan isteklere 5 saniye verir, sonra tampondaki her log kaydı yazılır ya da SHUTDOWN sebebiyle kayıp sayılır. Bir özet satırı sonuçları bildirir. Cevap vermeyen konnektör ve temizlik kapanışları durmayı artık tutmaz. Kubernetes'te `terminationGracePeriodSeconds` ya da `preStop` bekleme süresini düşürürseniz aradaki farkı 15 saniye ya da daha fazla tutun. [Bkz.](/tr/integrations/konnektorler/genel-bakis) APNZ-7213

- ### API Portal Abonelikleri Erişimi Yalnız Onaylı Aboneliklerden Alır
API Portal'da tüketicinin erişim kuralları yalnız uygulamasının onaylı aboneliklerinden gelir. Portal kullanıcısı var olan bir aboneliği yalnız iptal edebilir; aboneliği onaylayamaz, başka bir ürüne veya plana taşıyamaz. Yeni abonelik organizasyonunu uygulamadan, hesabını oturum açan kullanıcıdan alır; bu nedenle onay bekleyen veya reddedilmiş organizasyon abone olamaz. API Manager'da yazılan erişim kuralları (sözleşme, tüketici yenileme) ve sözleşme dosyasının silinmesi, hedefin projesinde kullanıcının yetkisini ister. [Bkz.](/tr/api-portal/uygulama-promote) APNZ-7212

- ### Yazma Uçları Kayıtlı Kaydın Projesini Doğrular
Yetkiyi gövdedeki proje id'sine göre veren yazma uçları artık kayıtlı kaydın projesini kontrol eder. Başka projenin kaydının id'si gönderilirse HTTP 400 ve `projectidimmutable` döner. Kimlik erişim satırları (sayfa açıldıktan sonra silinen satır artık yeniden oluşturulmaz), task flow çalıştırma ve kimlik kaynağı testleri aynı kurala uyar. Yeni global WS-Security from target politikası arayüzde artık doğru oluşur (kaydetme artık `notfound` dönmez). [Bkz.](/tr/admin/user-access-management/yetkilendirme-matrisi) APNZ-7211

- ### Kaydın Projesi Güncelleme İsteğiyle Değiştirilemez
Güncelleme isteği artık bir kaydın projesini değiştiremez. Bu kural bağlantı ayarları, IP grupları, ortam değişkenleri, veritabanı ve API kimlik doğrulama kayıtları, sertifikalar, şifreleme anahtarları, key store, JWK, sözleşmeler, task flow'lar ve OIDC kimlik sağlayıcıları için geçerlidir. Başka projeye ait bir kaydı kendi proje id'si ile güncelleyen eski APIops veya REST entegrasyonları artık HTTP 400 ve `projectidimmutable` hatası alır. Kaydın projesini değiştirmek için **Global'e Taşı _(Move to Global)_** kullanın. [Bkz.](/tr/admin/user-access-management/yetkilendirme-matrisi) APNZ-7207

- ### Portal Proxy Client Secret Değerini Tarayıcıya Göndermez
API Portal artık proxy client secret değerini API spesifikasyonunda göndermez. MCP aracı `get_api_auth_info` artık `client_secret` döndürmez. Entegrasyonunuz bu değeri kullanıyorsa token'ı `get_token` ile alın. Secret gerektiren oturumsuz (anonim) Try It çağrısı artık HTTP 401 alır. API Portal'ı API Manager ile birlikte yükseltin. [Bkz.](/tr/api-portal/mcp-kullanimi/mcp-genel-bakis#token-ve-kimlik-doğrulama) APNZ-7209

- ### API Ürünü Dokümantasyonu API'lerden Üretilebilir, Try It Yalnızca Ürün Adreslerini Çağırır
API ürünü, portal dokümantasyonunu yüklenen dosya yerine API proxy'lerinden ve proxy gruplarından alabilir. Proxy değişince dokümantasyon güncellenir. Mevcut ürünler yüklenen dosyayı korur. Portal Try It konsolu artık yalnızca ürünün kendi gateway adreslerini çağırır ve yönlendirmeleri izlemez. API Portal'ı API Manager ile birlikte yükseltin. [Bkz.](/tr/api-portal/api-urunu#dokümantasyon-kaynağı) APNZ-7146

- ### Promotion Instance Uçları Sistem Yöneticisi veya Promotion Manager İster
Promotion instance uçları artık sistem yöneticisi veya Promotion Manager ister. Promotion sihirbazının seçim listeleri, herhangi bir projede PROMOTION yetkisi olan kullanıcılara açık kalır. Uzak proje ve API listeleri artık routing şifresi taşımaz. Çalıştırma detayı, işin kaynak projesinde PROMOTION Görüntüle yetkisi ister. [Bkz.](/tr/admin/api-promotion/genel-bakis#yetkilendirme) APNZ-7208

- ### URL ve Dosyadan İçe Aktarma ile Bağlantı Testleri İçin Yetki Gerekir
URL veya dosyadan spesifikasyon içe aktarma, Test Console'da URL'den içe aktarma, URL'den sertifika okuma ve Promotion instance bağlantı testi artık kullandıkları ekranın yetkisini ister. Bu yetkisi olmayan istek HTTP 403 alır. [Bkz.](/tr/develop/api-proxy-olusturma/api-proxy-olusturma) APNZ-7205

- ### Manager ve API Portal Girişi Beni Hatırla Değerini Yok Sayar
Manager ve API Portal girişi artık her token'a normal token geçerlilik süresini (`token-validity-in-seconds`) verir. `/api/authenticate` adresine `rememberMe: true` gönderen istemci bu süreyi alır ve hata almaz. Yükseltmeden önce verilen token'lar özgün bitiş süresini korur, en çok 30 gün. Yenileme bu süreyi uzatmaz ve kısaltmaz. `token-validity-in-seconds-for-remember-me` yapılandırma anahtarı hâlâ kabul edilir ve yok sayılır; eski yapılandırmalar açılmaya devam eder. APNZ-7204

- ### XML'den JSON'a Dönüşümde Dizi Yolları Düzeltildi
`root#liste#aciklama` gibi bir dizi yolu, yolun son elemanını artık tekrar eden her üst elemanın altında ve her derinlikte JSON dizisine dönüştürür. Önceden üst eleman iki veya daha çok kez tekrar ettiğinde eleman tekil değer olarak kalıyordu. Bu düzeltme REST to SOAP yanıt dönüşümünü, XML Dönüştürme politikasını, Redaction'ı, İş Kuralı politikalarını ve XML dönüşüm test aracını kapsar. [Bkz.](/tr/develop/politikalar/xml-donusturme) APNZ-7171

- ### Portal Test Ekranı ve MCP Token Aracı Çalışmayacak Token İsteklerini Reddeder
Bazı token politikaları token'ı uygulama credential'ına değil, yalnızca API'nin kendi istemcisine verir. Bu durum kendi anahtarlarını yöneten OAuth2 politikası için geçerlidir. Anahtarlarını portalın yayımlamadığı JWT politikası için de geçerlidir. Bu API'lerde portal test ekranı artık **Authorize** düğmesini devre dışı bırakır ve bir ipucu gösterir. MCP aracı `get_token` isteği reddeder. `get_api_auth_info` portalın token alamadığını belirtir. Portal ağ geçidine hiçbir istek göndermez. [Bkz.](/tr/api-portal/api-urunu) APNZ-6092


- ### API Portal Angular 22 Sürümüne Yükseltildi, CVE-2026-88059 Kapatıldı
API Portal artık Angular 22.2.3 üzerinde çalışır. Bu yükseltme, bir güvenlik taramasının API Portal için bildirdiği CVE-2026-88059 zafiyetini kapatır. Düzeltme Angular 22.1.1 ve sonrasındaki sürümlerdedir. API Portal sunucu tarafı render kullanmaz; bu nedenle sunucu tarafı render önbellek sorunu yükseltmeden önce de istismar edilemezdi. APNZ-6932
