Bu sayfa listelenmemiştir (unlisted) — sidebar'da ve arama sonuçlarında görünmez, yalnızca 2027.01.0 sürüm notlarındaki ve log tablosu sayfalarındaki doğrudan bağlantı üzerinden erişilmek üzere tasarlanmıştır.

## Kimler ihtiyaç duyar

Bu script yalnızca kurulumunuzun bir log connector'ının — ortam log connector'ı veya SIEM hedefi — **failover connector** olarak SQL/JDBC connector'ı üzerinden **ilişkisel bir veritabanı** (Oracle, MySQL, PostgreSQL veya SQL Server) kullandığı durumu ilgilendirir.

**Failover connector olarak MongoDB kullanıyorsanız bu sayfayı tamamen atlayın.** Manager, MongoDB üzerinde indeksi otomatik oluşturur.

## Ne değişti

Apinizer 2027.01.0, bir connector'ın gönderemediği her kayıtla birlikte kayıt tipini saklar. [Gönderilmemiş Logları Taşı](/tr/analytic/gonderilmemis-api-trafik-loglari-tasima) ekranı ve alarm, kayıtları seçmek için bu tipi kullanır.

**`log_UnsentMessage` bir yeni kolon alır:**

- `log_type` — gönderilemeyen kaydın tipi (API trafik, policy capture, token, denetim vb.).

Kolon nullable'dır. Yükseltme öncesi yazılan kayıtlarda `log_type` boş kalır. Gönderilmemiş Logları Taşı ekranı bu kayıtları **Tipi bilinmiyor** olarak gösterir ve diğer tipler gibi taşır.

Script ayrıca önerilen `(connector_id, log_type)` indeksini oluşturur. Alarm ve Gönderilmemiş Logları Taşı ekranı tabloyu connector ve tip bazında okur.

:::warning Script'i yükseltmeden ÖNCE çalıştırın

Gateway her failover insert işleminde `log_type` kolonunu yazar. Kolon eksikse **her failover insert işlemi başarısız olur**. Birincil hedef çalışmadığında log kayıtları kaybolur. Script'i gateway'i 2027.01.0 sürümüne yükseltmeden **önce** çalıştırın.

:::

## Ne zaman çalıştırılmalı

Bu script'i bir log connector'ının her failover veritabanına karşı 2027.01.0 sürümüne yükseltmeden önce **bir kez** çalıştırın; bakım penceresi gerektirmez. Kolon nullable olduğu için yükseltme öncesi satırları yazmaya devam eden eski gateway worker'ları etkilenmez. DDL için bir değişiklik yönetimi süreciniz varsa önce production dışı bir ortamda deneyin.

:::warning Bu script'i iki kez çalıştırmayın

Var olan bir kolonu eklemek hata verir. Tabloyu 2027.01.0 sürümünün [Apinizer Log Tabloları Oluşturma Komutları](/tr/operations/yonetici-kilavuzlari/apinizer-log-tablolari-olusturma-komutlari) sayfasındaki `CREATE TABLE` komutlarıyla oluşturduysanız tabloda bu kolon zaten vardır; bu script'i çalıştırmanız gerekmez.

:::

## Oracle

```sql
ALTER TABLE log_UnsentMessage ADD (log_type VARCHAR2(50));
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## PostgreSQL

```sql
ALTER TABLE log_UnsentMessage ADD COLUMN log_type VARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## MySQL

```sql
ALTER TABLE log_UnsentMessage ADD COLUMN log_type VARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## SQL Server

```sql
ALTER TABLE log_UnsentMessage ADD log_type NVARCHAR(50);
CREATE INDEX idx_unsent_connector_type ON log_UnsentMessage (connector_id, log_type);
```

## Doğrulama

Script'i çalıştırdıktan sonra kolonun var olduğunu doğrulayın. Örneğin PostgreSQL, MySQL veya SQL Server üzerinde:

```sql
SELECT COUNT(*) FROM information_schema.columns WHERE LOWER(table_name) = 'log_unsentmessage' AND LOWER(column_name) = 'log_type';
```

Oracle üzerinde `LOG_UNSENTMESSAGE` için `USER_TAB_COLUMNS` tablosuna bakın. Sonuç 1 olmalıdır.
